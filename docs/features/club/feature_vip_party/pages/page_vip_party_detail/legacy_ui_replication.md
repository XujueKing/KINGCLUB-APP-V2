# VIP 组局旧版 UI 复刻规范

- 旧版来源：`KingClub-app/pages/Choose2`
- 稳定基线：`master / 505d222 / 1.1.37`
- 设计状态：`Approved for Development`
- 复刻版本：`VIP Party Legacy Replica v2 / Browse`

## 视觉结构

```text
[返回]                    VIP组局
[今天 08.26] [周四 08.27] ... 横向日期

[08.26 预选卡座和套餐] [预定一个新卡座]

[大号桌位]                  [席位格]
[营业日与时段]              [套餐名]
[KINGCLUB]                  [价格] [二维码]

[点卡片后同页展开粉色成员区]
[头像/席位] [公开名称或安全占位] [局长/邀请/申请加入]

[旧版规则与营业时间]
```

## 必须复刻

- 黑色径向暖金背景、香槟金文字、粉色席位格和洋红展开区。
- 日期横向选择、旧版圆角预定卡、桌位大字、时间、位置、套餐、价格和二维码位置关系。
- 详情不跳现代化详情页；点击组局卡在原列表位置向下展开，再点一次收起。
- 展开区逐席排列，保留“局长”“邀请”“申请加入”等当前角色允许的动作。
- 页面末尾保留组局规则、着装文明提示、不得退座和营业时间。

## App 与安全差异

- App 不显示微信胶囊，也不显示常驻 `UI MOCK` 标签。
- 席位格只表达占用/空置，不公开真实成员性别；使用交替图标只是旧版 Fake 视觉占位。
- viewer 仅看到“已加入会员”或“空置”；host 才能看到 Fake 邀请入口。
- 不复刻卡颜、性别比例、年龄筛选、踢人赔付和客户端金额计算。
- 二维码、加入、邀请、创建、支付全部为本地 Fake；真实接口和 SDK 继续阻断。

## 同页详情行为

- 普通公开组局：展开后显示安全成员占位、规则摘要和“申请加入”。
- 自己作为局长的组局：展开后显示局长标识和空位“邀请”，不出现危险踢人操作。
- 付费加入：规则确认后只生成 Fake 待支付意图，不宣告支付成功。
- 局长请客：规则确认后显示 Fake 加入成功，并更新本地席位。
- 满员、锁定、离线时保留只读桌卡，写操作禁用且原因可见。

## 验收重点

- 393×852 与 1080×2400 下桌卡、展开区和规则区无横向溢出。
- 日期切换会收起详情并恢复列表顶部语义。
- 展开/收起不丢失当前日期；返回先退出本页，不生成隐藏页面栈。
- 所有关键按钮在 Fake 状态下有稳定结果和返回路径。
