# 入场凭证

- Scope ID：`KC-F-025`
- 文档状态：`Approved for Development`
- 所属业务域：`club`
- M0 范围：`In Release Scope`
- 设计版本：`Admission Credential v1`
- 最后更新：2026-08-25

## 目标与用户价值

让已付款或免付确认的会员在有效时间窗内出示可轮换、可撤销、不可从页面参数伪造的入场凭证，并清楚理解未生效、已入场、已离场和失效状态。

## 已确认事实

- 旧 `ticket` 从 URL 反序列化整份订单，客户端用静态 `memberId` 拼接网页 URL 并本地绘制二维码。
- 静态码无短时过期、轮换、受众或防重放信息，可被截图长期复用。
- 旧页面固定展示 20:30～04:00、成员性别席位图和客户端传入价格，不重读权威订单状态。
- 旧验票/出场通过旧超级接口直接改变 `memberStatus=0/1/2`；角色和时间规则耦合在存储过程中。
- 已批准的安全扫码页只允许把 admissionContext 导航到本页，扫码本身不得直接登记入场或离场。

## 当前建议

- 每个已确认参与席位拥有一个 `AdmissionRef`，页面进入时必须重读权威凭证，路由不携带 memberId、订单或二维码内容。
- 二维码由服务端签发短时不透明 `AdmissionDisplayToken`，默认建议 30 秒轮换，具体间隔由服务端策略在安全上下界内返回。
- 动态码不使用 HTTP URL，不包含 userAccount、memberId、姓名、订单号、桌号或状态明文。
- 入场必须由已授权工作人员核验端向服务端提交 token；消费者 App 不能自助宣布入场成功。
- 离场可由工作人员登记，或会员扫描场内签发的 `admissionContext` 后在本页明确二次确认；扫码动作本身不写状态。
- 离场后是否可再次入场由服务端 `allowedActions` 返回；允许时重新签发动态码，不复用旧码。
- 不允许保存、分享、复制或导出二维码；前后台切换立即遮盖并停止轮换，恢复前台后重新鉴权获取。
- 离线时不生成新码、不延长旧码；提供“请工作人员协助核验”的安全替代流程。

## 本期不包含

- 员工验票 UI、员工身份授权、闸机系统、访客票、转赠、截图分享、Apple/Google Wallet 票卡。

- 真实超级接口、推送、WebSocket、相机或原生防截屏能力接入。

## 已确认产品决策

1. 使用短时动态二维码，默认 30 秒轮换，禁止静态 memberId/订单 URL 码。
2. 入场只能由授权工作人员核验；消费者不能自己扫码完成入场。
3. 离场扫描只打开本页，会员二次确认后才提交；服务端决定能否再次入场。
4. 离线不提供可长期使用的备用码，改为工作人员人工核验。
5. 页面不展示同桌性别/成员格子和客户端价格，只展示本人凭证、场次、区域与权威状态。

## 开发门禁

用户已于 2026-08-25 批准本版本；全部 48 页批准前不创建 Flutter UI，全局 `UI Flow Approved` 前不接真实凭证签发、工作人员验票、扫码或原生安全能力。
