# 入场二维码与隐私安全

## 动态码约束

- token 至少绑定 credentialVersion、随机 nonce、签发/过期时间和 `admission_verifier` 受众，但这些信息不以可读明文暴露给客户端。
- 工作人员核验端必须登录并具备当前场所/班次权限；仅扫描 token 不能绕过工作人员授权。
- 服务端原子检查付款/免付确认、活动、时间窗、撤销、重复核验和当前状态。
- 同一 token 的重复扫描返回 `alreadyProcessed`，不能把 checkedIn 再切回 checkedOut。
- 页面不显示可手输静态码；人工协助通过工作人员受控查询，不让会员报出永久 ID。

## 客户端防护

- 页面进入后台、任务切换器或会话失效时立即使用隐私遮盖并销毁内存 token。
- Android 可在 UI 阶段评审 `FLAG_SECURE`；iOS 使用后台遮盖和录屏检测提示，但文档不得承诺绝对阻止截图。
- 禁止保存图片、系统分享、复制、长按识别和截屏附件日志。
- 录屏/投屏被检测时遮盖二维码并提供工作人员协助；具体原生能力后续单独验收。

## 最小披露

- 页面不展示实名、身份证、手机号、永久账号、完整订单号、支付金额、其他成员或性别构成。
- 可以展示本人公开昵称/头像摘要、场次、区域、套餐摘要和状态，具体由服务端投影控制。
- 埋点仅记录入口、状态类别、轮换结果和协助点击，不记录 token、AdmissionRef 或订单详情。
