# 入场凭证页交互

| 触发 | 行为 |
|---|---|
| 页面进入/恢复前台 | 重读凭证；允许时签发新 token |
| 到 refreshAfter | 请求新 token，成功后原子替换二维码 |
| token 到期 | 无条件遮盖，禁止继续显示 |
| 收到核验事件提示 | 重读权威状态，不直接显示已入场 |
| 扫到 admissionContext 进入 | 验证上下文后显示离场确认，不自动提交 |
| 确认离场 | expectedVersion + 稳定幂等键提交 |
| 离场超时 | reconcileExit，不生成新幂等键 |
| 点再次入场 | `checkedOutReentryAllowed` 初始保持无码；重读 allowedActions 后再签发全新 token，成功才展示二维码 |
| App 后台/录屏/会话失效 | 遮盖并销毁 token，恢复后重新鉴权 |
| 点帮助 | 展示安全提示和工作人员协助流程 |
| 从订单详情进入 | 只接收不透明 `AdmissionRef`，恢复与来源订单一致的卡座、时间和套餐投影 |
| 长按标题 | 仅 UI Mock 调试使用，切换未开放、可入场、已入场、离场确认、再次入场、结束、撤销、离线与隐私遮盖场景 |

- 防止屏幕常亮、亮度提升等行为泄漏到其他页面，离开时必须恢复系统前值。
- 二维码刷新不改变页面焦点；读屏只在状态变化或临近失效关键节点播报。
- 页面埋点不包含 token、AdmissionRef、订单号或场次精确成员信息。
- UI Mock 使用本地 Fake token 生成真实可渲染二维码；扫码内容无业务效力、不可触发任何服务端状态写入。
- 凭证二维码 token 中不写入订单明文；Fake 阶段只用受控投影的非敏感场次标记生成演示码。
