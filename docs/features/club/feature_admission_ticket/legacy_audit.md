# 旧版入场凭证审计

## 发现的问题

1. `Choose/Choose2/chat` 把整份订单 JSON 放入 `/pages/ticket/ticket?order=...`。
2. `ticket` 不请求服务端，直接信任 `tableId/datetext/friends/memberStatus/orderName/price/id`。
3. 二维码固定为 `...?type=1&qrCode=<memberId>`，可截图、转发、枚举和长期重放。
4. 码内容复用通用网页 URL 与 type 数字分流，缺少 audience、过期、nonce 和签名边界。
5. 页面展示同桌性别席位、客户端价格和固定营业时间，超出入场最小信息。
6. 已入场水印来自旧路由对象，其他设备完成核验后页面不会权威刷新。
7. 旧扫码端解析 URL 字符串后直接调用写接口，类型解析脆弱且容易误路由。
8. 旧存储过程将验票角色、时段、订单与状态切换混在一起，部分逻辑存在固定手机号/角色或日期边界问题。
9. 入场与离场记录存在，但未定义请求幂等、重复扫描、核验结果未知和多设备并发策略。
10. 没有页面遮盖、禁止导出、截屏风险说明或离线安全降级。

## 可保留的产品意图

- 展示本人场次、卡座区域、套餐摘要和当前进出场状态。
- 会员向工作人员出示二维码入场。
- 已入场/已离场清晰可见，并允许按场馆规则再次入场。
- 当天有效、超时失效和取消后撤销。

旧接口和 `k_order_member/k_ticket_records` 仅作迁移线索，不作为 V2 API 或客户端状态机直接复用。
