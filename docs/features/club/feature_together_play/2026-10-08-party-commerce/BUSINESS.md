# 商家预订和组局业务分析

## 现状与复用

旧小程序 `pages/vip-order/vip-order.js` 将预订日期、编号卡座、人数、套餐、AA或免费、男女条件、券金币和余额放入一个订单草稿。`pages/order-manage` 同时显示计划人数和已预订人数。这提供了编号桌台、套餐和席位的业务基础，但不能直接代表新版整月独占合同或酒店式预订已经存在。

新版已有商家套餐、活动报价、发布、报名、付款、入场核销与分桌。报价校验套餐版本、素材审核和参加条件，发布校验桌台容量与时段冲突；门店官方账号发布免个人押金。合作者任务、七天结算和独立分佣账本也已实现。

| 现有实现 | 可以复用 | 本次缺口 |
| --- | --- | --- |
| `TogetherEntryPage`、`VipPartyRoute` | 城市恢复和日期选择 | 首页仍打开个人创建表单；旧深链也能进入 |
| `FavouriteStorePage._reserve` | 店铺、所选桌台 | 预订错误地等同于个人创建派对 |
| `TogetherPartyCreatePage` | 主题、人数、时间、套餐、条件、已审核素材 | 发布者身份不能靠用户打开“官方发起”开关声明 |
| `TogetherPreparationService`、`TogetherPublicationService` | 已确认价格、幂等发布、历史活动及官方身份校验 | 普通个人仍可发布；没有合同授权；报价与发布仍有服务层业务SQL，修改时应收敛到过程 |
| `TogetherCatalogService` | 已付款人数、票券、资格 | 未付款只显示待分座，需增加合作者指定位置的公开信息 |

## 三条业务链

### 顾客预订位置

首页吃喝玩乐 → 当前城市、日期和人数 → 选择门店的散台/卡座/包厢产品 → 阅读时段、容量、最低消费、定金和取消规则 → 选择具体可售位置或由商家分配的同类位置 → 确认预订 → 免费直接确认、定金收到有效支付回执后确认 → 我的预约 → 到店 → 收银账单抵扣该预约定金 → 最终消费结算。

定金是已付款权益，不记为一次酒水销售，不发酒、不扣酒水库存、不重复计提成。最低消费是消费承诺，既不等于当前应收，也不能自动在预订时扣最低消费全款。预约定金在最终账单中明确显示已付和剩余应收，按原交易来源追溯。

### 商家发布活动

商家平台 → 发布AA邀请 → 选择官方门店 → 选择AA、男A女免或全免费 → 时间、计划容量、套餐、参加条件、素材 → 预览及权威报价 → 发布 → AA邀请 → 顾客报名/付款 → 商家排位 → 入场核销 → 基础套餐按既有整桌出库规则备酒。

购买前显示“报名后由商家安排座位”，不显示假的桌号。不能因为不披露桌号就不限实际资源：发布必须有可核验的桌台容量池；报名、活动取消和分桌共同维护已售权益。购买后分配桌位是安排动作，不重复扣票、不重新卖相同席位。

### 合作者签约与编号组局

商家发布卡座合作任务 → 合作者任务大厅 → 合同详情 → 整月、明确编号桌台、容量和门店、资金门槛、收款主体、默认/调整收益规则、完成条件 → 领取与签约 → 必要资金付款/验证 → 合同生效 → 合作者平台我的签约卡座 → 选择合同及编号桌台 → 发布场次 → AA邀请显示编号与人数 → 顾客占一个付款席位 → 入场核销 → 收益明细及7天结算 → 合同完成与资金退回。

10人卡座已付款4人，显示“V2 · 已报名4/10人”，第5人成功付款后为5/10；浏览详情或未付款订单不成为已就坐人数。已入场人数与已报名人数区分显示，不能将付款当作物理到店。

## 权限

| 身份 | 可以执行 |
| --- | --- |
| 普通会员 | 浏览、预订、报名、取消自己的订单、查看自己的预约与票券 |
| 有效合作者 | 领取任务、申请签约、在本人有效合同内发布编号场次、查看自己的工作与收益 |
| 商户老板/授权经营者 | 管理授权门店预订产品、官方活动、合同任务、排位和本店预约 |
| 超级管理员/平台授权者 | 按已授予权限管理任务、审批、风险和平台收款合同；不是自动拥有任意商家的经营修改权 |

身份、门店、合同所有人、状态与区域在服务端校验。省级/区域身份影响可见与管理范围，不自动获得桌台签约或收款权限。审批与领取不能让客户端自报权限。普通会员旧创建深链、收藏店铺预订入口和直接调用旧接口都应受到同一发布限制。

## 独占与冲突

合同使用门店时区的自然月，数据库存UTC起止，区间采用左闭右开。月份和时区在签约时快照。整月独占的是桌台发布与销售权，商家不能再把合同覆盖的桌台放回公共预订库存；平台管理员也不能绕过合同。合作者本人若要同时售卖自己的桌台预订和组局，必须经过同一资源锁。

生效前锁定门店与指定桌台，检查其他生效或付款结果待确认的合同、已确认预约、已发布场次。已有预约不能被新合同挤掉；商家需选择没有冲突的月份/位置，不擅自取消顾客。合同结束不取消已付款场次；只能创建完整落在合同有效期内的活动。收银临时排位、商家盲盒分配和新增预约都要检查合同范围。

免费预订确认即占位置；定金未付款不占库存，先实时检查位置，核实实际付款后在同一资源锁内确认预约。支付期间有并发竞争失去位置，实际付款沿原渠道退回，不生成假预约。付款结果未知继续查询原请求，不重复收款。退款和取消只释放对应预约权益，已到店消费不按普通未到店取消处理。

## 合同资金和收益

合同保证金、承包金额、顾客定金、历史个人发布押金四种资金分别记录。无门槛合同不制造0元支付单；有门槛合同记录币种、收取方、原渠道交易和退款要求。商户收取的钱不能增加平台现金余额；平台收取的钱也不能直接增加商家可提现收益。

保证金和承包金额均按合同条件退回，分别保留原付款及退款记录。签约时固定营业收入、有效订台次数等可量化目标、统计口径和完成审核规则；无保证金可线下协商，但不能把未核实的线下付款标为已到账。期限到达不自动等同于目标完成。合同取消、违约、完成审核、冻结与退款都是可追溯状态，不删除原凭证。

用户确认两种收款方式都支持：APP线上支付，或原收取方登记线下收款凭证。退款沿每笔原渠道、原收取方执行，两项资金可以使用不同渠道。线上未知结果继续查询原交易；线下收款与退回分别记录真实凭证、经办人和时间，不把提交截图当作渠道已到账，也不把线下资金自动转为平台余额。退款中不重复发起，不因收款配置修改换商户。

默认沿用商家平台费率20%–40%、合作者15级6%–20%。合同允许授权调整，并保留规则版本；最终费率需不造成平台分配超过门店应付，不能用月签约任务再发一遍相同带局奖励。顾客的2%推荐收益从其有效消费对应的带局份额拆出。有效消费、核销入账、退款冲回、7天可提现保持既有口径。

定金抵最终账单时只计算一次实际消费。若最终消费使用储值本金，不能借由“之前定金用微信”绕过储值本金不计提成的规则；必须记录最终账单支付组成与定金分配，退回未消费定金不形成有效消费。

## 取消、通知和异常

到店时间减4小时用于区分提前取消和临近到店取消，恰好截止算提前取消；两种取消均退定金并释放座位，不收取消费。采用服务器时钟，APP仅展示时间。按原支付来源退定金，未知退款状态继续原请求查询，不重复退款。定金已经抵扣消费后不能继续以未到店取消退回，须按原消费退款规则处理。

预约确认、退款结果、场次取消/分座、合同生效/到期/完成/退回都通过既有系统消息链通知，消息卡点击进入对应详情。前台横幅与未读角标沿用全局通知控制器；不能将前台WebSocket等同于离线手机已收到推送。扫码核销成功从结果页回到扫码入口或当前业务详情，遵守全APP摄像头返回规则。

网络超时不能显示成功。提交按钮有正在处理态，同一请求重试复用请求号，状态未知时恢复原订单。售罄、权限撤销、合同到期、套餐涨价、素材撤回都返回可理解原因，不能静默更换桌号或支付方式。
