# 预订与编号组局数据及接口方案

## 复用边界

门店、城市、桌台、套餐、素材、会员、伙伴、任务、派对、报名、入场券、预约、付款及分佣沿现有对象。新增结构只描述现有对象缺少的“预订产品”和“月签约权益”，不重新造会员库、桌台库存、钱包或分佣账本。

| 对象 | 计划用途 |
| --- | --- |
| `kingclubCommerceTable` | 唯一位置身份、店铺、名称、容量；散台/卡座/包厢分类不从V前缀猜测 |
| 预订产品及桌台关联 | 商品展示、时段、免费/定金、最低消费、取消规则版本、授权位置集合；与酒水商品分开，防止预订扣酒水库存 |
| `kingclubCommerceTableReservation` | 顾客预约复用；增加产品版本、会员、收款来源、定金权益、状态和快照，不继续要求虚构员工创建预约 |
| 月签约合同及资金记录 | 编号桌台、自然月UTC范围、合作者、任务领取、资金类型/收取方/币种、分成版本、完成条件、独占状态 |
| `kingclubPartnerTask` / Claim | 商家发布合同任务和伙伴领取，关联合同；保留原获客/商户入驻/平台带局任务 |
| `kingclubTogetherQuote` / Party | 增加真实发布渠道、合同引用和资源范围快照；个人历史记录保留 |
| Booking / Admission | 原子付费名额、个人票券、核销；编号桌的公开信息不含别人票码 |
| 支付、退款与分佣记录 | 原渠道回执和资金成分；按原交易退款；最终消费计算一次；合同任务不重复发带局佣金 |

## 超级接口和过程

页面或动作优先一次超级接口、一个过程。服务层只负责可信会话、输入结构、结果结构及外部适配；金额、状态、授权范围、汇总、交易锁和幂等在过程内完成。分页、上传素材、支付回调是独立动作，不无限堆在首页读取中。

| 页面或动作 | 输入 | 一次返回 | 数据库职责 |
| --- | --- | --- | --- |
| 发布工作台 | 渠道、门店或城市、分页 | 当前权限、门店/合同、编号、容量、素材及套餐状态 | 校验发布者，不读取或冻结钱包 |
| 吃喝玩乐 | 城市、日期、人数、类型、游标 | 产品卡、店铺、价格规则、可预订状态、下一页 | 按授权上架范围和实时资源筛选 |
| 预订产品详情 | 产品、日期、时段、人数 | 素材、门店、可用位置、消费/取消规则和权威金额 | 校验容量、合同、预约、派对冲突 |
| 确认预订 | 稳定请求号、报价、同意版本 | 免费已确认或原付款尝试、状态、剩余动作 | 锁门店/桌台，报价版本、幂等、定金权益 |
| 预订取消 | 原预约、稳定请求号 | 是否有效取消、位置释放、退款请求及状态 | 服务器区分4小时边界，两种取消均原资金回退、防重复 |
| 商家产品/合同管理 | 门店、动作、稳定请求号、期望版本 | 本次更新与可操作状态 | 授权、资源冲突、产品版本与审计 |
| 合同签约与完成 | 原合同/领取、稳定请求号、版本 | 收款要求/凭证状态、生效或退款状态 | 独占、资金归属、目标完成和重放 |
| 活动报价/发布 | 官方/合作者渠道、合同、资源范围及草稿 | 权威价格、规则、发布编号与状态 | 套餐/素材/权限/合同、原子名额和事务 |
| 收银最终结算 | 原预约、场次、消费单、支付组成 | 已付定金抵扣、余款、回执、未消费金额处理 | 定金一次使用、真实消费一次计提成 |

接口ID和过程版本在实现迁移中正式登记，未登记的计划不宣称可调用。新增迁移从当前414之后递增，不能修改已有部署迁移。每批同步目录、接口、双语注释、开发日志及验证。

已实现的发布渠道：419新增kingclubTogetherTablePool并冻结合同policyRef。K261008002052（工作台）、K261002001984（报价）、K261002001982（发布）由轻薄适配层调用kingclub_party_publisher，价格、权限、合同、真实位置冲突和幂等集中在过程。公开投影移除contractRef/tablePoolRefs，合作者固定编号可公开，商家编号仅本人已付款订单可见。位置池保留历史引用；撤销不删除凭证。

## 状态与一致性

预订产品：草稿 → 上架 → 下架；已成交订单持有原版本。顾客预约：待付款 → 支付确认中 → 已确认 → 已到店 → 已结算；未到店可取消 → 退款中 → 已退款。免费预约跳过支付；过期只处理确定未付款，未知渠道结果不能清台。迟到/违约作为独立处理，不伪造消费。

合同：草稿 → 已发布 → 已领取/待资金 → 生效 → 任务待确认 → 完成/退款中 → 已退回；暂停、取消、违约和结果未知各有审计。整月权益原子分配，不允许同桌重叠两份生效合同。任务奖励/佣金与合同保证资金分列。

业务写锁采用门店 → 桌台（稳定排序）→ 原订单/合同 → 资金账户的统一顺序，避免收银、预订、合同互相死锁。每个动作请求号与操作者、资源和输入摘要绑定；同号不同输入拒绝。服务端事务回滚不会清除前一次成功回执。

## 必要验证

权限：普通会员旧接口/深链拒绝发布；伪造官方/合同归属、过期/暂停合同、跨店/跨城市访问拒绝。历史本人票券、撤销与退款不受新发布权限误伤。

资源：同桌同月二人签约只有一人成功；已有预约阻止独占；商家公共产品和盲盒分座不得使用合同桌；相邻时段允许，重叠拒绝；10人桌第10人成功，第11人售罄且不扣款。

资金：免费不出支付单；定金仅一次抵扣；重复回调/退款/合同完成不重复入账；商户直收不进平台余额；微信与平台现金计佣，储值、券、金币、赠送不计；2%只扣对应顾客部分；核销后7天成熟；退款对应冲回。

取消：服务器截止前、恰好4小时、迟1毫秒；定金抵扣后不能再按未到店退；渠道结果未知保留原请求；不同门店时区与月底跨天不偏移。

上线：全量后台verify、实际MySQL隔离事务/并发验证、Flutter权限/状态/键盘与导航测试、320/390/430dp视觉；部署前开发库备份并检查只影响KINGCLUB。最后分别验收真实请求次数/端到端耗时与两端实机，不以单元测试模拟成功代替到账。

## 已编码合同资金契约（420）

K261008002053调用kingclub_contract_funds：detail、record_offline、record_return、complete、payment(prepare/query/cancel)、refund(request/query)，一次动作返回整份合同及两项资金、渠道/凭证、履约进度与可操作状态。公开输入不能包含paid、binding、admin、_internal等内部字段；最终资金确认、目标条件与生效仍取SQL结果。合同详情使用K261008002051，一次投影不逐个资金读取。

kingclubMonthlyContractFund冻结原收方及金额，PaymentAttempt每项最多一笔未决，Refund每项唯一；不增加平台现金/门店储值/收益。短事务提交发送状态后由现有微信适配器通信，跨进程连接锁与恢复租约防止同时重发/关单；结果未知保留，验签查询确认后记已收/已退。merchantApp与商家小程序merchantDirect、平台APP配置各自明确选择；未配置不可猜。

量化订台按核销过的不同活动场次，收入按未冲正已核销有效微信/平台现金；两项条件all/any达成并经核对才准备原渠道退款。原银行/现金/线下微信/支付宝由原收方实际退回后记录凭证。线上只退原交易和原商户。

系统消息partner_contract_received/refunded/completed与Outbox同事务去重，target为partner/contract:<UUID>。contractNotices=1兼容新通知类型，旧收件箱不返回无法解析的新类型。
## 已编码多桌分座契约（421）

商家多选1至30个不重复同店位置，SQL按每桌一份套餐冻结数量/总价；合作者固定一份本人合同位置。K261008002054/kingclub_party_allocation提供workspace、detail、assign：整页一次读取，动作一次请求并直接更新完整结果。真实paid且未核销报名单可选；上限、原池、权限和退款后的空位由数据库判定。不确定时同一选择保留稳定请求重试。

购买前不公开商家池，购买后顾客活动详情展示自己的安排；多桌未分配不能核销。旧柜台整场安排不能压到单桌；收银实际核销先调用kingclub_party_admission_position，内部过程调用不是新增客户端请求。名额退回只来自真实退款状态，调桌历史不删除。
