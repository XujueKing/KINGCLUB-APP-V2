# 一起玩活动发布与购票流程

本稿整理2026年10月4日用户提出的完整流程，供产品和开发评审。范围是同城活动发现、三类发布者、AA与邀请制活动、活动详情、资格与报价、下单支付、入场券和分桌。整桌结账收银不在本稿范围。本次只整理文档，不表示这些能力已经实现或上线。

本次明确要求优先于旧小程序和此前文档；此前已确认且没有被改动的押金、取消及赔偿规则继续保留。下文标注“待确认”或“建议”的内容不是已确定规则。

## 用户看到的完整流程

首页点击“一起玩” → 选择城市和日期 → 浏览同城活动邀请卡 → 点击卡片进入整页活动详情 → 查看自己的匹配结果和应付金额 → 下单页选择券、金币、余额和支付方式 → 服务端确认报名成功 → 返回一起玩列表，显示本人红色入场券 → 点击入场券查看票面和二维码。

邀请制走同一详情入口，但必须同时具备邀请资格并满足活动要求。免费不等于已经报名，仍需确认参加，成功后才生成入场券。

## 页面组成和卡片含义

一起玩列表沿用日期条及右侧日历选择入口，活动按当前市级城市和所选活动日期展示。当前株洲只有一家入驻门店，结构仍须支持未来同城多家夜店和其他娱乐商家。

页面从上至下为日期选择、本人所选日期的入场券及两行提醒、同城邀请卡列表。当天没有成功报名的票，就不显示票卡区域和对应提醒，不用“尚未购买”的大卡片占位。有不同门店的多张票时必须都能查看，不能用单个订单覆盖其他票。

| 卡片 | 用途 | 展示与点击行为 |
| --- | --- | --- |
| 活动邀请卡 | 商家或个人寻找一起玩的参加者 | 展示活动、价格、规则和名额；点击进入活动详情，不能把它当作本人票券 |
| 本人入场券 | 该日期已成功报名的凭证 | 按本次要求使用红色票卡；不再显示售卖价格，显示活动、门店、时间和入场入口 |
| 待付款订单 | 尚未完成报名的订单 | 允许继续支付或查看订单状态，不能提前显示为成功入场券 |

“付款后有票”和“已分配桌号”分开：自动分桌活动可先出票，桌号暂显示“待分配”；分桌成功后同一张票更新桌号，不能先填虚构的888。指定桌号活动在报名成功后显示已确定桌号。本次红色入场券要求覆盖此前已购彩卡使用紫红配色的约定；具体红色色值待页面设计确认，尚未改动当前票面代码。

## 发布者身份和权限

| 类型 | 发起条件 | 用户侧标识 | 预留与费用 |
| --- | --- | --- | --- |
| 店铺官方账号 | 具有该店官方发布权限 | 邀请卡右上角固定标明“官方” | 由店铺提供活动、套餐和可用桌台 |
| 店铺营销、运营或兼职营销 | 在平台具有店铺签约授权，且店铺预留卡座 | 展示真实发布者头像和身份，不冒用“官方” | 使用授权门店及预留资源；分成须另有有效备案签约 |
| 个人 | 先承担整场全额押金或支付台费，再发起拼桌邀请 | 展示个人头像和发布者信息 | 关联所选门店、套餐及卡座，不能仅填一段店名后自行发布 |

授权发布和允许分成是两个条件。有发布授权不等于自动取得分成比例；身份、授权有效期、门店归属和桌台预留均由后台记录控制。个人发起者若符合“非官方发布者”的分成条件，也应按签约规则处理，不能根据页面身份自行计算分成。

个人担保从会员APP平台余额按商家确认的基础消费冻结，不能用某家店的储值余额替代。用户已确认：商家基础消费1000元，即使计划售票1200元也只冻结1000元；参加者付款成功并完成入场核销后，按确认的实收口径等额解冻，累计以1000元原押金为限。此次补充的“支付台费”作为另一条路径保留，其后是否退还、抵扣或随报名返还，不能自动套用冻结解冻规则，见待确认事项。

## 活动类型

### AA组局

发起时先选定一家门店，再选择该店提供的活动套餐和规则。同一家店同一天可以发布多场不同活动，也可以设置每日固定活动。每场有自己的时间、容量、规则、报名和分桌结果。

每日固定活动应按日期产生独立场次：今天和明天不能共用已报名人数、桌台预留或入场码。固定模板修改如何影响已经生成但尚未开始的场次属于待确认运营规则；已有成功订单应保留成交时的规则和金额。

| 配置项 | 本次确定的能力 | 需要表达的结果 |
| --- | --- | --- |
| 活动人数 | 设置整场最大参加人数 | 显示已报名和总人数，不能超过本场及可分配桌台容量 |
| 分桌方式 | 指定桌号，或先报名后由系统组合分桌 | 自动分桌默认开始前24小时执行，提前量可设置；活动可预留多张桌 |
| 男女比例 | 可配置 | 参与报名与实际分桌时均检查，不仅在卡片上显示比例 |
| 年龄 | 可设置参与范围；超龄禁止或加价 | 允许加价时默认超1岁加10元，可修改；未达到最低年龄不按“超龄加价”处理 |
| 颜值评分 | 男女分别设置最低要求 | 显示本人是否达到当前活动门槛 |
| 星座与属相 | 可设置排除项 | 命中排除项时显示不匹配原因 |
| 性别计费 | AA、男A女免、男女分别按金额或百分比计费 | 详情显示对当前会员适用的规则和金额 |
| 人均金额 | 统一人均价，或男价、女价 | 发起时确定，报名时计算本人最终报价 |
| 套餐与活动规则 | 选择本店提供的套餐及其规则 | 展示包含内容、人数口径、额外消费和入场要求 |
| 会员等级 | 可设置门槛 | 显示所需等级及本人匹配情况 |
| 外部团购券 | 分别设置抖音券、美团券是否允许使用 | 下单只显示该活动可用且可核验的券 |
| 金币代币 | 可设置是否允许 | 不允许时不能用金币抵扣本活动 |

2026-10-04用户确认按单桌基础消费和计划男女人数计算人均基准，再设置单人价格。基准100元、男女1比1时，女士50元，男士应为150元，确保计划人数的基础收费合计覆盖单桌基础消费。不能把男女比例独立乘基准导致少收。设基础总额T、男数M、女数F、女单价W，则男单价为(T−F×W)÷M；非整分余数的分配方式仍需确认。活动超额定价与分成另外计算。

### 免费邀请制

官方或发起者承担费用，来宾免费参加；活动仍有总人数、门店、套餐和桌台约束。可以设置年龄、颜值、男女比例、星座、属相、会员等级等与AA相同的资格条件，也可限定“已关注本店的人员”和玩家等级。会员等级和玩家等级应分别表达，不默认是同一字段。

符合条件与收到邀请是两个条件。仅满足颜值或等级，不能直接获得免费入场券。详情需区分未获邀请、已获邀请但不匹配、可以确认参加、已成功参加等状态。邀请由谁发送、是否允许申请以及是否需要发起者二次审核，待确认。

免费活动引用年龄等规则时，不自动启用超龄收费；“免费邀请制”是否允许超龄后收费需单独确认，避免详情显示免费而下单突然加钱。

## 发布流程

选择发布身份与门店 → 校验官方或签约授权，或个人担保条件 → 选择活动类型 → 选择本店套餐 → 设置日期场次或每日固定活动 → 配置总人数、预留桌台和分桌方式 → 设置报名门槛与男女收费 → 配置团购券、金币可用性 → 选择卡片模板及海报 → 预览并发布。

发布前必须有明确的门店、有效套餐、可履约的桌台资源和收费规则。个人担保失败不能发布成可报名活动；营销授权失效或桌台预留冲突也不能继续接收报名。规则修改、授权撤销后如何处理已经成交的场次，应保留历史成交信息，不直接改写已购票权益。

## 邀请卡模板与素材

平台提供KINGCLUB默认模板以及服务器样例素材库，各家店可使用自己的颜色、风格和品牌设计。自传图片沿用此前“上传后审核，通过后才公开使用”的要求。

默认模板必须包含品牌logo、店铺名称、活动名称、简单描述、时间、发布者头像或官方标识、AA价格或免费说明、总人数，并提供报名入口。官方标识在右上角；非官方发布者要能被清楚识别。沿用已有席位展示时，有头像用会员头像，空位使用未点亮的男女图标。

定制卡片可以直接是一张图片，不强行套用默认模板的文字排版。但图片必须仍绑定门店、活动和场次，供筛选、详情、报价和报名读取，不能从图片文字识别后决定扣款。官方身份标识属于平台展示信息，定制图片上仍应保证可辨识。

活动列表的卡片图、详情海报和成功后的入场券是三种不同用途的内容。详情海报最多三张，不能用“列表用了三张图”代替三张详情海报。

## 活动详情页

点击邀请卡打开完整页面。建议从上至下安排为海报、活动主题与时间、门店和发布者、套餐与规则、本人资格及报价，底部固定下单入口。海报最多三张、左右滑动，有多张时显示页码或指示点；未要求自动轮播。

门店logo和店名提供进入店铺介绍或推广官方账号的入口，保留此前确认的店铺介绍要求。详情同时应能看到活动地点、指定或待分配桌号、已报名与总人数、各项报名要求、套餐内容、费用说明和取消规则。

本人资格区域逐项告诉会员“是否匹配”和原因。例如颜值达标、年龄超出2岁需加20元、等级不足或未获邀请。资料缺失时提示补全资料，不能把未知资料自动判为通过。未登录可浏览公开内容，个人匹配和下单需要登录后读取本人资料。

底部按状态显示下单、确认免费参加、继续支付、查看入场券、满员、截止或取消等行为。不匹配且不能通过已配置加价规则解决时，不能继续下单。详情报价及下单提交时均需重新检查名额、资格和价格，页面显示只是对服务端结果的展示。

## 计价和非官方分成

可确认的计价顺序是先确定对当前会员适用的基础金额，再列出符合活动规则的超龄加价，形成优惠前报价。结算页随后展示可用券、金币和余额，以及还需外部支付的金额。所有金额明确到分，客户端不能自己修改最终应收。

用户已确认年龄按活动当天的周岁计算。超龄加价示例：若最高年龄设为30岁、本人活动当天32周岁，且允许每岁加10元，则加价20元。用户同时确认男女单价不能整除到分时由发起人调整价格或人数，不擅自四舍五入或给个别参加者分配余数。

活动人均售价可以高于套餐对应金额。非官方发布活动的超出部分按发布者与商家备案签约的约定分成；没有有效分成约定时，超出部分全部归商家。不能把超出部分默认归个人，也不能仅凭发布者填一个比例就生效。

套餐通常可能按整桌售卖，而活动按人售票，所以分成前必须先确定套餐的人均结算基准；未确定分摊人数前不能把整桌套餐价直接与单张票价相减。超龄加价是否计入超额、优惠券补贴和金币抵扣如何影响分成、何时结算或回退分成，均待确认。未确认前不固化分成公式。

## 下单与支付

订单页显示门店、活动场次、本人名额、报名资格、套餐权益、基础价、加价、优惠和最终应付，用户可以选择可用券、金币、会员APP余额、本店储值余额及已接通的外部支付方式。

| 资金或权益 | 范围 | 下单要求 |
| --- | --- | --- |
| 活动优惠券 | 符合券适用条件的活动 | 显示能用与不能用的原因，核对有效期和适用门店 |
| 抖音与美团券 | 活动明确允许且支持核验的券 | 校验所属门店、套餐和使用状态，不能把输入券码直接当作支付成功 |
| 金币代币 | 活动允许使用 | 抵扣比例、上限及能否叠加待配置口径确认 |
| 会员APP余额 | 平台会员余额账户 | 只使用可用余额，不挪用其他活动已冻结的押金 |
| 本店储值金额 | 当前活动所属门店 | 不允许把另一家店的余额用于本店活动 |
| 外部支付 | 实际已接通且适用于该门店的支付渠道 | 支付结果由服务端确认，拉起支付或返回APP不等于成功 |

已确认允许组合：先扣优惠券，再扣金币，余款由用户选择 APP 余额、本店储值或微信支付中的一种。两类余额不混扣，不因不足自动切换账户；抵扣比例与上限按活动及权益配置执行。展示各项抵扣明细，避免重复扣款。本人金额为0时确认报名即可，不制造外部支付流水。发起人押金仅在参加者付款成功并入场核销后，按商家实收口径解冻，并以剩余冻结金额为上限。

成功后返回原城市、原活动日期的“一起玩”，刷新本人票区和活动人数。付款处理中保留订单并查询结果，不能立即报失败引导重复付款。支付失败或订单关闭后应释放临时占用的券、金币、资金和名额；锁位时点及保留时长待定，不能无限占位。

## 限购和报名人数

用户本次明确：一个人同一天、同一家店、同一种卡片只能购买一次；同一天可以购买不同门店的活动。不能沿用旧版“有任一订单就禁用其他报名”的全局限制。

2026-10-04用户补充确认：按具体活动场次限制一次。同一家店同一天发布不同主题的AA活动，同一会员可以分别购买；同一活动场次不能重复成功报名。每日固定活动每天生成独立场次，不以重复使用的模板ID限制多日购买。限购唯一性使用会员与活动场次，门店和日期由该场次确定。

名额按成功确认的参加者计算，待付款不能点亮为已参加，已取消不算有效参加。限购、重复提交和最后一个名额须由服务端一并检查；重复支付通知只能生成一份参加记录及一张票。退款后是否恢复当日购买资格待确认。

## 分桌与入场

指定桌号活动预留对应桌位，自动分桌活动先售报名名额，再在配置的时间组合分桌，默认提前24小时。活动最大人数不能超过本场可履约资源；不同活动占用同一桌台的时间不得冲突。

分桌时检查桌台容量、男女比例及本场规则。系统任务重试不能重复分配席位；调整桌号后入场券展示当前有效桌号并保留可追溯记录。比例不足、未达最低开局人数、临近活动才报名以及24小时内新发布活动如何安排，见待确认事项。

票面沿用已确认的卡座编号、活动时间、方形席位与头像、二维码、票号、主题、门店logo及店名，不显示售卖价格。两行列表提醒只随本人票券出现；完整票面保留入场须知。已使用、已过期、活动取消或凭证不可用时不展示可用二维码，最终入场资格由服务端核验。

## 个人押金与取消规则

以下为此前已经明确的业务规则，保留为本次流程的资金约束；未说明的部分不自行推导。

| 情形 | 已确认规则 |
| --- | --- |
| 个人发起并冻结押金 | 从会员APP平台余额冻结商家确认的基础消费，不按额外加价后的售票总额冻结，门店储值余额不能代替 |
| 参加者支付成功 | 生成入场权益，尚未入场核销不解冻押金 |
| 已付款参加者入场核销 | 立即按确认的商家实收口径解冻发起人等额押金到 APP 可用余额，累计不超过剩余冻结额；重复核销不重复解冻 |
| 商家自己门店的官方活动 | 不需要交押金；个人发起才冻结押金，营销人员的担保责任不自动等同官方活动 |
| 免费参加者 | 实付为0，不因新增一个人数就解冻一笔虚构付款 |
| 普通取消时间 | 开始前至少48小时可以普通取消；之后不能沿普通取消入口直接取消 |
| 发起人取消 | 按整场总费用扣20%违约金给商家；参加者退款、剩余冻结释放须按结算明细处理 |
| 商家取消 | 全额退还参加者实付，并另补偿该实付的10% |
| 踢人 | 提出踢人的一方承担：退被踢者原付款、额外赔被踢者实付的100%、赔商家该实付的20%；免费参加者无补偿 |

## 分阶段完成与验收

先确认本稿 → 完成一起玩列表与邀请卡 → 完成整页详情、三张海报和资格报价 → 完成下单与支付权益选择 → 接入报名、票券、分桌 → 接入发布授权、担保和分成结算。每一步区分页面完成、真实接口完成和真机验收，不将预览成功当作交易闭环。

主要验收场景包括：同城多店同日多场；当天无票不显示票区与提醒；官方与营销身份正确；个人余额不足无法发起；年龄加价和资格不符有明确原因；男女不同价格正确；无分成签约时超额全归商家；自定义卡片仍能进入正确详情；超过三张海报不可提交；不同门店余额不可串用；免费邀请未确认前无票；同店限购与跨店购买按规则工作；支付结果未知不重复扣款；自动分桌不超容量；跨午夜票券在正确时段有效；取消、踢人和重复回调不重复退款或解冻。

### 2026-10-04 抵扣资金来源确认
