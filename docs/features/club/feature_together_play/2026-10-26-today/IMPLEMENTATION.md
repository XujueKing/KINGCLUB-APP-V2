# 今日活动页正式接入

2026-10-27用户明确批准从设计稿接入APP。只在main实现，未删除原日历/城市组件或旧按日查询；用户确认的新活动详情展开是普通右滑页面规则的特例。

## APP范围

- 首页AA邀请进入TogetherTodayPage：大字今日、本人头像、原位0–32dp淡出、两组已确认菜单；手动城市沿用HomeCitySession，换城市清除商店，时间默认今日推荐而非当天。
- 推荐一页20条，按需继续加载；下拉刷新保留已有内容，失败不填示例；切换筛选的迟到响应不覆盖当前结果。
- 卡片复用TogetherAvailableRow及原24/12/13字号和图像对比度。按用户最新对照要求，正式列表/详情关闭实时BackdropFilter，底栏使用海报底部采样的同色半透明层；旧页面保留原默认配置。原位矩形展开、固定右上关闭、系统/边缘返回；尺寸以实际Navigator布局为准，减少动态效果时取消位移。
- 推荐、账户记录、详情不显示加载圈和进度条；海报不显示加载圈。点击先用卡片已有资料展开，路由展开完成后才请求最新详情；资格/报价未确认前禁用加入，失败保留重试。已完成海报对比度采样使用有界缓存，封面解码尺寸按设备宽度限制，列表/详情复用同一解码尺寸。头像栏只显示完整席位，横滑查看其余席位。
- 今日/头像在滚动时只改变上层透明度，不逐帧重建菜单。阅读后关闭仅更新对应活动和已查看标记，不重拉整页；进入原购买流程后才刷新最新报名状态。
- 每会员本机最多保存200个已成功加载详情的活动引用；打开失败不标记、A不解锁B。卡片主体始终打开详情，小按钮首次查看、之后加入。详情加入只进入原TogetherBookingPage；满员/不符条件不能用已查看绕过。已报名保留原入场券入口。
- 可用活动券复用TogetherPartyCard/TogetherTicketPage，仅后台判断仍可用且未核销的付费/免费报名；历史和购买记录读取本人原报名投影，购买金额取原booking.quoteJson快照，不用当前活动售价冒充已付款。
- 席位继续使用真实照片/无照片男女标志。推荐单卡最多预览首20席和本人，防止大活动生成数万头像控件；详情仍可打开原参加者清单。账户和购买页用KingBackButton，不显示返回今日。

## 统一服务契约

复用K261004001985，带view走kingclub_together_feed，缺省view保持原48小时按日接口。推荐view=recommendations要求cityCode，可选storeRef/date；tickets/history/purchases只按当前可信会员查询，跨城市，不接受客户端传入其他账号。默认推荐为已发布、营业门店、未结束活动，不增加未确认的30天窗口或个性化算法。日期筛选为北京时间自然日。

每页一次超级接口/一次存储过程：数据库按开始时间、活动引用稳定分页，返回本页活动、本人报名状态/金额快照、首20席与本人、本人头像引用。服务在提交/释放连接后复用80×80公开头像压缩缓存，不在连接内等文件读取。没有新会员、券、订单或钱包表；购买/付款/入场核验逻辑沿用既有链路。

服务递增迁移470登记只读投影与接口，471兼容线上尚无多桌分配表，472更新条件必填契约；不重放历史迁移。首次联调失败时已还原运行文件，修正兼容后才重启KingClub开发服务；其它容器未操作。Windows CRLF上传470后已统一为Git LF并校正同内容校验和，无SQL语义改写。
