# 今日活动推荐：UI与交互方案

状态：2026-10-27用户已确认正式接入APP，进入实现与真机验证。下文保留设计评审记录；最新实现范围见 IMPLEMENTATION.md。

## 页面定位

“今日”指会员现在可以选择、浏览的活动与推荐内容，不是“活动开始日期等于今天”。周五、周六、下周的活动都可以出现在推荐中。具体推荐窗口、排序和平台精选方式尚未确认，不把技术草案的30天范围当作既定业务规则，也不宣称已有个性化推荐算法。

首页原“AA邀请”入口暂不改名，进入后显示“今日”。新入口名称与后续导航体系可在评审后一起确定。

## 参考与保留

以用户提供的App Store Today顶部截图和上滑截图为视觉基准：黑底、左侧大标题、右侧圆形头像、大幅卡片、沉浸滚动。现有卡片大图铺满、三层文案和24号主题字方案继续保留，不在此轮重新放大标题。2026-10-27用户再次对照后，正式页底栏改为从海报取色的同色半透明层，不做实时背景模糊；取消活动页可见的加载圈、进度条，下拉刷新保留已有内容，出错才显示重试。

原日历、城市按钮和按日选择的设计保存在[原设计预览](../2026-10-08-party-commerce/preview.html)，日期选择组件 `TogetherDateStrip` / `TogetherCalendarSheet` 也留在APP原代码中。本轮没有删除、移动或重写这些组件；实现阶段再整理为其它按日查询页面可复用的组件。

## 顶部与滚动

| 项目 | 方案 |
| --- | --- |
| 左侧标题 | 中文“今日”；英文可本地化为Today。34号、粗体、左对齐，不带返回箭头 |
| 右侧头像 | 本人真实头像，约44×44，圆形，至少44×44点击区；无真实未读信息时不画角标 |
| 两侧留白 | 以402逻辑宽度参考，20左右留白；尊重设备安全区 |
| 首卡起点 | 顶部安全区之后约一行标题，下面直接进入首张推荐，不叠日期和城市行 |
| 上滑 | 标题、头像保持上层原位，开始滚动即快速淡出；不跟卡片平移、不缩小、不转换成小标题导航条 |
| 状态栏 | 卡片可以进入系统状态栏后方；顶部轻暗渐变保持时间/电量可读，渐变不挡触控 |
| 返回手势 | 保留iOS原生侧滑、Android系统返回；不因隐藏箭头而移除返回能力 |

用户补充纠正：截图上滑后看不到标题，不代表标题随列表卷走。标题与头像是独立上层，屏幕坐标保持不变；下面的卡片单独滚动。设计稿暂以滚动0→32逻辑像素映射透明度1→0，16像素时约半透明，仅作为可评审的动画初值，正式阻尼和阈值等真机再定。隐藏后标题层不截获卡片点击，也不保留不可见读屏/键盘焦点。回到顶部时按反向进度淡入。

滚动位置由同一个列表控制，顶部留白只是滚动内容中的占位；“今日”和头像不属于这个滚动内容。未来从详情返回应恢复先前位置；不为每次打开头像或详情重置整页。点击系统状态栏回顶遵循iOS既有机制，不画假的系统栏或替换系统手势。

## 点击“今日”

下拉菜单锚定标题下方，无需在左上再放箭头图标。

1. **返回首页**：第一项。固定回APP首页，不再使用前版“返回上一页”的含义，不回到旧日历入口。
2. **切换城市 · 株洲市**：复用APP已有城市选择与手动城市记忆，选择后只刷新该城市内容，定位不覆盖手选城市。
3. **切换商店 · 全部商店**：选择当前城市中的商店；设计稿暂以全部商店为未筛选值。切换城市时清除原城市商店选择，避免城市与商店错配。此项只筛选推荐内容，不切换商家登录身份。
4. **选择时间 · 今日推荐**：默认值明确为“今日推荐”，不是默认限制活动开始日期为今天。也可指定日期；确认后在菜单右侧显示日期，取消不改变原值。可再次选择“今日推荐”解除指定日期。详细日期范围后续再定，本轮不增加未经确认的业务限制。

以上菜单顺序和文字以用户本次给出的为准；移除前版菜单中的“刷新推荐”。下拉刷新等其它刷新交互后续单独决定，不塞进这四项菜单。标题暂保持“今日”，筛选值只在菜单内回显；是否根据筛选改标题待以后讨论。

点外部、按Esc、开始滚动时关闭菜单。标题应带“可展开菜单”的无障碍语义。菜单打开时焦点进入菜单，关闭后回到标题；正式实现补全读屏和焦点管理。

将返回藏入标题菜单的可发现性低于常规返回箭头，因此系统返回手势必须保留；这项选择遵循用户本轮明确提出的视觉偏好。

## 点击头像

在头像下方展开右对齐菜单，不再直接进入前版暂定的“我的活动”总页。菜单与左侧今日菜单互斥，顺序固定为：

1. **可用活动券**：会员已获得且没有使用的邀请券，直接沿用改版前AA邀请的邀请券票卡样式。不是优惠券、尚未报名的活动推荐或待付款订单。
2. **历史加入活动**：曾加入活动的历史入口；完成、取消等状态如何归类后续细化。
3. **购买记录**：查看活动相关购买、支付和退款记录的入口，具体清单范围及页面后续设计。
4. **返回首页**：与今日菜单相同，固定回APP首页。

点菜单项后进入对应分类，返回时保留推荐列表位置和筛选值。可用活动券页面展示原邀请券票卡的版式示例，历史和购买记录暂只表达去向。预览不生成真实券、订单或历史，不扩展交易操作。

没有真实未读数据时不照抄参考图中的红色“3”。正式实现使用登录会员本人头像，复用既有缓存与身份范围。预览头像取自已有公开营销海报，仅作版式演示，不代表真实会员。

## 进入后的子页面与可用活动券

用户确认：进入可用活动券、历史加入活动、购买记录及购买页后，不显示“返回今日”文字。统一复用APP其它子页面的 `kingAppBar` / `KingBackButton`：左侧原 `assets/legacy/friendship/back.png` 返回箭头，8×16图形、48×48点击区，标题居中17号/600，透明抬头；不另造箭头或增加文字。点箭头回到进入前的推荐位置，保留城市、商店和时间选择。今日主页面仍按已定的大标题菜单，无箭头。最新卡片展开详情改按用户新截图采用右上角关闭按钮，此特例覆盖此前活动详情使用普通箭头的版本。

可用活动券复用现有 `TogetherPartyCard`，不是推荐页新做的App Store大图卡。票卡保持690:232比例、紫红径向渐变、左侧桌号与门店/标志及POSITIONING CARD，右侧两行席位、活动主题、时间和入场码入口图标；已获得券不显示售卖价格。有头像用会员头像，无头像已加入显示点亮男女标志，空位保持暗色。未分桌显示“待分配”，不能用示例888填正式券。

此入口只列未使用的邀请券；具体有效性由原券状态规则判定，不能仅靠客户端“未核销”布尔值把已取消或已失效券当可用。待付款不冒充可用券，已使用券不在本页列出。过期/退款等如何纳入历史页后续讨论。点击券继续原入场券票面及状态核验流程，不新建出票或核销逻辑。

设计预览用一张明确标注的888示例票卡核对版式，入口使用原二维码图标而非有效核销码，不创建会员报名或券记录。浏览器字体只供设计评审，正式版仍复用APP字体与组件。

## 卡片与文案

- 首张推荐直接跟在顶部下方；后续可使用“本周精选”等外部分组标题。外部标题用途和配置来源仍待定义，不能自动把活动主题当分组标题。
- 图内为小引题、大主题、小介绍。小介绍不是日期；时间在详情明确展示。主标题暂用24号、最多两行，具体字体继续在真机评审。
- AA卡底栏保留参与者头像与空位，不在头像下加文字；按本次新要求在右下角增加查看/加入小按钮，席位区自适应显示完整头像并可横向查看其余席位。有照片用照片，已加入无照片用点亮男女标志，空位用暗色男女标志。
- 商家统筹卡底栏为活动缩略图、文字和查看/加入按钮。卡片中不添加店名与店logo。真实活动类型取服务端数据，不按图片或店名猜。
- 整卡点击始终进入详情；小按钮按是否已打开该活动详情显示查看/加入，具体见下表。保留现有购买、付款、入场与核销路线。

## 卡片原位展开与查看/加入判断

依据本次App Store两张截图，活动详情采用卡片连续展开，而非整页从右侧滑入或从固定位置弹出。点击时读取该卡片在屏幕中的实际矩形（包括滚动后或部分露出的状态），同一海报、文字、磨砂底栏从该位置扩展到屏幕全宽；圆角随展开收至0，详情正文在下方出现。背景推荐列表停在原滚动位置。设计稿动画420ms、平滑减速，仅为可调初值；系统减少动态效果时取消位移动画。

详情顶部不再放普通抬头，按本次截图在右上角放圆形关闭按钮。关闭/系统返回沿相反路径收回对应卡片，恢复原推荐位置及筛选值，不返回列表顶部。详情长文可滚动，购买页返回详情保留原详情状态。账户分类和购买页仍用APP统一返回箭头。

| 位置与状态 | 点击卡片主体 | 右下小按钮 | 点小按钮 |
| --- | --- | --- | --- |
| 尚未打开此活动详情 | 原位展开详情 | 查看 | 同样原位展开详情 |
| 已打开过此活动详情 | 仍原位展开详情 | 加入 | 直接进入该活动购买页 |
| 活动详情页 | 继续阅读介绍 | 加入（始终） | 进入该活动购买页 |

按钮事件必须与整卡点击分开，点加入不能再触发详情，也不能重复导航。阅读状态按活动分别记录，不以总点击次数判断；查看A不解锁B。这里“强制阅读”落实为先成功打开该活动详情，不增加阅读倒计时、滚到底或测试题；系统不能证明会员确实阅读。详情失败未加载成功时不能标记已查看。实际不可加入、售罄或活动变更等仍服从原服务端校验，不能把已查看当成购买资格。

预览只在当前页面会话用示例活动分别记录已查看，刷新可重置以重放首次流程。正式实现拟按会员与稳定活动标识在本地记忆，跨设备同步、内容重大更新是否重置等暂不扩展到本次UI设计。未成功购买不能生成入场券。购买预览只表达原购买页的去向和返回关系，金额显示待获取报价，不创建订单或扣款。

## 必须补齐的页面状态

| 状态 | 正式实现要求 |
| --- | --- |
| 首次加载 | 保留顶部结构，以卡片骨架或原有加载状态占位，避免空白跳动 |
| 无推荐 | 说明当前城市暂无可选活动，提供切换城市和刷新；不展示虚假活动 |
| 刷新失败 | 保留已加载内容，提示重试；首次读取失败显示明确重试入口 |
| 分页 | 有界按页读取和稳定游标；滚动加载，不按每天发起多个请求 |
| 城市切换 | 取消旧结果覆盖，新城市失败不能继续冒充旧城市数据 |
| 系统字体放大 | 标题和文案允许增长或两行，不压住头像，不牺牲44点击区 |
| 无照片/图片失败 | 头像按既有男女标志回退，海报按既有错误状态处理 |

## 实现边界与尚待决定

当前真实活动接口只支持48小时查询窗口。未来必须增加有界的跨日推荐读取，不能只隐藏日历、仍读取当天，也不能在手机逐天请求拼出整页。旧按日接口继续兼容。查询规则、可报名判断、容量与排序由服务端统一返回，最终报名仍重新校验。

在用户要求先做UI后，已开始的接口代码草稿撤出工作代码并保存在本机私有草稿中；没有部署接口、执行SQL迁移或改动活动日期/报名/付款。这段是UI评审阶段记录；后续用户已批准APP实现，实际代码、服务与安装结果以IMPLEMENTATION.md为准。

已确认：今日菜单四项、头像菜单四项、选择时间默认“今日推荐”。待UI确认后再决定：推荐范围和排序、历史/购买详细页面及原券状态归类、已报名凭证是否还在推荐流保留、分组标题配置、首页入口名称。本轮不为了预览提前创建数据库表或接口。
