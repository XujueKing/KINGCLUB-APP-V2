# AA 确认订单页交互

| 触发 | 行为 |
|---|---|
| 选择优惠券/余额/金币方案 | 调用 `requote`，服务端返回完整新报价 |
| 首次进入加载中 | 不展示可复用的金额与抵扣，底部金额为 `--`，提交禁用；Fake 完成加载后进入 `quoteReady` |
| 重报价进行中 | 保留旧金额并显示刷新提示，锁定抵扣、规则勾选和提交；返回仍可安全回详情 |
| 重报价完成 | 一次性替换整份抵扣/实付明细，显示“报价已更新”，清除规则勾选，用户确认提示后继续 |
| 查看规则 | 打开当前 terms snapshot，只读展示 |
| 勾选同意 | 仅对当前 quoteRevision + termsSnapshotRef 生效 |
| 确认并去支付 | 复用本页面稳定幂等键调用 `createReservation` |
| 返回 | 未提交直接回详情；提交中先对账，不能盲目取消 |
| 提交超时 | `reconcileSubmission(idempotencyKey)`，不生成新键 |
| 返回 pendingPayment | `openPayment(PaymentIntentRef)`；未开放时使用 AA-M16 |
| 返回 confirmed | `openOrderDetail(OrderRef)` |
| 提交时售罄 | 停止提交并显示未创建订单/未扣款；只允许返回 AA 列表刷新 |
| 检测到已有预订 | 停止创建第二张订单，展示已有订单摘要并提供返回查看入口 |
| 提交结果未知 | 锁定提交和抵扣，保留同一幂等键，只允许继续查询或安全返回 |
| 提交时资格失效 | 清除同意状态，说明未创建订单/未扣款并返回 AA 列表 |
| 进入离线 | 保留只读报价，禁止重报价和创建；恢复联网后重新确认规则 |
| 会话失效 | 立即清除报价、抵扣、同意和幂等上下文，由全局协调器 reset 手机号登录 |
| 报价引用无效 | 清除全部报价与提交上下文，不显示金额或支付入口，只允许返回套餐详情重新获取报价 |
| 0 元报价 | 规则确认后按钮为“确认预订”；提交仍创建 Fake 预订并返回免付确认，不拉起支付 |

- 按钮启用条件：首次加载完成、报价引用有效、报价未过期、无重报价、规则已同意、允许提交且在线。
- 重复点击、App 前后台切换和网络重试均保持同一幂等键，直到得到确定结果或明确无订单。
- 服务端返回价格/规则版本变化时清除同意勾选，并将差异置于可见区域。
- 页面和日志禁止保存完整优惠券编号、支付凭据、实名、性别或客户端计算金额。
- 倒计时为读屏播报提供低频关键提醒，禁止每秒抢占播报焦点。
- UI/Fake 验收通过长按标题打开隐藏状态面板；面板不得成为正式页面常驻入口。
- Fake “继续查询”只把同一模拟提交对账为 `pendingPayment`，不得再次创建订单。
- 会话失效优先级最高；出现后返回键与“返回登录”执行同一个 reset 意图，原业务栈不可恢复。
