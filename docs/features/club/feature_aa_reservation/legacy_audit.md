## 发现的问题

1. `order` 按客户端读取的年龄直接从 `actualAmount` 减 180/120/60 元。
2. `order2` 信任 URL 中的整份订单、`userAccount` 和 `gender`，再据此填写支付和赠券字段。
3. 优惠券、金币、余额、实付金额、赠券、经验值和信用分均由客户端组合，存在篡改、舍入和并发风险。
4. `Choose` 列表库存只是快照，进入详情和确认之间没有明确占位，售罄竞争没有标准恢复路径。
5. `isClick` 只防当前页面连点，没有跨重试幂等键；支付结果未知时可能重复提交。
6. 固定营业时间文案存在 20:30 与 21:00 两种版本，数据库以 04:00 切业务日。
7. “取消预订”方法为空；“预订后不得退座”没有版本化规则快照和售后出口。
8. 旧列表展示“卡颜”、年龄限制、同桌头像与性别占位，并硬编码女性赠券，容易泄露或形成不透明差别待遇。
9. 接口返回 JSON 字符串再二次解析，状态码、金额和业务字段类型不稳定。
10. 已支付后直接凭客户端持有的订单对象进票页，缺少进入时重新读取权威凭证状态的约束。

## 可保留的产品意图

- 按营业日选择日期并查看可订套餐。
- 明确展示套餐内容、人均价格、剩余席位与活动规则。
- 一人一席的随机拼桌体验。
- 已有预订在列表顶部可见，并能进入待支付、订单或入场凭证后续流程。

旧接口 ID、存储过程和表仅作迁移线索，不作为 V2 客户端契约复用。
