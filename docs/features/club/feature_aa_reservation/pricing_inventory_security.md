# 一起玩 AA 价格、库存与安全

## 权威边界

| 数据 | 权威来源 | 客户端职责 |
|---|---|---|
| 会员资格 | 身份/会员服务 | 展示资格结果，不推导 |
| 营业日与时间 | 预订服务 | 按时区格式化 |
| 套餐与库存 | 预订服务 | 展示快照和刷新 |
| 原价、活动价、抵扣、应付 | 报价服务 | 展示逐行明细 |
| 席位占位 | 预订服务事务 | 展示状态和到期提示 |
| 支付最终状态 | 订单/支付服务 | 复核后展示，不信 SDK 回调 |

## 并发与幂等

- 数据库必须以“会员 + serviceDate + 有效状态”形成唯一业务约束，不能只靠页面按钮禁用。
- 创建占位同时校验资格、库存、现有预订、报价版本和规则版本。
- 同一幂等键重复提交返回同一订单；不同键的并发请求仍由唯一约束阻止重复席位。
- 占位过期由服务端释放；客户端倒计时结束只触发重读，不能自行宣布已释放。

## 隐私与公平性

- 列表不展示其他会员头像、姓名、账号、精确年龄、性别构成或实时到场状态。
- V2 消费者端不展示/采集“颜值分”，不按客户端性别硬编码价格或赠品。
- 若运营未来坚持性别配比、年龄场或定向活动，必须先完成合法性、透明说明、申诉和服务端规则评审，不能沿用旧字段直接上线。
- 日志和埋点禁止记录实名、身份证、生日、订单完整 payload、优惠券号和支付凭据。

## 风险与回滚

- Fake 阶段用功能开关模拟 AA 入口关闭、报价服务不可用和支付模块未开放。
- 真实接入时先灰度只读列表，再开启报价，最后开启创建预订；任一步可关闭写入口而保留订单查询。
- 价格或库存异常时优先关闭提交，不用客户端兜底价格继续销售。
