- 文档状态：`Approved for UI Mock`
- 视觉基线：旧版 `pages/blacklist/blacklist.wxml`、`blacklist.wxss` 与全局 `app.wxss`
- 数据方式：仅本地 Fake，不调用旧超级接口 `S231202504160683` / `S231202504060674`
- 最后更新：2026-08-27

## 旧版可见结构

1. 黑色全屏背景，顶部 690rpx 宽横排栏：左侧旧返回图标、中间“黑名单”、右侧旧“添加”图标。
2. 页面不增加新版卡片或搜索框；主区域直接使用纵向名单。
3. 每行高 120rpx：左侧 65rpx 方形小圆角头像，中部昵称 + 拉黑时间和一行签名，右侧粉色开启状态的 switch。
4. 行分隔线沿用旧版 `#300716`，标题/普通文字沿用旧版香槟金 `#C9B69E`，昵称使用白色。

## 本期 Fake 行为

- 初始显示 3 个虚构黑名单用户，仅包含进程内 `targetRef`、公开昵称、签名和拉黑日期。
- 点击用户行进入 `blockedByMe` 用户资料页，不传递永久账号、手机号或 conversationId。
- 点击已开启 switch 进入解除确认，文案明确“不会自动恢复好友”；确认后 450ms 本地演示并移除该行。
- 顶部添加图标进入已实现的 Fake “添加好友”页。
- 下拉刷新只执行本地延迟；不查询缓存、数据库或服务器。
- 最后一项解除后显示简洁空态，保留顶部栏和添加入口。

## 文档差异回写

- 用户后续确认 UI 先完全复刻旧版，因此本轮可见 UI 以旧版 WXML/WXSS 为准：不显示搜索框，解除入口使用右侧 switch。

## UI 验收基线

- Android 竖屏首屏显示完整顶部栏、列表行和 switch，底部不出现 App Shell 导航。
- 200% 字体下行内文字不覆盖 switch；必要时行高自适应。
- 页面只使用旧版真实 `back.png`、`add.png` 和 `touxiang.png`，不用文字符号或手绘图标代替。
- 真实接口、WebSocket 和持久化继续保持阻断。
