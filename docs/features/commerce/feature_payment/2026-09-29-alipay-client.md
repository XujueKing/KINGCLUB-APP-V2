# 支付宝 APP 接入

用户已要求支付宝直连／服务商模式由后台配置切换。APP 只选择微信或支付宝，商户、授权令牌、金额、签名与回调地址均由服务端确定。

## 实施规则

- 下单沿用 K260919000814，新增 paymentProvider（wechat/alipay）；微信旧请求兼容。
- 支付宝回执只接收 provider=alipay 与非空、有长度上限的 orderString。未知渠道或渠道不匹配阻断调起。
- 首次网络提交前保存渠道与幂等键；响应丢失、重进页面保持相同渠道，不新建支付单。旧缓存缺少渠道按微信处理，非法缓存阻断恢复。
- SDK 回调仅触发查单。只有 K260919000815 返回 paid 才进入现有成功页、清理待付款缓存。
- 支付宝未配置时由后端在占用库存前拒绝；客户端不得伪造可支付订单。
- SDK 使用 Tobias 5.3.4 稳定版封装官方支付宝 SDK；iOS 使用独立回调 Scheme，保留微信 Scheme。开发测试不执行真实付款。

## 验证与剩余项

需验证两渠道回执解析、跨渠道拒绝、缓存恢复、SDK 成功不等于到账、Android/iOS 编译。真实支付宝支付待用户注册及后台商户配置，不能将替身测试视为真实验收。团购券核销不属于本次客户端支付变更。

参考：https://github.com/OpenFlutter/tobias

## 本轮验证

- 6 个支付测试文件、51 项通过，包括已有微信流程；定向静态检查通过。
- 配置未启用时，先按原请求号确认是否已有订单；仅确认未建单才允许改选渠道，并保留原幂等键。不会因配置关闭就丢弃可能已经生成的订单。
- iOS 回调沿用 Flutter 3.47.1 的 Scene → legacy plugin 转发，已核对本机 FlutterPluginAppLifeCycleDelegate 的 sceneFallbackOpenURLContexts 实现；未额外覆盖 SceneDelegate，避免重复回调。
- Android 本机首次构建在复制原生库阶段因 D 盘空间不足中断；正在改用临时构建目录验证。iOS 编译、真实调起及真实付款尚待验证，不标记完成。
