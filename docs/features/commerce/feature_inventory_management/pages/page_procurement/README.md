# 门店采购审批与采购清单

2026-10-07 用户直接授权开发。本页仅推进已确认的手机审批及采购职责，不扩大旧库存重设计范围。

收银端创建固定批次号 CG；草稿可跨天追加。提交后生成 SQ 申请单号，清单锁定并通知老板。老板手机批准或退回；批准后老板或有 purchase.buy 授权的店员可查清单、采购并确认已采购。柜台在“收货入库”按同一批次逐项确认数量和柜格。凭证可后补，未收货不增加库存。

APP 入口：设置中的“门店采购”、商家管理中的“采购审批 / 清单”、采购系统消息。权限依据会员会话对应的既有员工映射和实时门店授权。cashbook.review 可审批及采购；purchase.buy 只采购；shift.manage 可查看收货任务。普通会员没有门店任务，不自动增加权限。

界面：黑色金色，与 APP 既有样式一致；48 像素以上按钮；待批准、待采购、待收货、已入库列表。详情显示批次、申请号、商品规格、供应商、数量、单价、金额、已收数量和柜格。操作只更新返回批次，不清空页面。失败保留请求号以核对/安全重试。

超级接口 K261007002032：context（kingclub_procurement_mobile_context）一次返回已授权门店、权限与 30 个任务，可按 before 分页；purchase_batch 独立详情读取；purchase_batch_review / purchase_batch_order / purchase_batch_document 复用 kingclub_inventory_command 事务与账本。审核和采购只能在会员 APP 会话操作。文件上传复用私有附件接口；柜台亦可后补凭证。

状态并发使用 revision；重复动作使用 requestId；跨门店拒绝。通知复用系统消息和会员事件 outbox，新客户端 procurementNotices=1 兼容旧客户端。手机号、会员码、密钥不写本页。验证涵盖权限拒绝、请求去重、审批状态、跨店、收货成本与柜格，以及存货不因申请/采购提前增加。

验证：4 项专项测试覆盖会话切换、错店响应、老板审批及普通采购员工不显示审批；相关 Dart 分析通过。手机可以拍照或选照片补采购凭证，复用私有附件；最大 8 张、单张 1MB。服务端 394–396 已部署，实际有效会员会话 context 读取通过，完整业务事务测试回滚，SUNMI 已保留数据更新。手机仍需包含本页的新版本；当前连接的手机 ADB 为 offline，没有对手机进行安装或宣称发布成功。

手机窄屏（390×844）亦验证审批界面。审批返回结果直接更新详情和原列表，返回不追加一次 context 请求，不发生“状态已改、列表仍显示待批”的过渡。Android commerce profile 构建通过，用于编译验证，不将独立验证包当作用户已升级的正式 APP。
