# 克洛泽清吧：商家入驻至下单模拟

用户最新要求先模拟完整商家流程，覆盖此前“商家入驻暂不开发”的阶段限制。地点为湖南省株洲市，门店为克洛泽清吧；仅作为用户指定的模拟展示名称，不推定其经营主体、证照、地址、账号或商品真实数据。

## 流程

1. 商家注册并建立经营主体草稿，填写所在地区及门店。个人登录账号与门店官方账号分开，经营主体可管理多个品牌/门店。
2. 提交营业执照、适用许可证及其他要求的资料，文件上传服务器私有存储，业务记录保存 fileId、SHA-256、资料类型、有效期、提交人及审核状态。需要哪些许可证由实际经营类型和地区配置，模拟清单不是法律结论。
3. 审核：草稿→待审核→通过/驳回补充。补充新版本不覆盖历史文件；过期/撤销重新审核。只保存资料不能自动标为资质已核验。
4. 建立 APP 内门店官方账号，关联经营主体、门店和地区；老板/员工使用自己的登录身份管理。推广图、视频经处理和审核发布，公开素材与私有资质分开。官方账号不是抖音/美团账号授权。
5. 维护商品分类、规格、价格、库存、是否上架，套餐关联组成商品；库存与点单共用。金额使用分，真实报价由服务器计算。
6. 门店、资质、商品满足上线条件后才允许点单。模拟采用先付款门店：提交预留→模拟付款回调→出库→上菜→清台，清台后历史保留。

## 文件隔离

复用新服务器 AttachmentService、LocalStorageAdapter、FileRepository。真实入驻资料必须保持 private，不能接受客户端指定 public；审核人员通过商家资质授权接口读取，不能把证件放到公开图片/视频流。当前附件服务仅已有上传人私有权限，跨商家审核授权尚需新增，不能假装已经具备。

本轮没有收到真实资料。用明确标记的 .txt 占位说明验证上传/读取/拒绝他人读取，绝不绘制证照、填造证照编号或模拟合法性认证。输出位于独立后端 .tmp-merchant-simulation，每轮唯一目录，文件实际写入本机服务端存储适配器；不是远程服务器上传，也不是生产数据库记录。元数据和审核/订单是隔离模拟，不调用真实微信、不导入旧数据。

## 验收

输出逐步骤报告、隔离快照、附件索引和审计记录；演示缺资料不能提交、未审核不能营业、他人不能读取私有资料、服务器算价、缺货不可超卖、付款回调防重和清台保留订单。宣传图/视频仅模拟内容记录，未提供素材时不声称已发布真实媒体。价格、库存、付款、审批全部显著标为模拟。

后续真实上线缺口：经营主体/资质版本/官方账号关系表与接口、真实文件及审核权限、真实媒体处理、商品及库存持久化、支付联调；需要迁移编号与目录登记后才可部署，不直接把模拟 JSON 导入生产。
