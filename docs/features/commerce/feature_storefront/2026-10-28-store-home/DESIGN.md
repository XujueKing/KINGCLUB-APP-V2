# 特约商户店铺主页：UI与内容布局

状态：2026-10-28 用户要求先设计，待逐页评审。本轮交付本地交互设计稿和布局文档，不修改正式APP、接口、账号或数据库，不构建手机安装包。

## 产品方向

用户希望会员“一想起玩，就用我们的APP找店铺、找活动、订位置”，平台帮助店家引流。店铺主页承接浏览活动后对商家的兴趣，也承接直接找店的用户。首屏回答：这是哪家店、在哪里、有什么可参加的活动、怎样预订。

每个特约商户都有可分享、可再次访问的独立店铺主页；同品牌不同分店各有门店身份和可售内容。品牌可以关联多家分店，本轮先完成单店页面。店铺主页不是管理后台，商家编辑、审核和财务入口仍在商家平台。

## 确认沿用的内容

- 沿用当前APP黑底、白色主文字、灰色次文字、香槟色操作；字体跟随各系统。普通子页用统一返回箭头与17号标题，无“返回推荐”文字。
- 活动卡保留已确认的大图、三层文字、底部身份栏和查看/加入逻辑。主标题24号；小标题及第三行13号，小标题加粗、相邻间距8。门店身份示例为KING CLUB／天元区湖南工大店。
- 点击门店LOGO和店名组成的整块身份区域进入所属店铺；点击活动海报和主题进入活动详情；点击查看/加入维持原有分流，互不冒泡。
- 参加者头像仍进入会员公开资料，不能被误接成店铺入口。卡片满10人改为头像底栏时，活动详情中的门店身份入口始终保留。
- 普通会员从主页浏览、报名和预订；发布仍从商家平台和合作者平台进入。

## 本轮建议的页面结构

| 顺序 | 区域 | 内容与交互 |
| --- | --- | --- |
| 1 | 门店主视觉 | 一张封面，可进入图集；以后可配置短视频但默认静音、不自动抢播。缺少环境照片时使用品牌封面，不拿活动海报充当门店实景。 |
| 2 | 门店身份 | LOGO、品牌名、分店名、商家已填写的经营类型/特色；只有后台核准才出现特约/认证状态。不展示猜测评分、销量、人气、距离。 |
| 3 | 到店信息 | 营业状态/营业时间、地址和导航。营业时间独立配置，不能复制某一场活动时间当作门店营业时间。定位未授权不显示假距离。 |
| 4 | 快捷操作 | 收藏、联系商家、导航。收藏复用现有门店收藏关系；联系进入真实商家官方会话，未开通时如实提示；联系电话以公开配置为准。 |
| 5 | 页内导航 | 精选、活动、订位、介绍。精选把正在招募的活动和预订入口放在同一屏流中；其余标签分别聚焦，避免首屏堆满介绍。 |
| 6 | 本店活动 | 优先可报名的近期场次，清楚显示活动日期，不按“今天”截断周五活动。卡片展示类型、主题和相关头像，接回既有活动详情及购买页。 |
| 7 | 选位置 | 散台、卡座、包厢；选择日期和人数后看实际产品、可用时段和规则。普通预订与参加AA拼桌各自进入相应流程。 |
| 8 | 店铺介绍 | 简短简介、环境图集、商家确认的特色与设施、详细营业时段、地址/到店提示。长文折叠展开，缺项不虚构。 |
| 9 | 底部操作 | 默认“联系商家”次按钮＋“选位置”主按钮。没有开放预订时主按钮变“查看活动”；两者都不可用时只保留有效联系/导航，不做假可订。 |

首屏不铺满服务标签、支付图标、经营统计和资质文件。商家要表达的信息放入介绍与图集，活动和可预订位置优先。评分/评价体系、团购商城、达人榜、人气排行不自动纳入本轮设计。

## 推荐的浏览路径

1. 推荐活动 → 点击门店身份区域 → 店铺精选 → 活动或订位；返回恢复原卡片位置。
2. 首页“吃喝玩乐”既有入口 → 找店铺列表 → 店铺主页 → 选日期/人数 → 产品详情 → 原确认预订/付款。
3. 店铺活动标签 → 活动详情 → 查看参与要求 → 原报名流程。活动报名选择编号卡座/系统随机的规则继续保留。
4. 收藏门店或分享店铺 → 同一稳定门店主页；门店页可分享，分享内容不能携带会员、付款或核销凭证。

店铺跳转建议采用普通页面导航，保留系统返回与当前页滚动位置，不把整张活动海报飞入店铺页。已有活动原位展开动画仅用于活动详情。店铺封面图集单独打开并原位关闭。

## 订位区域的内容层级

第一层选择“日期、人数、散台/卡座/包厢”，第二层产品卡展示图片/位置类型、适合人数、当前付款方式及消费要求，第三层详情展示完整可用时段、金额、取消规则和位置分配方式。

“免费预订”指现在无需支付，不代表没有最低消费；“无最低消费”是另一项规则。定金可抵最终消费、顾客取消仍退定金并释放位置，继续遵循用户前述约定。支付结果未知不能给成功预约，付款时再次校验库存。活动占用与普通预订使用同一实际桌台库存，不能两个模块各自售卖同一时段。

不默认所有普通预订都让顾客挑具体桌号。商家产品明确允许选编号时再显示编号；商家安排的位置要在购买前说明。AA活动按照该活动既定的自选/随机规则显示席位，与整桌预订区别清楚。

## 店铺介绍建议字段

| 内容 | 展示建议 | 商家维护规则 |
| --- | --- | --- |
| 封面/图集 | 封面1张，图集按环境、活动海报等内容分类 | 图片审核后公开；保留原图和展示规格，缓存按版本更新 |
| 品牌/分店 | KING CLUB／天元区湖南工大店 | 关联真实门店，展示简称不改营业主体/订单门店 |
| 简介 | 一句话特色＋可展开长介绍 | 商家填写，缺少时不代写事实 |
| 营业时间 | 常规每周时段、跨夜时段和临时调整 | 单独配置；暂停营业与停止线上预订分别表达 |
| 地址/导航 | 城市、区县、详细地址、核验坐标 | 无坐标保留地址；地图目的地不使用猜测定位 |
| 特色/设施 | 仅列商家确认的音乐类型、包厢/停车等 | 不根据图片推断；缺项隐藏 |
| 联系方式 | 官方会话、公开电话 | 联系人身份及启用状态从服务器返回，不跳店主私人主页 |
| 消费/到店提示 | 年龄限制、预订须知、到店核销说明 | 展示与实际服务一致的内容；具体活动规则由该活动负责 |

## 页面状态

- 无活动：活动区显示“本店暂未发布活动”，仍能看介绍、收藏和有效的预订产品。
- 无预订产品：不展示虚构桌位或价格；提供查看活动/联系/导航等有效入口。
- 暂停接待：显示商家公告与状态，禁用新的报名/预订；已经持有的订单和券通过原本人入口处理，不能直接隐藏或改写。
- 预订名额已满：可换日期或看其它产品，不以联系按钮承诺一定有位。
- 官方会话/电话未配置：分别提示，不假装已能聊天或拨打。
- 主页未公开/门店不可用：说明暂不可查看，提供返回；本人已有订单仍按订单权限读取。
- 读取失败：保留已有资料，给局部重试，不把失败显示为无活动。

## 身份与后续接口设计方向

页面以活动返回的稳定 `storeRef` 定位所属门店。门店资料、活动、位置都必须属于该门店，不能由前端传店名拼接。门店的官方会话使用真实 `officialAccountRef` 关联；当前缺少启用官方发布账号，不应伪造账号/认证来充页面。

建议独立店铺首页超级接口和 `kingclub_store_home` 存储过程，一次返回发布状态、基础资料、公开图集首屏、当前活动预览、可预订产品预览、收藏状态、联系/导航能力及后续游标。正式接口编号和数据库迁移待本轮UI确认后按登记规范申请，本轮不假称已存在。

每组预览建议最多3条；更多活动/产品是独立分页浏览动作，复用现有目录而非一次拉全店所有订单或报名人员。公开图像用轻量缩略图和版本标识，资料页静态媒体可缓存；库存、资格和付款结果以动作时服务端校验为准。收藏复用 `K261005000810`。地图跳转、收藏、联系以及实际预订属于独立用户动作。

## 交互设计稿说明

[打开本地交互预览](preview.html)。侧栏可切换活动入口、店铺精选、活动、订位、介绍、找店铺及异常状态；图集、收藏、日期/人数选择、产品规则和返回路径均可操作。支持320/375/402/430宽度及大字模式检查。

本轮使用已有店铺LOGO和用户提供的万圣节图片。品牌封面是排版示意，不是门店实景；无真实环境图片/营业时间/评分/距离时不捏造。产品、场次与席位演示均标注为设计示例，不创建预订、不扣款、不发送商家消息。正式APP仍待用户确认后实施。
