# APP扫码确认收银登录

2026-10-04用户授权与个人组局同步开发。仅本仓库负责APP识别及确认页面，服务端与收银由对方会话负责，当前接口尚未确认上线。

入口复用首页/个人中心现有扫一扫，包括相册识码。仅接受完整 kingclub://cashier-login/v1/<64位小写hex>，不接受额外参数、片段、空白或相似域名。

进入独立“登录 KING 收银台”页面，通过已认证会员加密超级接口 K261004002009(action=inspect,challengeId)读取设备名、有效期和本人有效员工门店。单店默认、多店主动选择；无授权不允许确认，不创建员工。只有用户点击确认登录才调用approve并携带storeRef；点击取消登录才调用reject。返回箭头关闭页面，不默默批准。没有收银凭据返回APP，也不替换APP登录会话。

响应超时不当作批准成功；显示结果待核对，允许查询同一个challenge，不自动重复批准。会话变更使页面失效；有效期到达禁用确认。服务器仍须核验授权、门店、有效期和原子状态。

待联调：接口上线、普通会员403错误码、过期/已经处理的状态、真实收银台获准后的轮询结果。自动化与真机联调分别记录。


## APP交付交接

入口：MemberScannerPage相机和相册统一识别，ScanRoute.cashierLogin先于好友资料解析分流，避免依赖聊天仓库。确认页CashierLoginPage展示deviceLabel及storeName，不显示内部员工编号、设备UUID、challengeId或任何收银密钥。客户端采用预定接口结果result包装，403错误以AuthFailure提示，approve/reject响应未知锁定按钮并只允许inspect核对。后端契约出处：ccsop-service/docs/独立项目/KingClub V2/05-接口与权限/2026-10-04-收银二维码登录.md。

实现不代表接口已部署；真实收银机出码→APP扫码确认→收银机领取会话的端到端联调仍待上线后完成。无权限提示不提供自动创建员工操作。后端需自行读取此文档协调，APP会话不修改后端文件。
