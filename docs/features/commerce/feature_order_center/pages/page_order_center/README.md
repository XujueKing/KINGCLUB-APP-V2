## 用户任务与线框

```text
[返回]              我的订单
[全部] [待支付] [进行中] [已完成/售后]
[类型标签] 标题                         [状态]
```

状态以文字+颜色双编码；列表卡不承载取消等高风险写操作。

状态见 [states.md](states.md)，交互见 [interactions.md](interactions.md)，验收见 [acceptance.md](acceptance.md)。

## 旧版复刻基线

**已确认事实**

- 旧版没有统一的“我的订单”列表，订单分散在 `order`、`order-manage`、`shoping3`和 `detail-order`。
- V2 列表视觉取旧版 `mybalance` 的黑色画布、顶部横向分类、金色选中线、密集列表和弱分隔线；订单内容取 `shoping3` 的棕金商品信息层级。
- AA、VIP 和扫码点单使用同一列表，通过类型标签和摘要区分；局长管理不进入本页。

**UI Mock 安全边界**

- 列表只传递不透明 Fake `OrderRef`，不传 `userAccount`、整份订单 JSON或金额参数。
- 列表不放置取消、支付、退款或核销写操作；仅允许进入详情。
- 无 WebSocket 直改状态；Fake 事件只显示“有更新”并要求刷新。

## Android 真机验收

- Xiaomi 14 Pro（1080 × 2400）已验证默认混合列表、待支付筛选、分页到底、首屏失败、空态与订单详情跳转。
- 正常用户路径不显示 `Fake`、`Mock`、内部 `OrderRef` 或测试场景提示；验收场景切换器仅通过长按标题进入。
- 列表卡只提供查看详情，传递不透明 `OrderRef`，未提供取消、支付、退款或核销写操作。
- 真机证据见 [2026-08-29 Android 验收](audit/2026-08-29-device/README.md)，视觉结论见 [design-qa.md](design-qa.md)。

## 2026-08-29 支付后列表一致性 v3

**已确认事实**

- 888 号桌扫码点单支付成功后，返回订单中心必须首屏可见该笔订单。
- 列表摘要必须与支付结果和订单详情一致：`KINGBAR 湖南工大店 / 888号桌 / 轩尼诗XO、芝华士12年 / 实付 ¥3680`。
- 该笔订单已支付并进入出品流程，归入“进行中”状态族，不得回退为“待支付”。

**UI Mock 准入**

- 本轮只修正 Fake 订单摘要、状态族和详情引用，不连接真实订单接口或 WebSocket。
- 待支付筛选仍保留独立 Fake 订单，用于验收状态分组。

## 2026-08-29 AA 支付后列表一致性 v4

**已确认事实**

- V5 AA 预订支付成功后，订单中心“全部”首屏必须出现同一笔 `KING CLUB AA预订`。
- 默认无抵扣演示摘要固定为 `08月29日 20:30 · V5卡座 · 3880卡座套餐`、实付 `¥268`、状态“已确认”。
- 该订单归入“进行中”状态族，不得出现在“待支付”或“完成·售后”。
- 列表只传 `order-aa-v5-paid-r0-0829` 不透明 `OrderRef`，点击后必须打开已验收的 V5 AA 详情。

**当前建议**

- 以订单创建时间降序排列，新 V5 AA 订单位于 888 桌订单之前；旧已完成 AA 样例继续保留，用于完成/售后筛选验收。
- 本轮仍只更新本地 Fake 列表与导航回归，不引入真实订单缓存、接口或 WebSocket 推送。
