# 订单详情页交互

| 触发 | 行为 |
|---|---|
| 页面进入/恢复 | 以 OrderRef 重读详情 |
| 点继续支付 | 获取新的 PaymentIntentRef 后进入支付处理 |
| 点查看凭证 | 获取 AdmissionRef 后进入 P033 |
| 点取消 | 二次确认后 expectedVersion + 幂等键提交 |
| 取消超时 | 原键 reconcile |
| 状态冲突 | 刷新详情，不覆盖服务端状态 |
| 点联系客服 | 打开已批准支持出口，不传完整敏感订单对象 |
| AA 支付成功页点查看订单 | 只以 `order-aa-v5-paid-*` 打开同一笔 V5 AA 已确认详情，并替换支付结果页 |

页面不根据本地时间或支付 SDK 回调改写订单状态。

## Fake 演示约定

- 长按“订单详情”标题打开本地场景选择器；该入口不进入生产信息架构。
- 默认待支付详情的动作集合为 `contactSupport / cancel / pay`；按钮顺序为辅助动作在左、主动作在右。
- 已确认详情的动作集合为 `contactSupport / viewAdmission`；退款中与未知状态只保留刷新/支持类安全动作。
- 离线缓存显示缓存时间并移除所有写动作，恢复网络后才重新读取 Fake 详情。
- 待支付订单的取消确认弹窗明确取消后订单将关闭且无法继续支付；“暂不取消”和“确认取消”在弹窗底部居中对齐，连续点击在提交期间无效。Fake/幂等语义只保留在测试和代码层，不进入用户文案。
- 取消结果未知只允许使用原 Fake 幂等键执行“查询处理结果”，不得再次创建取消请求。
- 取消成功只更新当前订单的状态、提示与时间线；标题、类型、桌位、商品、金额和 `OrderRef` 必须保持原订单，不得切换成另一条示例订单。
- 无效引用、非本人订单和不存在订单使用相同安全错误文案，不透露对象是否存在。
- 金额卡、状态提示、客服反馈和支付/凭证出口不得暴露 `Fake`、`Mock`、内部引用或测试说明。
- AA 支付后详情返回时不得回到可再次触发支付的结果页；不得把套餐、价格、卡座或用户对象复制到路由参数。
