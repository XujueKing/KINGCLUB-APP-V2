# 订单详情页

- Scope ID：`KC-P-037`
- 文档状态：`UI Mock Implemented / Android Device Verified`
- M0 范围：`In Release Scope`
- 所属功能：[消费者订单中心](../../README.md)
- 旧版来源：`shoping3`、`detail-order`
- 路由：`OrderDetailRoute`，`/commerce/orders/detail`，`$extra: OrderRef`
- 设计版本：`Legacy Order Detail v2 / Fake Flow`
- 最后更新：2026-08-29

## 旧版视觉基线

- 顶部延续消费者订单中心的黑色画布、香槟金标题和返回键，不复刻微信胶囊。
- 订单信息、商品明细和金额汇总复刻 `shoping3` 的浅棕金卡片、深棕文字、紧凑分隔线与商品图文层级。
- 状态摘要与时间线吸收 `detail-order` 的纵向信息结构，但不展示旧版交易对手头像、完整账号或可枚举订单号。
- 底部动作区使用黑色渐变托底；只展示当前 Fake `allowedActions`，不会从状态名称自行推导动作。

## 用户任务与线框

```text
[返回]              订单详情
[状态：待支付/已确认/...]
订单类型 · 场次/桌位摘要
[商品/套餐明细]
商品小计 / 优惠 / 实付 / 退款
[状态时间线]
[联系客服]                [继续支付/查看凭证]
```

主操作区只渲染 allowedActions；订单号默认部分隐藏，支持受控复制时单独评审。

## 本轮 UI Mock 范围

- 默认演示“扫码点单 · 待支付”，包含订单摘要、两件商品、金额拆分和状态时间线。
- 通过标题长按切换已确认、退款中、离线缓存、未知状态、无效引用、会话失效、取消冲突和取消结果未知。
- “继续支付”只生成 Fake `PaymentIntentRef`；“查看凭证”只生成 Fake `AdmissionRef`；不会调用支付 SDK、超级接口或 WebSocket。
- 取消必须二次确认；提交冲突后重读 Fake 最新状态，结果未知时保留同一 Fake 幂等键并允许对账。
- 页面返回订单中心时只传递 `OrderRef`，不通过 URL 或路由复制订单、金额、账号和桌位对象。
- 正常用户路径必须使用正式产品文案，不显示 `Fake`、`Mock`、内部引用、测试意图或“未发生真实交易”等验收说明；本地场景工具只允许通过长按标题进入。

状态见 [states.md](states.md)，交互见 [interactions.md](interactions.md)，验收见 [acceptance.md](acceptance.md)。

## 2026-08-29 v3 支付后订单详情冻结

1. 从支付成功页点击“查看订单”必须进入与刚完成支付相同的扫码点单订单，禁止回落到旧的 V8/1156 待支付样例。
2. 支付后详情统一显示：`KINGBAR 湖南工大店`、`888号桌`、轩尼诗 XO、芝华士12年、商品总价 `¥3710`、优惠 `-¥30`、实付 `¥3680`。
3. 状态必须为“已支付”，时间线首项为“支付已确认”；不得继续显示“等待支付”或“继续支付”。
4. 扫码点单已支付订单不误放入场凭证动作；底部保留客服与刷新状态。
5. 页面继续沿用旧版 `shoping3` 浅棕商品/金额卡和 `detail-order` 纵向时间线结构，不接真实订单接口。

## 2026-08-29 v4 完成与售后详情验收

**已确认事实**

- 已完成 AA 订单必须保持 `V2 卡座 / 08月26日 20:30 / 星光香槟套餐 / ¥168`，只读展示活动完成与入场核验时间线。
- 退款中扫码点单必须保持 `V2 卡座 / 缤纷鲜果盘 / 实付 ¥88 / 退款 ¥88`，并明确原支付路径处理中。
- 完成、退款中和已退款状态不得显示继续支付、取消订单或入场凭证动作。

**当前建议**

- 本期已确认不建设 App 内退款申请/客服工单页；退款状态只保留“联系客服”受控降级出口和刷新。
- 真实客服渠道仍待全局 UI 门禁通过后按批准配置接入。

## 2026-08-29 v5 AA 支付后详情冻结

**已确认事实**

1. AA 确认订单支付成功后点击“查看订单”，必须使用不透明 `OrderRef` `order-aa-v5-paid-*` 打开同一笔 AA 订单，不得回落到扫码点单或旧 AA 完成样例。
2. 该 Fake 投影固定展示 `KING CLUB AA预订`、`V5 卡座 · 08月29日 20:30`、`3880卡座套餐`和本人 1 席；未使用抵扣时实付 `¥268`，使用 Fake 抵扣时必须与支付结果页的最终金额一致。
3. 状态为“已确认”，时间线依次体现支付确认、预订提交与 V5 卡座选择；页面不得显示 `888号桌`、扫码商品或继续支付动作。
4. 套餐图片复用已批准的 `assets/legacy/aa/package_3880_v1.png`，保持旧版浅棕金信息卡、黑色进度卡和底部动作区。

**当前建议**

- 支付成功页使用替换导航进入订单详情，详情返回时回到支付流程之前的 AA 套餐详情，避免重复提交或重复支付；引用中的报价版本只用于恢复 Fake 投影，不作为用户可见参数。
- 本轮只补 UI/Fake 投影与导航，不接订单接口、支付 SDK、WebSocket 或真实入场凭证。

## 2026-08-29 v6 与提交订单统一排版

**已确认事实**

1. 用户指定订单详情的浅棕信息卡、商品卡和金额卡，必须沿用已验收“提交订单”页的字体与排版体系。
2. 顶部标题使用与“提交订单”一致的常规字重和字号，不使用额外粗大的详情页标题。
3. 第一张信息卡按“标签在左、值在右”的双列结构展示订单名称、订单日期、桌号和脱敏订单编号；商品卡顶部继续显示门店/订单名称，保证现有内容不被删减。
4. 商品图、商品名称、英文规格、容量、单价、数量和小计的尺寸、间距、对齐方式与点单确认页一致；订单详情保留现有已支付内容和金额。
5. 金额行沿用点单确认页的普通金额与强调金额层级，保持 `3710 / -30 / 3680` 业务内容不变。

**当前建议**

- 状态卡继续保留，因为订单详情仍需表达已支付、退款中等状态；其视觉密度收紧到与下方旧版卡片协调。
- 本轮只调整 UI/Mock 排版，不改变订单状态、路由、动作权限或 Fake 数据。
