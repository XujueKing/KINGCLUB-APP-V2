# APP 与收银共用真实订单读取

OrderCenterRoute 和 OrderDetailRoute 使用 MemberOrdersPage，正式入口不再读取 FakeCommerceRepository。路由 extra 的旧 FakeOrderRef 类型暂保留兼容现有生成路由，它只传不透明引用，页面必经真实订单仓储和服务器归属检查；无法解析的旧模拟编号直接错误，不呈现样例详情。其他 AA/VIP 原型流程未因此成为真实链路。

MemberOrdersRepository 使用会员现有加密会话，通过统一 KINGCLUB API 调用 K261001001955；客户端不传会员号或门店作为查询授权。响应前后核对账号、会话、key 版本，切号或退出后的迟到结果被拒绝。列表最多 20 条，游标来自本人上一页末尾订单，详情必须精确匹配原引用。商品快照、金额加总、交付数量、币种、退款证据和分页重复均验证后展示。

页面保留深色金色视觉和统一返回组件，四语言展示。收银后付 pending 为“待结账”，先付 pending 为“待付款”；原已支付总额与退款金额分别展示，已上数量来自真实商品行。当前只展示，不把会员身份作为收银扣款/退款/取消权限。收银未结账单提示到收银台核对；APP 订单的后续付款/取消等仍需沿既有真实流程补接，不使用旧模拟支付按钮。

页面订阅 connection.ready / commerce.changed，只触发鉴权重读，不采用推送金额；350ms 合并事件，加载中事件排队补读。后台清除页面内容、恢复前台重新读取；登录会话变化取消旧响应。手动刷新、分页、详情和失败重试均走同一仓储，无样例或假空列表回退。

服务端 eae705b 已新增只读接口与迁移 248（本人分页索引、接口默认关闭），全套验证通过，尚未部署。此页面的事件接收已实现，但服务端会员经营通知仍待接线；不能把测试事件或 connection.ready 当作已经验证真实收银订单投递。

新增仓储与页面的 15 项测试通过，覆盖真假后付状态、分列退款、换号/退出迟到响应、游标与详情归属、金额/数量一致性、分页跳转、事件合并与加载中补读、前后台保护、失败不回退样例及四语言窄屏。连同原扫码下单仓储和原型订单组件回归共 38 项通过；原型回归只证明旧组件未被破坏，不是正式订单接口或 AA/VIP 验收。此次修改文件定向 Flutter analyze 无问题。

尚未构建/安装本次 APP；后续须继续会员事件投递、真实 MySQL/扫码与下单联调，再与收银候选包一起验证保留数据升级和双端同步。
