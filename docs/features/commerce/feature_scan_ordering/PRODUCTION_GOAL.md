## 实施与验收顺序

1. 页面自适应：无预览横幅，手机首屏约 3 瓶半，字体按页面比例、购物车半透明渐变覆盖列表，安全区/键盘/滚动可用。
2. 门店归属与目录：租户/品牌/门店/城市/桌台/场次真实解析，商品分类、SKU、价格、上下架/缺货；复用已有身份与目录，不导入旧数据。管理员维护基础档案。
3. 订单库存：服务端报价、券配置校验、提交预留、过期释放、付款后幂等出库；直接买单和 AA 30 分钟付齐成单，未成团按用户规则仅退 APP 余额，不同时执行微信原路退款。原路退款业务另行记录渠道退款单和状态，避免余额与渠道双退。
4. 微信支付：直连/服务商，APP 调起及小程序 JSAPI 的各自应用身份；私钥只在服务端，请求签名、响应验签、原始回调验签/AES-GCM 解密、金额/币种/商户/订单归属核对、唯一渠道单号、持久化去重。不能用客户端返回作为支付成功依据。
5. 异常与运营：查单/关单、迟到成功、退款单/退款通知、补偿任务、对账差异、支付凭据轮换、审计、限流、多店隔离、监控与回滚。
6. 四语言、真机 UI/下单/扫码回归；真实商户 APP 签名/包名绑定、回调可达、商户授权及生产环境验证。缺配置时明确失败，不返回 Mock 成功。
