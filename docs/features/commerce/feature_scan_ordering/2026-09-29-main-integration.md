# 扫码点单集成到 main

## 范围

用户授权将扫码点单开发分支合入 APP `main`，后续在合并版本上继续实机验收。

- main 基线：`d2fe9fd1`。
- 商务分支：`feature/commerce-management`，`e808fa38813915647c3dce2ba5356d620c8eb71e`。
- 在独立 worktree 集成；原 main 工作区中未提交的注册偏好页修改不纳入、不覆盖。
- 此次不合并 CCSOP 后端分支，不改变服务器部署、支付账户或回调配置。

## 合并处理

- Android 依赖同时保留 main 的厂商推送依赖与商务分支微信支付 SDK。
- MainActivity 同时保留推送、通话和微信支付 MethodChannel。
- 保留 main 的 preview 包身份；commerce 继续使用独立测试包。
- 构建脚本显式指定 `https://api.wuyexin.cn/commerce`，避免从登录接口地址推导出错误的点单路径。
- 储物袋在横屏/低高度窗口下允许整体滚动，手机竖屏九宫格仍保持原宽度，不通过缩窄九宫格规避溢出。
- 保留 main 聊天页右上角操作按钮的位置，恢复聊天附件/礼物截图基线；不重录 golden 掩盖差异。
- 桌台管理导航测试分别验证默认关闭及显式开启的路径，不改变生产入口开关。

## 验证

- 静态检查：无 error/warning，9 条测试代码花括号 info（默认 analyze 因 info 返回非零）。
- 点单/商品/购物车/桌台/存取酒/扫码/返回导航专项：155 项通过；唯一失败是导航测试未考虑已有功能开关，修正后关闭及开启两种配置均通过。
- 聊天附件与礼物 golden、统一返回导航：修复主线按钮位置后 7 项通过。
- 聊天分页的单独复测通过。
- 全量测试曾中止，不记为通过：当时 25 个失败中 22 个在未合并的 main 基线复现（法律文档、旧 smoke、媒体发送恢复用例）；其余为上述聊天 golden 和分页，已单独处理/复测。历史失败没有通过删除断言或更新截图掩盖。
- 首次 Android commerce profile 编译完成后因 D 盘不足在打包步骤失败；本次构建缓存转移 C 盘后，主线 preview/profile arm64 APK 构建成功（150.9 MB）。仅构建验证，本次未覆盖安装手机。
