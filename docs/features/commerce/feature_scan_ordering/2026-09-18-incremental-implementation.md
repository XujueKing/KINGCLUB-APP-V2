# 扫码点单增量开发：已有 UI 衔接

用户已明确改为边做功能边完善，先做扫码点单；本批允许 UI/本地流程实现，不等于授权真实付款或数据库部署。

旧版 index.js case 9 解析 tableId/shopId/tableName 后到 shoping，shoping.wxml 显示门店/地址/桌号、分类、商品和购物袋。新版已有 ScanOrderingCartPage、ScanOrderConfirmationPage 及跨页测试，保留旧布局，不重做界面。

审查发现：购物页固定示例门店/888 桌、初始两件商品；结算固定日期/门店/桌号。实际 MemberScannerPage 处理会员与群码，SafeScannerPage 是模拟目的地选择。没有证据证明真实桌码已接入。

本批新增 OrderingContext（会员、门店、桌台本次场次、营业日与显示资料），显式提供上下文时从空购物袋开始，报价携带至确认页；换上下文清空原选择并使延迟报价失效。无上下文的原演示路由保留原 UI，避免改动旧视觉验收样例。该对象不是鉴权凭据，不可把原始桌码直接当服务端授权。

当前是可测试的页面接入基础，实际相机/路由尚未传入上下文，商品与报价仍为 Fake。下一批应实现桌码识别与受控上下文解析端口，再接现有路由；保留会员/群码原行为，不能未经验证把二维码文字中的店名和桌名用于授权。AA/四语言/真实库存与支付仍未完成，本批不声称点单上线。

验证使用本地 widget 测试：新上下文空车、添加商品后报价/确认页同一门店桌台、报价等待换桌不跳旧单，以及既有点单回归。不使用聊天测试手机。

本批结果：4 个测试文件共 28 项通过；变更的 4 个 Dart 文件定向 analyze 无问题。初次新测试点击商品被底栏遮挡，修正为可见商品并等待滚动后重跑全部通过。依赖通过独立 worktree 的 offline pub get 准备，未修改依赖声明/锁文件；未安装到手机，未做真实相机、接口或视觉验收。
