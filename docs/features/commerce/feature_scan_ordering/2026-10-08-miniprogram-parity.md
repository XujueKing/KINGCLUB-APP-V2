# 微信小程序与 APP 扫码点单统一（2026-10-08）

用户要求：旧微信小程序与新 APP 的扫码点单接口、流程和使用方法尽量一致，使用同一服务器、同一业务数据。此次修改旧小程序和 KINGCLUB 服务，APP 现有点单实现作为对照基准。

## 已实现的统一

- 小程序使用微信已放行的 `https://api.shanghai-kingclub.cn`，APP 使用 `https://api.wuyexin.cn/kingclub-v2`；已核实都路由到同一 KINGCLUB 服务和 `ccsop_kingclub` 库。小程序实现 APP 同一 `/supper-handshake`、`/supper-interface` 加密协议。
- 同一手机号登录同一 KINGCLUB 会员账户；小程序通过当前协议、短信验证码和服务器会员状态验证。旧小程序 `preUserInfo` 不具备新接口身份权限。
- APP 与小程序会话分别管理，各自保留单设备规则，同时登录不会互相挤下线。小程序续期使用同一刷新接口和令牌轮换机制。
- 桌卡 → 桌台/当次开台 → 人数 → 商品分类/套餐 → 购物车 → 服务端组合支付报价 → 提交/支付 → 服务器确认 → 桌台账单/我的订单。
- 同一商品、规格、版本、售价、库存；新品/推荐聚合、套餐分类合并与 APP 一致。先付款或后付款由服务器桌台规则决定。
- 优惠券、K 币、店内余额、平台现金复用 APP 同一服务端组合支付入口；客户端仅显示报价和提交选择。
- 下单超时先查询原订单，保留原幂等编号；微信回调成功只触发服务器核对。退出或桌台重新开台后，原待付款订单仍按会员恢复。
- 订单记录、出酒数量、退款结果来自同一服务；不创建另一套小程序订单或资产账本。

## 微信终端差异

APP 保留移动应用支付；小程序使用 `wx.login` 一次性 code，由服务器向微信核验付款 OpenID，再返回 `wx.requestPayment` JSAPI 参数。AppSecret 仅在服务器配置。

支付配置仍遵守现有规则：APP 使用平台收款，小程序使用门店商家直收，均由共用支付配置入口解析。已经冻结的订单付款配置不能跨终端重绑；两端可以查看同一订单，继续外部付款须在原下单终端完成，或取消原单后重新点单。小程序提供微信和平台现金，APP 原有支付宝能力保留。
