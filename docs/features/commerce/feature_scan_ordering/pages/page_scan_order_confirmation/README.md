当前 preview 入口可使用固定 Fake 报价投影完成 UI 验收；真实接入阶段仍必须由不透明 `QuoteRef` 恢复服务端报价，路由不得携带金额、账号、原始二维码或订单 JSON。

## 用户任务与线框

核对服务端报价、桌位和商品，明确提交后创建待支付订单。

```text
[返回]              提交订单
门店名 · A08桌 · 报价剩余 04:32
[商品明细]
商品小计                         ¥300
优惠                            -¥32
应付金额                         ¥268
[价格或库存变化提示区]
[返回修改]                    [提交订单]
```

- 不在本页让用户手填余额、金币或现金分摊；支付方式由支付流程基于权威 PaymentIntent 决定。
- 主按钮提交时明确“提交订单”，不能提前写“支付成功”。

状态见 [states.md](states.md)，交互见 [interactions.md](interactions.md)，验收见 [acceptance.md](acceptance.md)。

## 旧版复刻基线

**已确认事实**

- 页面以旧版 `pages/shoping2` 的黑棕径向背景、居中金色标题、棕金圆角信息卡、商品明细和固定底部金额/主操作区为视觉主体。
- 用户本轮图二是排版唯一视觉真值：标题改回 `提交订单`；卡片左右边距、圆角、纵向间距、商品图尺寸、普通字重和底部栏比例必须按旧版恢复，不能沿用当前放大加粗的卡片排版。
- 商品行保留图片、商品名、规格、单价、数量与小计，支持展开/收起更多商品。
- App 不复制小程序宿主胶囊。

**已批准的安全差异**

- 删除旧版在确认页中手填金币、余额、优惠券与现金分摊的控件；仅显示 Fake 服务端报价结果。
- 旧版“立即支付”改为“提交订单”；成功只能表示创建待支付订单，不得表示支付成功。
- 支付方式改为只读说明“订单创建后选择”，后续由权威 `PaymentIntent` 决定。
- 路由只携带不透明 Fake `QuoteRef`，不携带金额、账号、原始二维码或订单 JSON。

真机证据见 [2026-08-29 Android 验收](audit/2026-08-29-device/README.md)，视觉结论见 [design-qa.md](design-qa.md)。

## 2026-08-29 v3 排版冻结

- 顶部：54dp 左右的导航区，返回键靠左，`提交订单` 使用约 16sp 普通字重并居中。
- 卡片：左右约 12dp，卡间约 10dp，背景 `#C9B69E`，圆角约 9dp；禁止大号粗体标题和值。
- 信息卡：保留日期、桌号和报价剩余；门店名在商品卡首行呈现，避免重复占高。
- 商品行：透明瓶图约 44 × 69dp；中文约 15～16sp 普通字重，英文/规格/单价约 11～12sp；右侧数量约 12sp、小计约 16～18sp。
- 商品卡底部：展开/收起居中，商品总价单独一行；优惠与应付等完善内容集中放入后续同风格报价卡，不在商品卡重复。
- 底栏：保持旧版 80dp 左右高度，左侧金额层级与右侧完整胶囊按钮；安全文案继续使用 `提交订单`，不伪装支付成功。

## 2026-08-29 v3.1 对齐与更多控制冻结

1. 信息卡左列标签统一左对齐，右列日期、桌号和报价剩余统一贴卡片右内边距右对齐；不得因文字长度不同落在卡片中部。
2. 报价剩余可以作为 V2 保留内容继续显示，但必须使用与日期、桌号相同的两列网格；临期时只改变数值颜色，不改变对齐。
3. 商品展开态文案严格恢复旧版 `shoping2.wxml`：展开时显示 `隐藏更多（共N件物品）`，收起时显示 `显示更多（共N件物品）`；禁止使用“收起更多”。
4. 更多控制采用旧版横向细线贯穿、中心卡片同色遮挡线、普通字重灰棕文字和右侧小箭头；不能使用默认 TextButton 的粗体、额外内边距或大图标。

## 2026-08-29 v3.2 更多区域分隔线冻结

1. 展开列表最后一件商品与“隐藏更多”之间不得出现额外的整行上边线。
2. 本区域只保留穿过更多文案左右两侧的单组横向细线，与旧版图二一致。
3. 商品之间仍保留分隔线；折叠状态下首件商品与“显示更多”之间同样不得叠加第二条横线。
