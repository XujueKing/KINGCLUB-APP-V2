# 每日桌台设置与扫码人数 APP 接入

依据用户 2026-09-20 已确认规则推进实现。每日设置页面使用传入的桌号、门店和营业日，展示四种模式、适用数值、当日修改历史；保存使用预期版本和幂等 UUID。日期由用户明确选择，初始营业日来自服务器上下文，不能把本机日期默认为门店营业日。分页保留历史。

扫码人数页面在已验证桌台/场次后读取 818；无人登记且允许编辑时选人数再调用 819，成功才显示商品页面（目录查询仍沿用原入口流程）。已有数量复用，不重复提交；不可编辑且没有数量时继续由原营业模式处理。失败显示本地四语言文案，版本冲突先刷新，不自动覆盖他人修改；网络不确定重试使用原 requestId。扫码不能自行开台。

界面复用 KingBackButton/kingAppBar；手机窄屏可滚动，数字键盘、按钮至少常规触控尺寸，支持简中/繁中/英文/泰文。新接口现网尚未部署放行，APP 用 KINGCLUB_TABLE_MANAGEMENT_ENABLED 显式开关控制扫码人数接入，默认关闭，不把配置失败当作成功。

管理页入口为商业独立路由，不改聊天或原主目录。后端决定管理员权限，客户端不写入假管理员身份。测试覆盖会话切换、场次范围、输入错误、首次选择/重复进入、失败重试和窄屏。未安装 B 手机或完成实扫前不标为真机验收。

## 本节点实现与验收

已新增 TableManagementRepository、TablePartyPage、DailyTableSettingsPage，接入现有 TableOrderingEntryPage 和商业路由。仓库复用安全会话和加密请求，核对请求前后身份及返回场次，拒绝畸形历史、金额/人数和杯数不一致。设置页只在成功读取当前版本后允许保存，金额按整数分构造，不用浮点乘法提交。

临时管理入口复用 `/commerce/ordering?manage=1&tableId=<桌号>&storeRef=<门店>&businessDate=<营业日>`；需要编译开关 KINGCLUB_TABLE_MANAGEMENT_ENABLED=true。未增加全局商家菜单，后续商家工作台接入该页；当前普通扫码仍走原路径，开关默认 false。不要将此深链参数当作权限或权威门店归属，服务器仍需校验。

45 项定向测试通过，6 个改动代码/测试文件静态检查无问题。覆盖扫码等待人数再显示购物车、已有数量无写入、失败重试 UUID 不变、会话切换、错误场次、畸形历史、四语言 320×640 窄屏和设置页 1.3 倍字体。测试注入接口结果，无真实核销、开台或支付。

本轮未构建或安装新 APK，未发布后端新构建，也未开启商业写接口。140/141 数据库已由上个节点实际迁移，不代表本页已可在线操作。剩余受控服务发布、商家菜单入口、B 手机真实扫码/人数/规则保存联调。
