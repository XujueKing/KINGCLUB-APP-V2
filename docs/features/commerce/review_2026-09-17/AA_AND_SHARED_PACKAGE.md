# AA 入局、共享套餐与加餐
状态：In Review。用户已确认：加餐 AA 逐人先付，人数付齐成单，未成团超时退款；基础套餐由员工确认开局并准备酒水时整桌出库一次。本文件优先补充此前按单人点单编写的规则。

## 1. 两条业务流程

**基础入局**：会员在抖音/美团购买团购后，在 App 自助核销；也可直接在 App 购买 AA 券。取得有效入局权益后，选择参加的卡座局。服务端按该卡座预设可坐人数、男女配比等校验名额，成功加入后手机与收银台同步显示预定。实际到店入座另外登记，预定不等于已经入座。

**加餐**：点单时选择「直接买单」或「发起 AA」。直接买单沿用提交预留、付款成功出库。发起 AA 时由发起人设置人数，展示商品、总金额、每人应付、已参加人数和截止时间；达到设定人数是成单条件，不能因发起人一人付款就把整单当成成功。每人先付自己的份额，人数和款项付齐才成单出库，未成团超时退款。

基础入局券与加餐 AA 是两种业务对象，不共用一个含糊的“团购状态”。发起人数是否包含发起人、默认只允许本桌会员还是允许邀请其他会员、人数上限与取消时限需在页面契约冻结前确定。建议界面明确写「共 N 人（含我）」并默认本局邀请，尚非用户已确认规则。

## 2. 第三方核销与入局权益

- 抖音、美团各经独立适配器处理券查询、核销、查结果及适用时的撤销。当前仅为接口设计，尚未验证商家资质、平台接口权限或现有接入能力。
- 手机提交券码不是核销成功；以平台确认的核销结果为准。超时显示处理中并查原请求，不能换新请求重复核销。
- 平台订单/券的唯一标识和核销流水防重；一个已消费的权益不能重复加入多局。
- App 购买以本服务端确认付款生成权益，不凭客户端支付成功页面。
- 核销成功但暂未选局，保留“可选局”权益；满员或配比不足不丢券、不假预定。有效期、改局及撤销核销规则待定。
- 第三方券面额、平台待结算款、实际到账及平台费用分别记录。自助核销不代表平台款已到账，不将外部成交再计作 App 新收款。
- 不导入旧券或旧会员数据，不在本轮连接平台或试核销真实券。

## 3. 名额与预定

服务端保存卡座局的容量、男女配比、套餐版本及时间段快照。加入时同一事务检查有效权益、剩余名额、配比和重复加入，成功才占用名额。不能用前端剩余人数判断并发结果。

预定名单与实际入座名单分别显示。退局/换局关联原权益、名额及历史，不能直接覆盖记录；开始后的换人及配比变更权限待定。配置变化不偷偷重写已预定的一局。

局状态建议：招募中 → 已满足开局条件 → 待入场 → 营业中 → 已结束；取消为单独分支。“满员”“满足开局条件”“已入座”是不同事实，最低开局人数是否等于容量待确定。

## 4. 共享套餐如何扣库存

一局对应一份共享套餐履约记录，套餐分解成实际酒水商品和数量。**不能每核销一个人的 AA 券就出库一整套。**套餐份数或内容若随人数变化，使用明确的配置规则和版本，不由客户端推断。

建议分两步：
1. 预定形成套餐保障时，整局预留一次组成商品；预留时点与未成局释放时限随开局规则确认。
2. 员工确认开局并准备酒水时，按实际批次将整桌套餐出库一次，生成吧台备酒任务。备酒/上桌只确认交付，不再扣库存。

基础套餐可能提前数日预定：不能在单个会员买券时就永久锁一整桌库存。应定义可预定额度和临近开局的实物库存保障；“有席位”和“有套餐库存”都必须满足承诺条件。库存不足时明确待处理/不可预定，不暗中更换酒款。

已确认整桌套餐一次出库；如分次上桌，仅更新交付数量，不能再次扣库存。补发、赠送、破损各有独立原因和授权。

取消时未出库部分释放；已出库但未上桌的酒水，经实物确认可再售才退库。退款和退库存分别记录，不能退款后自动把已喝酒水加回。

## 5. 加餐 AA 的资金和库存

用户已确认：参与者逐人付款，人数与足额付款均满足后，原子确认成团并形成一笔加餐销售订单。未凑齐按规则关闭并逐笔原路退款。未付份额不计入已付齐人数，人数齐但款项未齐不能出库。

- 一次参与绑定一个会员和其支付尝试；人数计数按服务端有效参与记录，重复点击/回调不重复计人。
- 最后一名争抢时不得超收人。支付结果迟到与团关闭并发时查明资金状态，进入退款处理，不能重复开团。
- 总金额与分摊方案在发起时由服务端生成；以最小货币单位分摊，尾差公开、总份额严格等于应收。成团过程中不能静默改价或人数。
- 库存按整份加餐锁定，不能只锁某个人付款对应的零碎酒水。预留期限必须覆盖批准的组团/付款窗口；若无法保障，阻止继续收款或走明确失败退款。
- 成团确认、订单生成、库存出库和内部记账应幂等关联同一团；外部退款通过可靠待办重试，不假定多人的渠道付款能在一个数据库事务中回滚。
- 每人收款、退款可单独查询；共享套餐成本按局归集，加餐成本按加餐订单归集，不按参与人数重复确认整套成本。

## 6. 手机、收银台和小票

桌台卡片显示局名/场次、容量与配比、已预定/已入座人数、共享套餐待备/已出/已上桌，以及直接买单和 AA 加餐。
AA 加餐显示“已参加 X/N、已付 X/N、待成团/待付齐/已成单/退款中”，不把待成团金额计为已完成消费。点开可看付款会员与共享消费范围。

小票区分整桌消费清单和单会员付款凭据，标明基础共享套餐、加餐、直接支付/AA、实收与退款；整桌汇总不能再次要求所有会员支付已经付过的钱。
