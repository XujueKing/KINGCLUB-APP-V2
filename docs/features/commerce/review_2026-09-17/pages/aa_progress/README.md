# 加餐 AA 进度

状态：In Review；线框版本 v1（文字线框）。适用 [公共页面契约](../README.md)，不代表编码批准。

## 目标、入口与返回

会员自行邀请付款，查看成单或退 APP 余额。

结算创建或受邀链接进入；storeId、aaGroupId。返回当前桌台/订单，重进读取原团。

## 线框与字段

商品/门店/发起人 → 共 N 份/已付 X 份 → 每份金额 → 倒计时 → 支付一份/分享 → 本人支付与退款明细。

aaGroupId、shareRef、paymentAttemptRef；显示 expiresAt、state、paidShares、totalShares、个人实付/余额退款状态。

## 操作与结果

一个人发起不算付款；参与者确认份额并支付。所有份额实付确认后唯一成单并出库；30 分钟到期未齐关闭，释放库存并分别退款至原付款会员 APP 余额。

## 状态与异常

倒计时以服务端截止时间为准；刷新/切后台不延长。付款处理中不计已付；迟到实收进入退款；退款失败显示处理中，不能显示已到账。 加载、空、离线、会话失效、无权限、返回和可访问性按公共契约执行。

## 数据与审计

GetAAGroup/JoinAndPayAA/CloseExpiredAAGroup/GetParticipantRefund；团状态并发保护，余额以原付款流水幂等入账，不同时原路退款。 事件记录本页查看/提交结果及必要业务引用，审计实际操作者；不记录码值或支付秘密。字段为待定稿语义契约，真实接口编号/DTO 映射待审定。

## 验收设计

合成例：300 元分 3 份，两人各付 100，30 分钟到期两人各到账 APP 余额 100，库存释放。三份及时付齐整单只出库一次。最后付款和超时竞态只能形成一种终态。

以上先用合成 Mock 场景评审，随后在项目 UI 验收通过后验证真实事务、幂等及接口错误映射；本轮未执行。四语言、大字和读屏须覆盖主操作、错误及回执。
