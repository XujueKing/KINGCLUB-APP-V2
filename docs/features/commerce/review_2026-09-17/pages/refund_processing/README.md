# 退款与退票办理

状态：In Review，仅文档，文字线框 v1。执行 [公共页面契约](../README.md) 与 [已确认营业规则](../../CONFIRMED_OPERATING_RULES.md)。首期超级管理员操作，后续配置权限；未明确的默认行为均为待评审设计，不代表修改真实账号。

## 入口与返回

订单详情/未分座报名/退款待办进入；sourceType、sourceRef、refundId 可选。成功回退款进度，返回来源。

## 信息和字段

原订单/报名 → 已付及可退额度 → 原因/本次明细 → 退款去向/返券/实物处理预览 → 确认 → 逐笔结果。

sourceRef、lineQuantities、reason、previewVersion、commandId；可退金额、付款会员、支付组成、权益归还由服务端计算，不允许客户端任意填钱包收款人。

## 操作与结果

加餐未成团：30 分钟自动退各付款会员 APP 余额，管理员只查看/重试原退款。未分座：人工决定失效与退票，资金或权益去向按来源政策预览。普通商品退款根据原支付/优惠快照计算，具体混合支付分摊和返券规则未冻结时显示待配置，不随意将券面值兑现金。

## 数据契约与异常

PreviewRefund/ConfirmRefund/GetRefund/RetryRefund；并发申请锁定可退额度，金额不超实收剩余；unknown 查原退款不换 ID 重发。退款、撤销券、实物回库各有独立状态，不能一个完成就全标成功。退酒先核查是否已存入会员保管，不能同时保留保管权益又恢复店内库存。

接口和字段是语义草案，未注册编号。服务端验证主体、门店、实际操作人、对象版本；写动作以 commandId 防重。加载骨架、空数据指引、无权限返回、会话过期重登后查原单；离线只读/保存草稿，不提交经营结果。失败保留输入并定位原因；超时未知保持原请求查询，不显示假成功。返回保留来源状态与筛选，切店不转移草稿。

## 审计、语言与验收

记录操作者、原/新版本、业务来源、状态、时点和原因；日志不保存完整券码或账户密钥。金额用最小货币单位整数并附币种；四语言共用语义状态，读屏标签/大字/非颜色反馈按公共约定，翻译资源尚待定稿。

两次并发各退 80、总可退 100，不能累计退 160。现金+券订单未定义政策不任意现金补券；未成团退款已入余额重试不再加钱；第三方撤销未知不恢复本地可用券。
