# 每日盘点

状态：In Review，仅设计；文字线框 v1。适用 [公共页面契约](../README.md)；首期由超级管理员操作，后续配置角色。本文未确认的技术处理均为设计建议，不修改真实账户或库存。

## 目标、入口和返回

确认实物与账面差异，分别核对可售酒、已出库待交付酒、会员保管酒。

库存 → 每日盘点；storeId、stocktakeId。返回保留盘点范围和未完成行。

## 手机线框与字段

门店/盘点位置/计数时间 → 商品逐行实数 → 待交付与保管酒分区 → 差异清单 → 原因/复点 → 确认调整。未填行显示未盘，不视为零。

scope、locationRef、productOrCustodyRef、unit、countedQuantity、countedAt、snapshotVersion、reason、commandId。数量允许零但不允许负数；单位必须明确。

## 操作和业务变化

创建盘点记录并保存每行计数时点；输入实际数后对比该时点同位置账面数量。存在差异先复点或填原因，再确认调整。已出库待交付与保管酒使用各自账，不混进可售库存。

## 异常与更正

计数期间继续营业：调整量 = 实点量 − 计数时点账面量；确认时在当前账面上加调整量，不直接覆盖当前量。若时点不可重建、并发移动无法定位或调整后低于已预留量，要求复点/先处理预留，不静默取消订单。保管酒差异形成调查记录，不自动减会员权益或变成店内可售酒。

加载用骨架；空记录提供新建/返回；离线仅存草稿，确认需联网。无权限返回工作台；会话过期重新登录后查询原操作。字段错误保留输入并定位，未知结果保留 commandId 查询，不重复新建。

## 契约与记录

draft → counting → reviewing → confirmed；旧调整更正引用原盘点单，不删记录。BeginStocktake/PreviewStocktakeDifference/ConfirmStocktakeAdjustment，调整及成本事件按盘点行幂等。

语义接口与字段尚未注册，正式 DTO/接口编号待统一定稿；事件记录门店、主体、来源、真实操作人、时间、请求和更正原因。金额精确整数、数量十进制加单位；不记录附件秘密地址或个人支付凭据。草稿/待确认/已确认/处理中明确区分。
