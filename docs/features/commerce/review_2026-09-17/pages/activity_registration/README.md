# 活动报名

状态：In Review；线框版本 v1（文字线框）。适用 [公共页面契约](../README.md)，不代表编码批准。

## 目标、入口与返回

会员在已选门店取得活动报名记录，报名成功不等于已分配座位。

地区/门店活动列表进入；参数 storeId、activityId。返回原列表；成功进入我的报名详情。

## 线框与字段

店名与日期 → 活动说明/套餐 → 本人权益 → 报名按钮 → 报名状态/卡座号。活动总报名人数仅作信息，不显示单桌剩余名额。

activityId、entitlementRef；会员不填写自己的账号 ID。显示 registrationId、registrationStatus、assignedTable、startTime。

## 操作与结果

选有效入局券或进入购买流程；服务端检查适用门店/活动、重复报名与权益后生成报名。已报名直接打开原记录；分座后刷新卡座号与到店提示。

## 状态与异常

无可用权益引导购买或选择合法本地券；活动结束拒绝加入。待分配显示“已报名，等待安排座位”，不承诺已有座位；人工失效和退票进度分开显示。 加载、空、离线、会话失效、无权限、返回和可访问性按公共契约执行。

## 数据与审计

JoinActivity/GetRegistration；报名成功只写报名/权益关联，不锁整桌库存、不出套餐。 事件记录本页查看/提交结果及必要业务引用，审计实际操作者；不记录码值或支付秘密。字段为待定稿语义契约，真实接口编号/DTO 映射待审定。

## 验收设计

活动报名 30 人仍可继续报名；某桌满员不阻止报名；重复点报名只生成一条。会员换语言、返回重进仍显示同一状态。

以上先用合成 Mock 场景评审，随后在项目 UI 验收通过后验证真实事务、幂等及接口错误映射；本轮未执行。四语言、大字和读屏须覆盖主操作、错误及回执。
