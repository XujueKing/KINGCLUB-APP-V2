# 调酒用酒记录

状态：In Review，仅设计；文字线框 v1。适用 [公共页面契约](../README.md)；首期由超级管理员操作，后续配置角色。本文未确认的技术处理均为设计建议，不修改真实账户或库存。

## 目标、入口和返回

登记调酒、试饮、训练和损耗，避免与订单已扣酒水重复。

库存 → 吧台用酒；storeId、可选 sourceOrderLineRef。成功到用酒回执，返回本日列表。

## 手机线框与字段

用途 → 来源订单/独立用酒 → 已登记酒款/单位 → 系统已扣量与实际量 → 差额及原因 → 确认。

purpose、sourceOrderLineRef、productId、batchRef、actualQuantity、unit、reason。配方版本和已扣量由服务端读取。

## 操作和业务变化

销售调酒关联订单配方和已扣数量；员工记录实际使用，系统展示本次还需扣的差额。非销售用酒独立选试饮/训练/损耗，填实际量。缺少换算关系先补主数据，不猜杯容量。

## 异常与更正

订单已扣 30 ml、实际用 35 ml，只新增耗用 5 ml；实际低于已扣量也不能凭填写自动回库，先核实实物可用及原扣减，再关联更正。整瓶移到吧台位置不是整瓶耗尽，位置转移与实际耗用分开。

加载用骨架；空记录提供新建/返回；离线仅存草稿，确认需联网。无权限返回工作台；会话过期重新登录后查询原操作。字段错误保留输入并定位，未知结果保留 requestId 查询，不重复新建。

## 契约与记录

RecordBarUsage/GetUsageSource：保存来源、配方、已扣/实用/差额和批次进货成本；缺来源或缺成本标待处理，不当作零成本。草稿可改，确认后冲正更正。

语义接口与字段尚未注册，正式 DTO/接口编号待统一定稿；事件记录门店、主体、来源、真实操作人、时间、请求和更正原因。金额精确整数、数量十进制加单位；不记录附件秘密地址或个人支付凭据。草稿/待确认/已确认/处理中明确区分。
