# 会员余额与流水

状态：In Review，仅文档；文字线框 v1。[公共页面规则](../README.md) 和 [营业规则](../../CONFIRMED_OPERATING_RULES.md) 适用。管理员经营操作先由超级管理员执行；会员限本人权益，不因后台全功能权限改变数据隔离。

## 入口与返回

会员资产 → 余额；管理员从订单进入必要的会员资金明细。参数 issuerScope、currency、cursor；返回保留来源。

## 页面和字段

发行主体/使用范围 → 可用/冻结 → 流水筛选 → 单笔来源与进度。

availableMinor、frozenMinor、currency、assetClass、eventId、sourceRef、status、occurredAt。

## 操作与数据效果

充值本金、退款余额、赠送权益分别可追溯，不把金币当现金。一期不默认开放提现或跨主体使用。AA 未成团按原付款会员逐笔实付退款到 APP 余额，只有余额流水确认成功才显示到账。管理员不能直接改余额抹差异。

GetMemberAssetStatement/GetAssetEvent；余额快照与事件版本关联，退款/支付防重。切主体或币种独立显示；部分来源不可用显示待同步，不用零替代未知。

## 状态、审计及四语言

加载骨架，空记录给下一步；无权限返回，会话失效重登后查询原对象；离线仅只读/草稿，不确认账务或交付。失败保留输入，字段错误定位，未知结果持原 commandId 查询，不重复新建。返回保留门店、期间及筛选；切店不能改变原单归属。

接口/字段为语义草案，正式编号/DTO 未冻结。服务端校验主体、门店、实际操作者和对象版本；金额最小单位整数及币种，数量十进制加单位。审计来源、状态变更、操作者和更正原因；日志不记录完整地址、二维码、财务密钥。四语言共用状态键，金额与日期明确单位/时区，大字可换行、操作有读屏标签；文案资源仍待定稿。

## 验收设计（未执行）

两会员各付 AA 100 元后未成团，每人增加 100，重试仍各一次；另一老板的余额不自动用于本店。冻结不等于扣款；赠送额和本金分别解释。

还需合成 Mock 验证并发/重复请求、错店、未知状态、返回和四语言；真实服务验收在项目 UI 验收后按批准契约进行。本轮无付款、退款、导入、交割或生产账务操作。

## 未定范围
