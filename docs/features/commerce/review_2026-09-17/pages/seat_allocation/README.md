# 报名池与分座

状态：In Review；线框版本 v1（文字线框）。适用 [公共页面契约](../README.md)，不代表编码批准。

## 目标、入口与返回

超级管理员在营业前为同一活动的会员安排多个卡座。

员工工作台 → 活动 → 报名池；storeId、activityId。返回保留待分配筛选。

## 线框与字段

上方活动/待分配数 → 待分配会员列表 → 卡座卡片（最小/最大、配比、已分配数）→ 自动安排/手动安排 → 方案确认。手机用选择列表，不要求拖拽。

registrationIds、tableSessionId、expectedVersion；显示每桌 minSeats、maxSeats、genderConstraints、assignedCount。

## 操作与结果

自动安排生成预览，手动勾选会员和目标卡座，确认前展示每桌人数及未分配人数。提交原子校验；确认后通知会员分座结果。未分配记录提供人工失效/退票操作，显示来源和原因。

## 状态与异常

方案人数不足显示“未达开台人数”；超最大人数或配比冲突不提交该无效方案；并发分配版本变化刷新对比。无法分配者留在池中，不自动退票。 加载、空、离线、会话失效、无权限、返回和可访问性按公共契约执行。

## 数据与审计

PreviewSeatAllocation/ConfirmSeatAllocation/AssignSeatManually；唯一有效分配关联报名及本次开台，不直接改写历史入座。 事件记录本页查看/提交结果及必要业务引用，审计实际操作者；不记录码值或支付秘密。字段为待定稿语义契约，真实接口编号/DTO 映射待审定。

## 验收设计

合成例：30 人、三桌最小 6 最大 10，可安排 10/10/10；人数 6 可开台，11 不得进同桌；并发手动与自动操作同一会员只能保留一份有效分配。

以上先用合成 Mock 场景评审，随后在项目 UI 验收通过后验证真实事务、幂等及接口错误映射；本轮未执行。四语言、大字和读屏须覆盖主操作、错误及回执。
