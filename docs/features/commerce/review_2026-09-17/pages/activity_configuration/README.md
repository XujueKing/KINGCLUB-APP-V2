# 活动配置

状态：In Review，仅文档，文字线框 v1。执行 [公共页面契约](../README.md) 与 [已确认营业规则](../../CONFIRMED_OPERATING_RULES.md)。首期超级管理员操作，后续配置权限；未明确的默认行为均为待评审设计，不代表修改真实账号。

## 入口与返回

工作台 → 配置 → 活动；storeId、activityId 可选。保存回活动详情，返回列表保留日期。

## 信息和字段

活动名称四语言/营业日期 → 报名权益 → 套餐方案 → 适用卡座 → 预览 → 保存/开放报名。

activityId、localizedNames、dateOrSessionRange、entitlementRules、packagePolicyRef、eligibleTableRefs、state、version。

## 操作与结果

设置卡颜局等活动，不设置报名总人数上限。报名只加入活动池，开局前再分桌。套餐方案关联商品配方版本，实际履约归每次卡座开台。开放前预览会员看到的规则；关闭报名不等于删除现有报名或自动退票。

## 数据契约与异常

SaveActivity/PreviewActivity/SetActivityEnrollmentState；编辑生成版本，已报名者保留原权益快照；变更日期/套餐先显示受影响报名清单，不能静默降低已售权益。影响如何处理仍需具体政策，未处理不直接覆盖。

接口和字段是语义草案，未注册编号。服务端验证主体、门店、实际操作人、对象版本；写动作以 requestId 防重。加载骨架、空数据指引、无权限返回、会话过期重登后查原单；离线只读/保存草稿，不提交经营结果。失败保留输入并定位原因；超时未知保持原请求查询，不显示假成功。返回保留来源状态与筛选，切店不转移草稿。

## 审计、语言与验收

记录操作者、原/新版本、业务来源、状态、时点和原因；日志不保存完整券码或账户密钥。金额用最小货币单位整数并附币种；四语言共用语义状态，读屏标签/大字/非颜色反馈按公共约定，翻译资源尚待定稿。

某卡座上限 10，活动第 11 人仍可报名；关闭报名后第 12 人不能新报名，但前 11 人可分座。新配方不修改已开台出库记录。

以上是合成 Mock 与后续集成验收场景，未执行。还需测试重复提交、并发更新、跨店访问和退出重进；真实接口在项目 UI 验收后按批准契约接入。
