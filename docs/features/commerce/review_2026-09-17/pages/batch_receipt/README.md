# 分批收货

状态：In Review；线框版本 v1（文字线框）。适用 [公共页面契约](../README.md)，不代表编码批准。

## 目标、入口与返回

超级管理员按实际收到的数量和进货价建立批次。

采购详情 → 收货；storeId、purchaseId。成功到入库回执再回采购进度。

## 线框与字段

采购来源/供应商 → 每行计划/已收/待收 → 本次实收、单位、批次、单价、存放位置、适用保质期 → 入库合计 → 确认。

purchaseLineRef、receivedQuantity、unit、actualUnitCost、batchLabel、locationRef、可选 expiryDate、commandId。

## 操作与结果

默认待收数量可修改；实际进价和数量明确显示。确认将本次批次增加至当前门店库存，采购剩余量更新，不重复登记已有关联付款。

## 状态与异常

零/负数量拒绝；超过待收量先提示修订采购，不静默超收。采购已取消、版本变化、重复批次收货请求明确处理。 加载、空、离线、会话失效、无权限、返回和可访问性按公共契约执行。

## 数据与审计

ReceivePurchaseBatch/GetReceipt；批次成本快照随实际出库引用，新批价格不覆盖旧批。收货回执包含入库前后量及来源。 事件记录本页查看/提交结果及必要业务引用，审计实际操作者；不记录码值或支付秘密。字段为待定稿语义契约，真实接口编号/DTO 映射待审定。

## 验收设计

10 瓶先收 4 再收 6，各自有批次和成本；第一次请求重试库存只增 4；两批不同进价各自保留；网络未知查询原收货单。

以上先用合成 Mock 场景评审，随后在项目 UI 验收通过后验证真实事务、幂等及接口错误映射；本轮未执行。四语言、大字和读屏须覆盖主操作、错误及回执。
