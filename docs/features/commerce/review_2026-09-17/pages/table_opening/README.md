# 开台备酒

状态：In Review；线框版本 v1（文字线框）。适用 [公共页面契约](../README.md)，不代表编码批准。

## 目标、入口与返回

超级管理员确认一桌达到开台条件并准备整桌共享套餐。

手机桌台看板 → 卡座详情；storeId、tableSessionId。成功到本桌履约单；返回桌台卡片。

## 线框与字段

桌号/活动 → 已分配与已入座人数 → 最小/最大及配比 → 套餐商品/所需/可用数量 → 确认开台并备酒 → 回执/待送数量。

tableSessionId、expectedVersion、commandId；套餐数量和版本由服务器读取，不由客户端随意传价格或扣库数。

## 操作与结果

预览满足人数配置并核对酒水；确认一次建立本次开台套餐履约、批次出库和备酒任务。上桌可分次确认已送数量，不再扣库。

## 状态与异常

低于最小人数、超最大人数或缺货显示具体差额；请求超时查原开台操作；已经出库显示原单，禁止再次生成。 加载、空、离线、会话失效、无权限、返回和可访问性按公共契约执行。

## 数据与审计

PreviewSessionOpening/ConfirmSessionOpening/ConfirmTableDelivery；幂等范围是卡座本次开台，不是活动 ID，也不是单个会员。 事件记录本页查看/提交结果及必要业务引用，审计实际操作者；不记录码值或支付秘密。字段为待定稿语义契约，真实接口编号/DTO 映射待审定。

## 验收设计

同活动三桌分别出三份配置套餐；连点/重试同桌一次出库；分两次送酒仍只扣一份；未达到最小人数不能确认开台。

以上先用合成 Mock 场景评审，随后在项目 UI 验收通过后验证真实事务、幂等及接口错误映射；本轮未执行。四语言、大字和读屏须覆盖主操作、错误及回执。
