# 期间检查与结账

状态：In Review，仅文档；文字线框 v1。[公共页面规则](../README.md) 和 [营业规则](../../CONFIRMED_OPERATING_RULES.md) 适用。管理员经营操作先由超级管理员执行；会员限本人权益，不因后台全功能权限改变数据隔离。

## 入口与返回

记账 → 更多 → 期间检查；ledgerId、period。检查后返回结账记录，区别手机日结交班。

## 页面和字段

期间 → 未过账/缺成本/未分类/对账/待退款检查 → 阻断项及提示项 → 结账预览 → 确认/历史。

periodId、checkRunId、sourceWatermark、issues、policyVersion、expectedVersion、requestId。

## 操作与数据效果

检查项逐条可跳来源处理；不存在“一键忽略全部”。设计建议不平衡、模板缺失及数据未知阻断，其他未完业务按明确政策承接。确认时重验快照，不能用过期检查结果锁账。超级管理员仍受期间规则约束。

PreviewPeriodClose/CloseAccountingPeriod/RequestPeriodCorrection；关闭后不得直接回写，后续调整按批准政策留痕；重新开启需原因和受影响报表版本。

## 状态、审计及四语言

加载骨架，空记录给下一步；无权限返回，会话失效重登后查询原对象；离线仅只读/草稿，不确认账务或交付。失败保留输入，字段错误定位，未知结果持原 requestId 查询，不重复新建。返回保留门店、期间及筛选；切店不能改变原单归属。

接口/字段为语义草案，正式编号/DTO 未冻结。服务端校验主体、门店、实际操作者和对象版本；金额最小单位整数及币种，数量十进制加单位。审计来源、状态变更、操作者和更正原因；日志不记录完整地址、二维码、财务密钥。四语言共用状态键，金额与日期明确单位/时区，大字可换行、操作有读屏标签；文案资源仍待定稿。

## 验收设计（未执行）

检查后又有新凭证，旧检查结果不能直接结账；连点只产生一次关闭记录；日结完成不等于账套已月结。

还需合成 Mock 验证并发/重复请求、错店、未知状态、返回和四语言；真实服务验收在项目 UI 验收后按批准契约进行。本轮无付款、退款、导入、交割或生产账务操作。
