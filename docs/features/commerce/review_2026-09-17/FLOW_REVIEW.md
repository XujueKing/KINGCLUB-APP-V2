## 已串联的主流程

| 流程 | 页面衔接 | 必须保持的结果 |
|---|---|---|
| 商品准备与采购 | 供应商/商品维护 → 采购 → 分批收货 → 库存流水 | 目录先建再选；只有实收增加库存；每批保存实际进价 |
| 单点 | 商品列表 → 详情 → 购物车 → 选券结算 → 订单详情 → 履约 | 购物车不占库存，提交预留，付款成功一次出库，交付不再扣 |
| 首次入局 | 活动报名 → 待分配 → 管理员分座 → 卡座开台备酒 | 活动不限报名，每桌按最小/最大及配比配置；每次卡座开台一份套餐出库 |
| 加餐 AA | 结算分份 → AA 进度 → 全部付清成单或 30 分钟退款 | 未成团不出库；实付逐笔退付款会员 APP 余额，重复任务不重复加钱 |
| 用券 | 券列表/详情 → 结算选择 → 支付占用/使用记录 | 按券配置报价；已用券关联订单；外部直接核销不能再发一张袋内券 |
| 存取酒 | 合格订单明细 → 存酒申请 → 原店确认 → 会员保管记录 → 取酒确认 | AA 门票酒禁存；购买者存、3 个月、原店取；保管与销售账分开 |
| 每日经营 | 用酒/耗品/支出/备用金 → 盘点 → 日结 → 利润来源 | 已扣用量去重；调拨不当费用；采购资金支出不重复冲减已售利润 |

## 合成数量演练（仅文档推演）

1. 收入啤酒批次 20 瓶，实际每瓶 10 元。套餐甲每套 2 瓶，套餐乙每套 4 瓶；两者共用这 20 瓶，不能各自维护独立实物库存。
2. 直接购买甲一套并付款：实物销售出库 2 瓶，剩余可售 18。甲可售 9 套，乙可售 4 套；同时出售仍由原料预留约束，不能把两个显示数量相加当总承诺。
3. 创建乙一套 AA，整套预留 4 瓶：在库 18、预留 4、可售 14。30 分钟未付齐，释放预留回可售 18，无销售出库；已付会员获得各自实付金额的 APP 余额退款。
4. 已买甲的会员留下 1 瓶，原店收存：可售仍 18，会员保管增加 1；不增加店内可售库存，也不再记一笔销售。来源可存余量减少，重复申请不能存第二次。
5. 盘点可售账为 18、实点 17，计数后又售 2 瓶：确认盘差 -1 后可售 15，不把当前库存覆盖回 17。会员保管 1 瓶另盘，不能混算为店内库存。

## 本次检查发现及处理

- 页面索引分批追加时表格被空行打断，已合并为连续表格。
- 套餐组成可能重复出现同一酒款，商品设计明确先合并原料用量，再计算可售份数。
- 商品、供应商停用后仍需读取历史单据，已明确保留引用与快照，不删除未完采购或应付。
- 订单详情需要显示资金、履约、退款三个状态，避免“已退款”被误解为实物已回库，已写入独立页。
- 权限不再是本期设计阻碍；超级管理员全经营功能仍不能跳过存酒资格、库存数量和门店业务约束。
