## 本批文件

[core_schema.draft.sql](core_schema.draft.sql)：MySQL 8 候选建表 SQL，共 25 张逻辑表。`kc_draft_` 是评审占位名称，不是正式迁移编号。文件不含建库、删除、改表或数据插入。

| 领域 | 表 |

| 库存批次 | location、stock_batch、stock_balance |

每表都有主体/门店/不透明引用组合主键、操作人、版本和时间；内部外键带主体及门店，避免只凭 ID 误关联其他店。会员身份、商户/门店、钱包、券和存酒保持现有服务映射待核，未直接建立第二套身份或随意改旧表。

## 已写入 SQL 的保护

- 每桌最小/最大人数合法；同次开台基础套餐唯一。
- 当前有效报名唯一，当前分配唯一；历史报名和分配可保留。
- 批次实存/预留非负且预留不超过实存；采购和销售数量为精确十进制。
- 外部商户付款流水唯一；退款来源唯一、单付款累计退款有上界。
- AA 份额唯一，组团状态与退款进度分离；到期任务有查询索引。
- 表内关系使用限制删除，不级联抹掉库存、订单或账务来源。

这些不等于完整业务校验。人数上限、配比、时间重叠、份额金额总和、同活动分配、当前投影与历史字段一致性、余额退款原子性都需要事务层核验。详见 [约束设计](../DATABASE_AND_VALIDATION.md)。

## 数据类型与事务注意

金额汇总用 BIGINT 的最小币种单位；批次单位成本用 DECIMAL(20,6) 的最小币种单位，允许毫升/小数量成本，最终结转到整数分时按明确舍入/尾差政策处理。该精度与 DTO 安全整数上限仍需核对。

quantity 的单位从商品及成交/配方快照确定。已有流水引用后不允许改商品基础单位；正式商品单位/配方版本表下一批补。库存 sourceType/sourceRef 等多态引用不能由一个普通外键保证，正式实现要校验其对应类型、作用域和存在性。

批次原始收货数量与当前余额不同，不能拿 received_quantity 直接当可售。收货业务去重、分批收货单号、位置商品聚合锁、退货/调酒/盘点来源下一批补；本批不能独立用于真实库存服务。

actor_ref 表示创建操作者，不能替代完整变更审计；所有已确认资金与库存事件需追加/冲正，业务账户写权限和审计机制尚待设计实现。
