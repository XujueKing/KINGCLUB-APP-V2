# 功能需求与简单操作流程

状态：In Review。U 编号是用户已确认要求；本文操作细节与页面组织仍为设计建议。

## 1. 产品原则

平台从设计起支持多经营主体、多品牌、多地区和多门店，每家店仍按小团队简单操作。员工默认进入授权门店，后仓/吧台位置按岗位带出；跨店权限、商品、库存、资金和账套隔离由服务端落实。不开复杂组织树页面，不做采购审批链，不拆微服务。

顾客使用“商店/扫码点单、我的订单”。员工进入独立“经营”工作台：**收银、库存、记账、商品**四个主要入口，顶部是今日待办。老板默认兼有权限，员工只看到被授权的按钮；不建立多层管理岗位。

日常文案用“卖出、收款、进货、入库、盘点、支出、退货、还差多少”，不要求输入会计科目、借贷方向、库存事务编号或链上 nonce。后台严谨不等于前台复杂。

**手机管理为主、吧台收银机为固定工作台**：常规经营操作和报表在手机完成，收银机集中看桌台消费/入座/预订并打印小票。两端共用一套业务数据，不重复录入；详见 [手机与收银机设计](MOBILE_AND_COUNTER.md)。

每次操作由服务端记录真实登录员工、确认时间、终端、关联单据和更正历史；收货人/领用人是业务字段，不代替实际操作人。断网只存待提交草稿，不能把库存/付款/记账显示为已确认。供应商和商品主数据也可由获授权人员在手机维护。

## 2. 库存：采购 → 分批次入库 → 自动出库 → 每日盘点

| ID | 操作任务 | 最少输入 / 默认 | 完成结果 |
|---|---|---|---|
| INV01 | 记采购 | 从启用供应商清单、商品档案选择，填数量、进货单价；备注可选 | 员工不得自由填写供应商/商品，保存采购单和金额；未收货不增加库存，未付款不伪造支出 |
| INV02 | 收货入库 | 选采购单，默认待收数量，确认实收；支持分次收货 | 每次收货生成批次，记录单价、数量、时间、来源和操作人；部分收货保留剩余待收 |
| INV03 | 快速采购并入库 | 勾选“已收货”“已付款”，付款账户按上次默认 | 一次操作关联采购、批次入库和采购付款，内部仍是三种可追溯事实 |
| INV04 | 看库存/缺货 | 搜商品或扫码，列表显示可售量和缺货 | 与顾客点单共用同一库存事实，不手工同步两份商品数量 |
| INV05 | 点单自动出库 | 直接买单提交预留、付款成功自动执行；AA 付齐成单出库，基础套餐开局备酒出库 | 库存立即更新，生成带订单号/商品/批次/数量/成本的销售出库记录；重复回调不重复扣 |
| INV06 | 套餐扣库存 | 后台配置套餐由哪些单品及数量组成 | 预留/出库按组成单品一次完成；短缺任意必选组成则套餐缺货，单品与套餐争用同一库存 |
| INV07 | 每日盘点 | 默认日期/仓位，逐项填实点数，可扫码定位 | 系统显示差异，确认后生成盘盈/盘亏记录及成本影响，保存盘点前后数量，不覆盖历史 |
| INV08 | 损耗/退货 | 选商品、数量、原因；按订单或批次关联 | 生成非销售出库或退回入库；退款与可回库数量分别处理 |
| INV09 | 查批次/出入明细 | 在商品详情展开 | 查看哪次进货、还剩多少、卖给哪些订单、成本多少；平时不强制选批次 |
| INV10 | 供应商清单 | 老板或授权管理人员维护；员工搜索/选择 | 保存启用状态和联系信息；停用后不能新采购，旧单仍保留当时名称/标识 |
| INV11 | 商品档案 | 酒水、可售商品、调酒原料、易耗用品统一受控分类维护 | 员工只能选择；无法通过 API 提交任意名称绕过档案；缺项提示联系管理人员 |
| INV12 | 易耗用品 | 选纸杯/吸管/清洁用品等档案，填采购/入库/领用/损耗数量 | 独立库存视图与盘点；默认不上顾客商店；成本按领用/损耗等规则关联经营账 |
| INV13 | 吧台领酒/开瓶 | 从后仓转到吧台，选酒款和瓶数；容量由档案带出 | 转移位置不重复增加采购或形成销售；开瓶折算为毫升/规定基本单位，保留原批次成本 |
| INV14 | 调酒用酒记录 | 选酒款、用量、用途，时间/人员自动带出；订单可关联 | 有配方的已付订单自动带出理论用量，只确认/调整实际量；未关联订单的试饮、损耗、训练等分别记，不能重复扣 |

自动取批次建议采用先入先出，保质期做提示；是否采用临期优先由业务确认。不能默认把任意数量换算为“瓶”，箱/瓶/杯/毫升等转换在商品设置一次，批次保留基本单位与成本精度。调酒用酒已纳入范围：建议每款可售鸡尾酒由管理人员一次配置用酒清单，员工不必每单重填配方。

主数据管理与业务录入分开：供应商、商品、单位/瓶容量由老板或被授予主数据维护权限的人建立；员工采购只能选择启用 ID，名称由服务端取。报价/实际采购单价仍可按授权填写并留历史，这不等于可以随意创建商品。供应商与商品是否限制可供关系尚待确认；不把所有“备注”也禁止输入。

缺货指**当前可售量不足**，包括被其他未付款订单预留占用。列表自动标“缺货/暂时售罄”，禁用加购；已有购物车提交时服务端再次校验。付款超时必须查清支付结果再释放库存，不能直接按手机倒计时判断未付款。

盘点期间门店可继续卖货：盘点记录快照和期间出入流水，提交时计算期间变动；无法可靠确定计数时点时提示重数该商品，不静默覆盖最新数量。同一天可复盘，所有确认留历史。

已付款但还没上桌/取走/发货的商品必须单独计入“待交付”，盘点页自动解释实物差异，不把还在架上的已售商品又算成可卖库存。员工只需确认实际数量和待交付清单。

## 3. 收银：选商品 → 收款 → 完成

| ID | 任务 | 设计 |
|---|---|---|
| POS01 | 快速开单 | 到店订单从桌台/本次开台及已入座会员进入，选商品/数量；付款会员与消费归属分别记录；商品价格由系统带出 |
| POS02 | 收款 | 显示原价、优惠、会员可用抵扣及需收金额；点一次收款，状态为待付/确认中/已付 |
| POS03 | 现金收款 | 输入实收，自动算找零；员工明确确认现金收到后完成订单、出库、记账 |
| POS04 | 电子支付 | 以受信支付结果确认；“顾客说付了”不自动代替到账查询，异常显示查单入口 |
| POS05 | 订单售后 | 从原订单选择退款商品/数量/原因，系统算可退金额；是否商品退回单独确认 |
| POS06 | 交班 | 开班记录备用金，交班输入实点现金；系统显示应有、实有和差额，说明原因后留档 |
| POS07 | 日结 | 显示收款、退款、现金差异、未确认支付；不强制制造多级审核，老板可检查异常 |
| POS08 | 吧台备用金领用 | 选资金来源，填金额与领取人，记录实际交接；支持补领、归还、结余 |

备用金页面默认自动带入当前吧台/班次和操作人。领用与补领是公司资金账户到吧台钱箱的调拨，归还相反；只有实际发生并登记的支出才计费用。交班显示“期初备用金＋领入＋现金销售−现金退款−现金支出−归还”的应有现金，不能把领取和支出重复扣利润。

吧台新增：POS09 桌台看板（预约/空闲/入座、会员、消费/已付/退款、待处理）；POS10 会员入座/换桌历史；POS11 小票打印/补打/失败重试。扫码会员与实际桌台关系由服务器核查，不能仅信任扫码字符串。收银机终端身份与实际操作员工身份区分，换班不共用一个不可追踪的管理员账号。

扫码订单会自动进入经营订单列表，不需收银员重复录入。员工补录电子收款若未来需要，必须与通道流水匹配去重，不提供“改为支付成功”的万能按钮。本轮不默认加入赊账、多人拆账或复杂折扣叠加配置。

## 4. 记账：简单录入，自动形成三层账

| ID | 使用者任务 | 后台能力 |
|---|---|---|
| ACC01 | 记一笔支出 | 选进货/房租/水电/工资/其他、金额、支付账户；照片和备注可选；普通分类自动映射会计模板 |
| ACC02 | 记一笔收入 | 选经营收入/其他收入/资金转入等业务类型；销售订单已记账的不重复录入 |
| ACC03 | 看今日/月收支与利润 | 收款、退款、进货付款、经营费用、已售成本、毛利和经营利润；点击数字能看到来源 |
| ACC04 | 查会员账/佣金 | 余额、赠送金、授信、金币/券、佣金分开；每次变化有原因和来源订单，不能混成同一货币 |
| ACC05 | 改错一笔 | 草稿直接改；已确认/已记账用“作废并重记”，后台关联冲正，不删历史 |
| ACC06 | 会计功能 | 自动凭证、科目/辅助维度、明细账、总账、期间汇总、试算平衡；在“更多→财务报表”进入 |
| ACC07 | 月度检查与导出 | 系统列缺少成本/未对账/未分类项；确认后锁定期间，可导出凭证和账表给会计 |
| ACC08 | 完整财务报表 | 资产负债表、利润表、现金流量表，支持来源追溯；期初/模板未配置完整时显示未完成，不能伪造平衡 |

用户已要求完整财务会计，不能把 ACC06～08 永久删减为“只导出流水”。但不需要店员手工编分录：每个核算主体的初始模板 + 常见业务分类即可；老板或会计偶尔处理例外。会计制度、计税和法定报表格式尚未确定，本包仅设计软件能力，不规定税率或宣称满足特定报税制度。

**利润口径**：采购付款不是全部当期费用；已售商品按实际出库批次结转成本。销售净额减销售成本得毛利，再减经营费用及相应盘点损益得经营利润。现金余额另按真实收付统计，老板可以同时看“赚了多少”和“手里多少钱”。未履约订单、成本待补齐等使用“预计”标签，不混入已确认利润。

合成示例（不含税费及其他费用）：采购 10 瓶，每瓶成本 30 元，已全部付款；售出并交付 2 瓶，每瓶 50 元，另付电费 10 元。销售 100、已售成本 60、毛利 40、经营利润 30、未售库存成本 240；本期现金净流量为 100−300−10=−210。系统自动区分这些数，不把进货款再扣一次。

## 5. 扫码点单：顾客先付，付款后自动出库

| ID | 任务 | 规则 |
|---|---|---|
| QR01 | 扫桌码进菜单 | 解析受控门店/桌台引用，服务端验证有效性；显示门店和桌号，不允许二维码自带金额或权限 |
| QR02 | 浏览/加购 | 单品、套餐、数量、缺货提示；顾客无需理解仓库或批次 |
| QR03 | 提交订单 | 服务端重新报价，原子预留组成库存，返回订单和支付状态；价格变化明确让顾客确认 |
| QR04 | 支付 | 使用服务器确认的抵扣及实付金额；关闭页面后仍可从订单恢复 |
| QR05 | 自动出库 | 直接买单付款成功、加餐 AA 付齐成单后原子确认销售出库；基础共享套餐由员工开局备酒触发；移交待上桌/待交付；库存和订单状态立即可查询 |
| QR06 | 取消/超时 | 查清未付款再释放预留；结果未知保持处理中，不能让顾客重复付款 |
| QR07 | 加单/上菜 | 加单是新的可追溯订单/支付，关联同次开台；上菜仅改变履约状态，不再次扣库存 |

本桌已购清单与个人付款明细区分，不能扫码就看其他顾客钱包/个人资料。营业日建议延续 04:00 分界，但需要统一核对，店员无需每日填写。

## 6. 商店：同一商品基础，按需要显示购买方式

| ID | 类型 | 顾客流程 | 店员流程 |
|---|---|---|---|
| SHOP01 | 到店酒水/小吃/套餐/券 | 选择商品→确认到店用途→支付→取货/使用 | 与扫码/收银共用商品库存和订单；券库存/有效期独立 |
| SHOP02 | 实物自提 | 选商品→选店和自提信息→付款→出示取货码 | 待取货列表→验证一次→完成；重复核销拒绝 |
| SHOP03 | 实物配送 | 选商品→填写地址→确认运费→付款→看配送状态 | 待发货→确认发出/记录物流→处理退换；不用先接复杂物流平台 |
| SHOP04 | 链上商品/资产交易 | 显示资产、价格单位、费用和归属→连接/绑定账户→签署明确交易→查看确认→交付资产 | 商品/资产映射、上架/下架、订单查询、异常处置；不让店员手填交易哈希完成交易 |

链上交易不是默认把人民币余额、积分或券都变成 Token；具体资产白名单、发行/转售规则及手续费承担见决策表。到店、自提、配送和链上订单可以先要求分单，避免一单混合多种交付/货币导致操作复杂；此为提案，不删减任何一种购买能力。

## 7. 页面组织提案

不另改全局底栏；在已授权经营入口和商店入口内部组织。

| 页面族 | 日常主要内容 | 次要内容按需展开 |
|---|---|---|
| 经营首页 | 今日收款/毛利概况、缺货、待处理订单、四个入口 | 月度统计、设置 |
| 收银开单 | 商品、购物清单、收款按钮 | 桌台、会员、优惠 |
| 收款结果/订单详情 | 当前状态、商品、支付/交付进度、退款入口 | 流水/审计来源 |
| 经营订单 | 待付款、待交付、售后，日期搜索 | 复杂条件 |
| 库存列表/商品库存详情 | 可售、预留、待交付；采购/入库/盘点按钮 | 批次成本和出入流水 |
| 采购/收货表单 | 选择供应商/商品、数量、单价、已付款/已收货 | 批次日期、部分收货；无自由新增供应商/商品 |
| 每日盘点 | 实点数量、系统差异、确认 | 期间变动与历史复盘 |
| 记账首页/收支表单 | 收支列表、记收入/支出、利润 | 关联凭证和资金账户 |
| 交班页 | 备用金领用/归还、应有现金、实点、差额 | 支付待确认明细 |
| 商品管理 | 名称、售价、图片、可售渠道、上下架 | 套餐组成、单位换算、链上资产设置 |
| 主数据清单 | 供应商、酒水/原料/易耗用品，员工只读选取 | 授权人员可新增/修改/停用 |
| 吧台用酒 | 订单带出用量、手工登记用途/实际量、当日清单 | 开瓶/调拨及理论与实际差异 |
| 商店/扫码菜单 | 分类、商品、缺货、购物袋 | 可用购买方式 |
| 确认购买 | 到店/自提/配送/链上所需字段，合计 | 费用明细、地址、签名信息按需出现 |
| 我的订单/售后 | 支付、交付、自提码、退款进度 | 交易证明 |
| 财务报表 | 利润/资产负债/现金流，月度检查与导出 | 凭证、科目、总账，授权人员可访问 |
| 吧台收银机桌台看板 | 全桌预约/入座/消费/支付状态，点桌查看详情 | 会员历史、订单操作、打印/补打 |

## AA 业务补充（用户最新确认）

参见 [AA 入局、共享套餐与加餐](AA_AND_SHARED_PACKAGE.md)。点单必须提供「直接买单 / 发起 AA」。抖音、美团券自助核销或 App 购买后取得入局权益，按卡座容量和男女配比预定；预定与实际入座分别显示。基础共享套餐在员工确认开局、准备酒水时整桌出库一次，不能逐人核销重复出库。加餐 AA 由发起人设置人数，参与者先付各自份额，人数与款项付齐才成单并整单出库，未成团超时退款。此前“付款立即出库”适用于直接买单；买入局券和单人支付 AA 份额不触发整套出库。
