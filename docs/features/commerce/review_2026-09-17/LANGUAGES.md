# 全平台四语言设计

状态：In Review。用户确认整个软件支持简体中文、英文、繁体中文、泰语。本轮只设计，不修改聊天/登录或公共 App 实现。

## 范围和默认行为

一套业务和数据、四套语言资源，不复制四套独立业务系统。建议语言标识 zh-Hans、en、zh-Hant、th；具体英文/繁体区域变体及译词需评审。语言选择使用原文名称，首次建议跟随系统，用户手动选择后保留偏好；不因切店强制改语言。

覆盖会员端、员工手机端、吧台收银机、通知、错误提示、空状态、帮助、报表和小票，后续开店管理/代运营后台同样遵守。聊天消息等用户内容不因界面切语言而自动翻译；自动翻译不是本次已确认需求。

当前 commerce 分支读取的 pubspec.yaml 未配置 flutter_localizations/intl 直接依赖；lib/src/app.dart 的 MaterialApp.router 未见 supportedLocales/localizationsDelegates；lib 下未找到 .arb 或明确 l10n 资源目录。部分页面/地理查询硬编码 Locale('zh')。这是当前独立分支快照结论，不能替代其他会话最新提交的核验，也不在本会话直接修改聊天代码。

## 文案和数据

界面用稳定文案键与参数，禁止拼接翻译句子。数量、份额、剩余名额、退款进度用完整模板。服务端返回稳定状态/错误码和结构化参数，由展示端翻译；审计保存事件码与原始数据，不能只存一条中文结果。

商品、套餐、用途分类、门店说明等商家内容支持按语言维护；规范商品 ID、规格、配方、库存单位和价格为同一份事实，不能因语言不同变成重复商品。缺少译文时建议展示门店原始名称并标注，不显示空白或伪造翻译。简繁机械转换不能当作专业词汇和品牌名已审核，英文/泰语需有可复核译文；本轮未宣称翻译已完成。

订单保存成交商品/套餐与语言内容版本快照。打印或回看可使用选定语言呈现，但不改变成交金额、商品身份、操作人和审计来源。法律名称、付款商户名和原始凭据保留原文。

## 日期、金额与地区

语言、经营地区、时区、交易币种是不同配置。切到泰语不自动改成泰铢、不改变门店和金额；中文也不代表门店位于中国。交易保存币种与精确金额，展示明确币种，不能只有模糊的货币符号。

事件保存统一时间和门店时区，营业日按门店规则计算；用户查看时清楚显示预约的门店当地日期/时间。日期显示与日历习惯需要评审，预约和小票避免年份歧义。底层业务日期不能跟随翻译变化。

## 小屏和小票

英文长度、泰语组合字符及断行、繁体字形都列入手机/收银机验收；不以固定字数截断金额、关键状态或姓名。字体许可、字形覆盖与性能在实现时验证。

打印端口输出结构化票据，打印机不能直接打印某语言时采用经过验证的字体渲染方案。不能假设热敏打印机内置泰文字库。纸宽、字体、混合语言、二维码清晰度和离线重印均需实际设备验证，尚未完成。同张票可选店内工作语言或会员语言，是否双语由票种配置决定，不默认把四种语言全部挤在一张票上。

## 验收与协作

四语言切换保持同一订单/局/门店和金额；长文、缺译、占位参数、字体缺字、日期币种、通知与小票均有合成场景。阻断性提示不得因缺译变成不可理解的代码。

全软件改造跨会话：本会话负责 commerce 文案清单、契约和验收要求；聊天、注册登录等需由对应负责人协调后接入同一基础，不在主目录直接修改。语言基础和新模块四语言在实际开发前形成独立实施清单。开店/代运营后台四语言随其后续开发交付，不提前建设后台。
