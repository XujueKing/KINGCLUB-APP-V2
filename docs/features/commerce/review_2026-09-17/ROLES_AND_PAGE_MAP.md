# 手机、吧台与权限页面图谱

> 最新已确认规则见 [营业规则确认](CONFIRMED_OPERATING_RULES.md)：活动不限报名人数、开局前分配卡座，按各卡座最小/最大人数开台；加餐 AA 有效 30 分钟，未付齐退 APP 余额；AA 门票酒禁存，单点/购买套餐由购买者存酒、仅原店取、保管 3 个月；券按配置选择使用，成本按进货价；收银硬件第二期。本文较早的冲突描述以该确认为准，技术方案仍待评审。


状态：In Review。角色为简单默认提案，可组合授权，不建立复杂职级树。所有权限按经营主体/门店限制，客户端隐藏按钮不代替服务端校验。

## 1. 默认权限提案

| 动作 | 会员 | 门店员工 | 店长/获授权负责人 | 老板/主体管理员 | 会计（如设置） |
|---|---|---|---|---|---|
| 浏览/预定/点单/参与 AA | 本人 | 可协助，不冒用会员付款身份 | 同员工 | 同员工 | 按会员本人 |
| 存取酒 | 本人申请/出码 | 本店核实与确认 | 本店异常处理 | 授权店范围 | 只读相关账务 |
| 查看桌台/备酒/上桌/交付 | 本人参与的必要信息 | 本店日常处理 | 本店管理 | 授权店范围 | 默认无实物操作 |
| 采购/分批收货/用品领用 | 无 | 选已有目录，按授权录入 | 本店复核/更正 | 授权店范围 | 查关联单 |
| 新建供应商/商品/套餐配方 | 无 | 不允许自由创建 | 需单独授予主数据权限 | 默认允许 | 默认无 |
| 盘点实数 | 无 | 本店录入 | 本店录入/确认差异 | 授权店范围 | 查看差异 |
| 退款、赠送、损耗调整 | 本人提出申请 | 默认只能申请 | 按授权确认 | 按授权确认 | 查相关凭证 |
| 备用金/支出登记 | 无 | 本人经手、授权账户 | 本店交接/复核 | 授权店范围 | 账务核对 |
| 成本/利润 | 无 | 默认不展示 | 可按店授权 | 授权店汇总 | 授权账套 |
| 凭证/结账/账表导出 | 无 | 无 | 默认无结账权 | 可另授财务权 | 授权账套操作 |
| 外部券人工确认 | 出示券/查看自己结果 | 专门核销权限者 | 复核异常 | 授权店配置 | 对账只读 |

同一人可兼店员/店长/会计，但操作记录仍是同一个真实账号。多人共用一个员工账号不能满足“谁操作可追踪”。平台运维身份不默认拥有任意商户退款、核销或查看全部财务的权限。

跨店操作先校验该员工对源店/目标店的对应权限，不能只校验“是员工”。失权后的未提交页面再次提交也要拒绝。终端与操作人分别记录；吧台换班切换员工，不把所有操作写成“收银机”。

## 2. 页面入口与衔接

| 使用端 | 入口 | 下一层 | 回到哪里 |
|---|---|---|---|
| 会员 APP | 地区/门店 | 卡座局列表 → 局详情 → 权益选择/付款 → 我的预定 | 原门店场次，保留筛选 |
| 会员 APP | 桌台扫码/商店 | 商品 → 购物车 → 直接买单/AA → 订单/团进度 | 当前局/订单，不回空购物车重复提交 |
| 会员 APP | 储物袋 | 酒/物/券 → 独立记录详情 → 使用/存取码 → 回执 | 原记录与刷新后的余量 |
| 员工手机 | 工作台 | 待处理桌台/备酒/交付/存取酒 | 当前门店待办 |
| 员工手机 | 库存 | 采购 → 分批收货；出入流水；日盘点；用酒/耗品 | 对应单据或当日列表 |
| 员工手机 | 收银/记账 | 开单/收款；支出；备用金；交班 | 原班次/原单 |
| 吧台收银机 | 桌台看板 | 局详情、预定/入座、共享套餐、加餐 AA、交付和小票 | 原桌卡保留选中 |
| 老板手机 | 门店/汇总 | 收支利润 → 来源单；异常 → 处理；主数据 | 原汇总范围 |
| 财务入口 | 更多 → 财务报表 | 凭证/总账/对账/月检/导出 | 当前账套和期间 |
| 后续独立后台 | 开店管理/代运营 | 本阶段不建设页面 | 后续单独规划 |

手机工作台优先显示今天需要处理的事项，低频主数据和报表放二级入口；不为了支持平台化让每个员工每天选择组织树。返回/切语言保留所属店和原单，切店不得悄悄改变草稿归属。

## 3. 各页必须一致的反馈

- 加载、空数据、无权限、离线、处理中、失败、已完成分别有明确状态；没有接口的功能不展示伪造成功。
- 写操作一键提交后保留原请求身份；再次点按先查原结果，不生成第二个财务/库存动作。
- 手机与吧台的实时通知是刷新提示，服务端查询为事实；断线恢复拉取当前状态，不要求人工重新录单。
- 小票使用已确认快照；打印机故障留待打印，不回滚付款，不要求顾客再付。
- 四语言使用同一字段和状态，商品、金额、数量、门店和操作后果不能因翻译不同而变化。
- 顾客申请/员工核实/负责人确认只用于确有权限差异的动作，不把每笔正常入库、备酒做成多级审批。
