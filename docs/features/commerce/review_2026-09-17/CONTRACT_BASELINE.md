# 经营数据与接口统一约定 v0.1

后续细化见 [核心字段与操作契约](CORE_DATA_CONTRACTS.md)。经只读核对现有传输层，业务去重键统一建议为 `commandId`，与已有传输上下文 `requestId` 区分；下文及较早页面中的业务 requestId 语义按此映射，正式 DTO 定稿时统一替换，不能修改或绕过握手防重放协议。

更新：2026-09-18。状态：In Review；设计草案，不是已注册接口或迁移脚本。适用于 [页面索引](pages/README.md)。正式 CCSOP 接口编号、现有对象映射及数据库字段仍需核对，不能直接按下列语义名调用生产服务。

## 1. 通用字段与边界

| 字段 | 草案约定 |
|---|---|
| tenantRef / storeRef | 经营主体与门店字符串 ID；服务端校验从属及访问范围，地区不是权限边界 |
| actorRef | 服务端从登录会话取得，不接受客户端指定操作人；代办另记 subjectRef |
| requestId | 客户端为一次业务意图生成并保留的字符串，重试不换 ID |
| expectedVersion | 对象版本；写入时比对，冲突要求读取差异，不能静默覆盖 |
| amountMinor / currency | 最小货币单位整数及币种；不得浮点计算金额，传输与存储须检查整数范围 |
| quantity / unit | 精确十进制字符串及明确单位；商品定义精度和换算，不以二进制浮点结算数量 |
| occurredAt / recordedAt | 业务发生时间与服务端记录时间分别保存；标准带时区时间，门店时区用于展示 |
| businessDate | 服务端按门店营业日配置派生，不能直接用手机当前日期 |
| sourceRef / sourceType | 原报名、订单行、出库行、支付或保管操作的可追溯引用 |
| status / allowedActions | 服务端事实及可执行动作；客户端隐藏按钮不能替代校验 |

ID 不按数值运算，不用姓名、券面名称或桌号代替跨店唯一引用。历史名称、价格、配方、优惠与配置保留版本快照。语言切换只改变显示，不改变对象或报价身份。

## 2. 状态必须分开

| 对象 | 草案状态及边界 |
|---|---|
| 活动 | 草稿/开放报名/停止报名/结束；活动报名无人数上限 |
| 报名 | 待分配/已分配/已入座/人工失效；退票另有进度，不以失效表示到账 |
| 卡座本次开台 | 待开台/营业中/已结束；每桌最小/最大人数与配比快照，达到最小可人工开台 |
| 加餐 AA | collecting/forming/formed/closing/refunding/closed；30 分钟窗口由服务端控制 |
| 支付 | 待付/处理中/成功/明确失败/结果未知；未收到通知不等于失败 |
| 履约 | 待备/待交付/部分交付/已交付/异常；出库与交付分别记录 |
| 退款 | 待处理/处理中/部分成功/成功/结果未知/需处理；按每笔付款跟踪 |
| 保管 | 待收存/可取/已取尽/到期；到期不等于实物销毁，取用申请另有状态 |

状态名称需在正式契约统一编码；不能各页面自行拼不同含义的“完成”。付款、出库、收入确认、交付、退款分别有事实，报表不得用一个订单状态推断全部。

## 3. 防重复、并发和补偿

通用请求去重建议按主体、动作、requestId 定位，并保存规范化请求摘要。同键同内容返回原结果，同键异内容返回冲突；不能用临时缓存替代永久业务约束。一次意图失败后的重新操作须重新报价/检查状态，不能盲目换键重发。

| 业务动作 | 事务内必须保护的事实 | 后续或失败处理 |
|---|---|---|
| 活动报名 | 有效权益占用、重复报名检查、报名记录 | 不占具体卡座或整桌库存；人工退票单独处理 |
| 分座 | 报名当前分配、卡座本次容量/配比及配置版本 | 自动/手动共用约束；换座原子释放旧分配并占新位 |
| 直接订单 | 报价快照、优惠占用、库存预留、订单身份 | 外部付款不纳入数据库事务；未知结果查原支付 |
| 付款确认出库 | 支付成功事实去重、有效预留转换、出库来源唯一 | 已关闭订单迟到付款进入退款处理，不擅自复活 |
| 基础套餐 | 每次卡座开台唯一履约、组成库存及批次成本 | 整桌一次出库；同活动多桌各自有履约单 |
| AA 成团或到期 | 团状态、付款份额和金额、截止时间、整单预留 | 最后一笔确认与到期任务互斥裁决；关闭后迟到实收退 APP 余额 |
| AA 余额退款 | 原付款可退额度、退款事实、对应主体会员余额与流水 | 失败重试原操作；不得再原路退款一遍，不修改原渠道收款事实 |
| 存取酒 | 来源可存量/资格、保管记录版本、本次量、码用途和消费状态 | 码预览不消耗；确认去重；保管账与可售库存分开 |

内部事件与可靠待办建议同事务记录，异步消费者按业务来源去重；外部副作用未知时查询或对账，不认为本地回滚撤销了外部付款。锁粒度、顺序、隔离级别和索引须在最终表结构与并发测试方案中定稿。

AA 截止规则建议按服务端确认进入成团裁决的时间计算；边界同时到达只能有一个终态。供应商时间戳不能未经验证覆盖已关闭团。具体有效时间边界需在支付适配契约明确，不能依赖客户端倒计时。

## 4. 统一错误与页面动作

以下为建议错误语义，不是现有服务错误码。

| 语义 | 页面动作 |
|---|---|
| SESSION_EXPIRED / SCOPE_DENIED | 重登后查原单 / 返回有权范围，不自动替用户切主体提交 |
| VERSION_CONFLICT | 读取最新对象，展示变化后重新确认 |
| IDEMPOTENCY_CONFLICT | 保留原单并提示请求内容不一致，禁止用旧键换金额 |
| STOCK_INSUFFICIENT / CAPACITY_CONFLICT | 列缺量或卡座条件；失败不得部分占用未声明资源 |
| COUPON_INELIGIBLE / COUPON_IN_USE | 展示适用原因或占用订单，重报价格 |
| PAYMENT_UNKNOWN / REFUND_PENDING | 显示处理中并查原操作，不再次付款/加余额 |
| CUSTODY_INELIGIBLE / WRONG_STORE | 显示来源禁存或原保管店，不提供绕过核销 |
| PERIOD_LOCKED / POLICY_MISSING | 到更正或配置入口；不硬编码会计/退款政策 |
| CHANNEL_NOT_ENABLED | 提示能力未接通；已有 APP 券仍正常使用 |

成功/处理中响应建议包含 operationRef、requestId、objectRef、status、version、allowedActions；错误附 fieldErrors 或 reasonKey、必要参数，四语言由资源映射。未知不是可安全重试新单的标志。
