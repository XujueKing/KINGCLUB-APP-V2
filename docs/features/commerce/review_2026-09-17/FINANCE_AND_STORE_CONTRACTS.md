# 记账、利润与商店详细流程草案

状态：In Review。补充核心经营流程，所有用例名为语义名称，不代表正式 API 已注册。用户仍须先评审需求与架构，本轮不编码、不导入旧数据。

## 1. 记账首页与收支录入

日常首页展示当前门店、营业日、本日实收、退款、支出、资金余额和利润状态。成本未齐或尚未交付时明确显示“待补成本 / 预计”，不将未知成本视为零。老板多店汇总只包括有权门店，按币种分别显示，不直接相加不同币种。

员工点“记支出”后选择业务分类、金额、支付账户和日期，可附票据、备注。选进货付款时关联采购单；选备用金补充时转为资金调拨；不能把两个场景都作为普通费用。订单销售、会员充值、第三方核销等由来源自动记账，手工录入页提示避免重复。

“记收入”仅用于尚无业务来源自动记录的收款；资金转入、借款、业主投入等使用明确分类，不默认记为销售。具体分类与凭证模板由核算主体初始化，日常无需填借贷科目。

用例：ListCashEvents、PreviewIncomeExpense、ConfirmIncomeExpense、CorrectIncomeExpense。提交金额/币种、业务分类、资金账户、发生时间、来源单与附件引用；服务端校验店、主体、权限及期间。草稿可改；已确认记录以关联冲正和新记录更正，不删除来源历史。附件查看权限随单据，不以可猜 URL 公开。

## 2. 利润详情：每个数字都能追到业务

| 数字 | 来源和展示约定 |
|---|---|
| 已确认销售净额 | 已履约销售及对应退款/折扣，不包含尚未消费的会员充值或仅发出的券 |
| 已售成本 | 实际销售批次/套餐组成成本，保留成交时成本快照及后续合法调整 |
| 毛利 | 已确认销售净额减已售成本 |
| 经营费用 | 已确认费用及适用损耗/盘点差异；不重复扣整笔采购付款 |
| 经营利润 | 按明确模板汇总，能展开费用及差异来源；未配置完整时标明不完整 |
| 手里多少钱 | 各资金账户真实余额，现金/银行卡/渠道待结算分开 |
| 待结算款 | 渠道业务已发生但未到账，到账只结清待结算，不再记第二笔销售 |

用例：GetOperatingSummary、GetProfitBreakdown、GetSourceDocuments。列表先按本店营业日，查看跨日退款时可追原销售和本次退款；期间口径由账套规则决定，不能用客户端日期临时重写过去利润。

人工第三方核销是来源录入方式，不代表银行已收现金。存酒是保管数量变化，不生成第二笔商品收入。AA 各人收款对应一笔加餐，成本按整单一次计算；基础共享套餐按局归集一次。

## 3. 会员资产、佣金与对账

会员页面区分充值余额、赠送权益、券、积分及佣金，不默认全部可提现或跨店通用。每次变动记录发行主体、来源、使用范围、可用/冻结和退款状态。授信能力保留原审计范围，但不启用先消费后付款的默认经营方式。

员工只能看到完成当前订单所需的可用权益摘要；个人跨店历史不向其他经营主体公开。佣金规则版本、生成条件、待确认/可结算/已结算/冲回分别保存，退款不能悄悄删除已付佣金。

对账页按门店/渠道/日期列“内部记录、渠道记录、差额、待处理”。导入渠道对账文件如未来需要，需独立授权及字段校验，不等于获准导入旧业务数据库。当前文档仅定义记录匹配和差异处理。

用例：GetMemberAssetStatement、GetCommissionStatement、ListReconciliationExceptions、ResolveReconciliationException。对账更正记录操作者和原因，不能靠直接改钱包余额使差额消失。

## 4. 会计查看与月度检查

高级入口展示凭证、科目、明细账、总账、试算平衡与三张报表；普通员工不必进入。每个核算主体独立设置期间、期初、模板及权限，门店作为经营维度；平台整体统计不混成一个法定账套。

凭证来源事件唯一，借贷平衡后才能过账；已过账修改通过冲正，锁定期间不能直接回写。月度检查列成本缺失、未分类、待退款、渠道差异和不平衡等项目。真实未完成项目不能被“确认”按钮抹去。

用例：ListVouchers、GetVoucherSource、PreviewPeriodClose、CloseAccountingPeriod、RequestPeriodCorrection、ExportLedger。是否允许带某类未完成项结账、反结账权限、收入确认/税务政策仍待专业模板确认。本文件描述软件约束，不规定法定会计制度或税率。

## 5. 商店商品与购买方式

会员先确认地区/门店。商品页显示商品规格、套餐内容、适用会员权益、售价币种、可售/缺货、可选履约方式和必要限制。商品内部唯一，显示名称可以四语言；门店价格、上下架、可售量分别维护。

用例：ListStoreProducts、GetProductOffer、QuoteStoreCart、CreateStoreOrder。服务端依据门店、商品版本、数量、权益及履约方式报价。到店、自提、配送、链上是否允许混单，当前建议分单简化；这是待审建议，不能悄悄删掉任一模式。

实物、券和链上资产分别绑定对应库存或可发行额度，不能拿实物库存状态代表链上资产可交割。

## 6. 自提

确认页填写提货门店、时间范围、必要联系信息，展示商品和最终金额。付款成功按实物订单规则出库并进入待备货/待自提；未交付部分保留物理位置及责任，不参与再次销售。

自提页显示当前状态及短期取货码。员工扫码先看订单和本次数量，确认实际交付后核销。多人重复扫或响应丢失只确认一次。取货码不是存酒码，作用域和业务类型必须不同。

用例：GetPickupOrder、IssueOrderPickupCode、PreviewOrderPickup、ConfirmOrderPickup。支持部分交付时，逐明细记录已交和剩余；整单完成仅在全部交付后发生。错店、退款中、已取消、码过期、无权限均不得交付。

超时未取不能自动销毁商品或当作顾客已收到。保管时限、退款/联系处理待确定；员工可看到待处理，不需维护复杂物流系统。

## 7. 配送

确认页收集收货人、电话、地址和可配送范围所需字段，显示运费与预计处理时间。地址在提交前校验，付款后改地址须重新判断配送范围、费用及授权，不能静默改已发货订单。

员工处理待备货、待发货、已发出、已收货/交付异常；可按明确方式记录承运信息，不强制接物流平台。填写单号不等于已送达，原物流信息更正保留历史。

用例：QuoteDelivery、ConfirmShipment、RecordDeliveryResult、RequestReturn、ConfirmReturnedGoods。每次发货关联明细及数量，部分发货不能把全单标完成。收货/签收证据及超时确认规则待定。

退款与退货入库分开：已退款但未退商品不自动回库；员工确认实收且可再售才按规则回库。破损、开封和不可再售各有处置记录。退款拆分原支付组成，不超过已收和可退额度。

收货地址仅供有权履约人员读取；跨店汇总和小票按必要程度脱敏。四语言不改变地址原文，打印失败不重发货。

## 8. 链上商品：先定义能力边界

范围继续保留，但具体资产、网络、计价、托管/签名账户及发行/转售尚未确定。因此本段为条件契约，不宣称已有可交易产品，也不将会员余额/券自动 Token 化。

商品页需明确售卖资产、网络、数量、价格单位、费用承担和接收账户。确认前展示不可与普通实物混淆的交割对象；用户签名必须对应明确意图，服务端不得代签。

用例：GetChainOfferCapabilities、PrepareAssetPurchase、SubmitSignedIntent、GetChainOrderStatus、GetVerifiedAssetReceipt。实际映射 SUPERVM/NOVOVM 能力需验证，不能把这些语义名当现成节点 API。

状态区分待签名、已提交、结果未知、确认中、已交割、失败及人工处理；只有校验网络、资产、数量、收付账户、费用及最终性条件后才确认业务交割。txHash 或网络 ACK 不足以证明成交；断线重试复用原意图，不再次付款。

链上已执行的交易不能用本地“退款”回滚。若销售包含链外资金与链上交割，必须先审定托管/锁定、超时、交割失败及退款方案；未明确前不开放真实购买。供应不足、签名拒绝、网络错配和重复回执都有独立结果。

## 9. 验收与待定项

追加合成场景：采购付款与成本不双计；充值再消费不双计收入；AA 多人付款不多计套餐；渠道到账不重复销售；不同主体/币种不混算；已过账/锁期不直接改历史；自提重复/错店不交付；部分发货/退货准确；链上未知不假成交、错误资产回执不完成。

本轮未执行业务测试。详细 UI 尺寸、最终字段索引、正式接口编号、会计模板和真实链上商品配置仍需逐项冻结。第三方自动核销按用户最新决定延期，员工人工过渡仍为待评审方案。
