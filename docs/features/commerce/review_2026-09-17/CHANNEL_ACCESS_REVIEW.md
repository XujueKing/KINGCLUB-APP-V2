# 团购官方接入实查：商户端与开发者端

日期：2026-09-17。状态：In Review。用户授权登录官方平台查资料并协助扫码。本轮仅浏览页面，不新增授权、不创建应用、不读取密钥、不调真实核销。

## 1. 账号可见事实

抖音来客已登录并读取「店铺管理 → 合作授权」。页面包含「SaaS 系统授权」和「自研 SaaS 绑定」。前者当前显示暂无服务商；后者显示开发者数量 0，同时列表区域有加载失败提示，因此不能据此断言账号绝无任何历史开发者绑定。自研绑定说明会自动授权该自研服务下全部应用能力，本轮未点击绑定提交。

面向不同老板/品牌的平台，应优先评审技术服务商路径，各商户独立授权；单店自研绑定不能直接当作服务所有租户的全局授权。经营宝/来客已登录与开发者应用具备 API 权限是不同事实。

美团经营宝标签存在，但读取时遇到连接问题；另开官方技术服务合作中心后成功读取公开 API 文档。开发者站显示登录/注册，点击后进入美团 App 扫码登录页，已交给用户完成。尚未核实该开发者账号的入驻、应用、业务授权状态。

## 2. 美团官方 API 已核对

以下均为浏览器实际打开的官方文档，替代此前“未读到美团契约”的阶段性结论。端点确认不等于本商户已取得调用权限。正文为归纳，不包含真实券码、账号令牌或示例凭据。

| 能力 | 官方文档 | 已确认要点 |
|---|---|---|
| 新版预验券 | [验券准备（新）](https://developer.meituan.com/docs/api/tuangou-ng-coupon-msprepare) | POST /tuangou/ng/coupon/msprepare；返回券种、套餐、可验数量和限制信息，预查询金额仅供参考 |
| 新版核销 | [执行验券（新）](https://developer.meituan.com/docs/api/tuangou-ng-coupon-msconsume) | POST /tuangou/ng/coupon/msconsume；code、num、idempotent；相同幂等键返回原结果，因此本地必须同时固定请求内容 |
| 已核销查询 | [已验券码查询](https://developer.meituan.com/docs/api)（目录 5.2） | POST /tuangou/coupon/queryById；用于已验证券，不能当未核销券查询 |
| 撤销 | [撤销验券](https://developer.meituan.com/docs/api/tuangou-coupon-cancel) | POST /tuangou/coupon/cancel；须检查具体券可撤销性。文档提示撤销可能使旧码作废并重发，不能假定原二维码恢复 |
| 会员自助查询 | [查询用户授权门店可核销券](https://developer.meituan.com/docs/api/tuangouself-coupon-query) | POST /tuangouself/coupon/query；独立业务，文档示例 businessId=33 |
| 会员自助核销 | [执行验券](https://developer.meituan.com/docs/api/tuangouself-coupon-consume) | POST /tuangouself/coupon/consume；codes 和 idempotent 必填；幂等因子结合授权门店，文档标明缓存 5 分钟 |

上述端点均在 https://api-open-cater.meituan.com。普通团购示例 businessId=1，与自助业务不能混用；最终授权业务 ID 按实际开通能力确定。公共请求示例使用 appAuthToken、developerId、timestamp、sign 等及表单编码；签名规则与授权流程还需逐页审读，不能只复制示例请求上线。

设计落实：
- 本地永久业务去重不能依赖自助接口的 5 分钟缓存；超过渠道窗口仍须查询/对账确认结果。
- 本地存袋/订单用途、金额、数量、门店与请求摘要固定，不能换了订单仍复用同一幂等键。
- 商品长 ID 按不丢精度的标识处理；套餐名不是唯一映射键。
- 成功需同时验证公共状态、业务结果与实际核销明细；订单直接用券不得再发可用 APP 券。
- 用户自助通道与店员核销通道作为独立授权能力评审，不能把店员权限暴露给会员。

## 3. 抖音服务商接入要求

[技术服务商入驻指南](https://developer.open-douyin.com/docs/resource/zh-CN/local-life/connect/partner/tech-service-entry-guide) 明确了服务商认证、第三方生活服务商家应用、解决方案能力、配置、测试验收、上线和商家授权步骤。平台多商户设计应以这条路线核对资质；本轮没有代填认证或签约。

该指南还强调业务核销结果判定、异常重试及信息同步；这对应本地“核销成功后发券/入账”和退款撤销同步，不能只做一个扫码调用。若接入平台回调，验签需保留原始请求体，不反序列化再序列化后验签。具体能力仍以目标应用的实际授权和相应接口契约为准。
