## 主要发现

- 旧扫码点单有商品列表、购物车、混合支付、订单和上菜链路；不是五个模块均已完整实现。
- 小程序“收银台统计”实际是加速度计计分页；后台虽有通用数据管理页，但还不能据此认定完整营业收银、交班和日结闭环。
- `k_warehouse` 是入库/出库/盘点登记；`k_goods_detail` 是套餐组成；`k_shop_thing` 是店内物品巡检；`k_subject` 是内容话题。不能只按英文表名建新模型。
- 旧订单区分开台/预约订单、一次付款的标准订单和支付交易；`goodsStatus` 表示上菜，不表示支付或库存。
- 旧库有事务、回滚与重复支付状态检查，应保留其业务意图；本地快照也存在待核实的金额信任、回调和源码/结构不一致，不能原样搬入新系统。
- 当前 App 的 commerce 仍是 Fake；CCSOP 支付适配器仍为 Mock。SUPERVM 有交易/回执基础，但没有找到完整 KINGCLUB 商店适配闭环。

## AA 业务补充（用户最新确认）

参见 [AA 入局、共享套餐与加餐](AA_AND_SHARED_PACKAGE.md)。点单必须提供「直接买单 / 发起 AA」。抖音、美团券自助核销或 App 购买后取得入局权益，按卡座容量和男女配比预定；预定与实际入座分别显示。基础共享套餐在员工确认开局、准备酒水时整桌出库一次，不能逐人核销重复出库。加餐 AA 由发起人设置人数，参与者先付各自份额，人数与款项付齐才成单并整单出库，未成团超时退款。此前“付款立即出库”适用于直接买单；买入局券和单人支付 AA 份额不触发整套出库。

## 平台化补充（用户最新确认）

[平台、多经营主体与多门店](PLATFORM_AND_STORES.md) 为本包归属与隔离规则。平台服务不同老板、不同品牌、多地区多门店；地区用于发现，经营主体用于隔离，门店用于实际经营。此前单店/一套主体模板只可解释为单个核算主体的简单默认，不能解释为全平台共用库存、钱包、收款或总账。手机、订台、AA、收银、打印及统计均须带正确范围。
