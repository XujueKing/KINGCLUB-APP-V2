# Native video capture targets

Installed flutter_webrtc 1.6.2+hotfix.1 Android GetUserMediaImpl.getConstrainInt checks outer constraintsMap.getType("ideal") instead of innerMap when the width/height/frameRate value is a map. Our nested ideal targets therefore fall back to default 1280x720@30. Group intended 640x480@24; direct intended 1280x720@24. Use numeric width/height/frameRate values supported by the actual parser. These remain device capture targets, not guarantees of exact camera sensor output. Existing group bitrate cap is unchanged; direct WebRTC congestion control remains in charge of its bitrate. No UI changes.

Validation: 39 direct/group media tests and four-file static analysis passed. Executed the installed plugin getConstrainInt method (unchanged except public/static visibility and removal of Android annotations) with its real ConstraintsMap/ConstraintsArray/ObjectType: nested ideals returned null, numeric group targets returned 640/480/24. Harness marker ACTUAL_VIDEO_PARSER_NESTED_TARGETS_LOST_NUMERIC_640_480_24_PASSED, build/audio-parser-check/VerifyVideo.java. This does not prove actual hardware capture resolution, delivered frame rate or bandwidth. No plugin cache modifications, no APK rebuild or phone installation; current 72902aa APK predates this patch.
