# 文件首批数据等待预算

32MiB 实机验证中 peer 阶段约 9.7 秒、零接收后才进入 HTTP。当前慢中继策略必须先收到数据才启动采样，无法改善完全无数据的等待。

首次优先尝试 peer 时，在恢复缓存后给予 3 秒首批新数据预算；若依然没有新增文件字节，关闭该文件接收尝试并走既有授权 HTTP 回退。连接本身已有独立 3 秒限制，因此不声称整个下载必定 3 秒内开始。

已开始接收数据的传输仍采用原有空闲、慢中继和总时限；恢复缓存不算网络进展。HTTP 失败后的 peer 救援不启用该短预算，避免两条路径都弱时反复提前放弃。取消、会话撤销、删除、摘要和权限检查保持不变，不关闭共享消息通道。

验证：增加 silent-peer 案例，断言 6 秒内通过 HTTP 获取全部分块并校验最终文件，区别于旧的 8 秒接收空闲超时。继续检查正常 peer 与 HTTP 失败后的反向恢复。

本轮结果：文件路径的 9 项跨通道检查全部通过（包括无响应、慢速直连、慢中继、损坏内容及反向恢复），静态检查无问题。无响应案例日志为 `no-first-data HTTP handoff`、peer 阶段约 3007ms；这是受控测试结果，不是手机实测耗时。
