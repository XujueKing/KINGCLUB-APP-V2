# UDP 到 HTTP 的部分文件交接

认证 UDP 碎片按原位落盘。接收任务关闭前，仅提取覆盖碎片全部到齐的 1 MiB
范围（尾块允许更短），写入同账号、消息、文件标识及整文件摘要绑定的加密缓存。
读取与写入串行，避免与接收写入/临时文件清理竞态；每块复核会话和删除状态。
HTTP 回退重新授权后读取这些范围，只下载缺块，最终校验原消息整文件摘要。

这些只是认证传输得到的完整分块，不标记为整文件验证成功、不允许离线导出，
也不伪造完成回执。摘要不符仍清除缓存并报错。缓存与 HTTP 自身的完整分块一样，
只有整文件验证完成才能转为持久化完成态。主动取消/关闭页面保留已完成的加密分块；退出账号或删除消息不续存（2026-09-21 修正，见 ../2026-09-21-peer-cancel-resume.md）。

两个方向已接入 ChatFileDownloader。HTTP 连续三次失败后重新授权并尝试设备通道，
接收器导入消息绑定的缓存，跨分块边界的碎片必须两边数据均存在。已有健康 HTTP
续传仍优先继续，不为切换强行中断。

反向集成案例验证 HTTP 首块成功、后续失败，设备接收器导入首块后仅接收剩余
碎片，完整文件及临时文件清理正确。实际 ChatFileDownloader.open 通过
NovoRudpBindingRuntime → MemberRelayFiles → PeerFileChannel 传入准备回调，
在第一个 REQUEST 前完成导入；单聊/群文件共用此入口。返回后不重复导入。
peer_file_prepare_test 验证准备等待及准备期间取消不发送 REQUEST；与双向交接
共 5 项测试通过，修改文件静态检查通过。真实原生发送方及公网双机仍待验证。

验证：不对齐边界/缺口导出、接收回执、HTTP 下载和续传共 43 项自动测试通过；
修改文件静态检查通过。

新增 udp_http_handoff_test 使用真实接收临时文件、加密缓存、ChatFileDownloader
和模拟认证帧/HTTP 适配器，验证三块文件接收首块后通道中断，HTTP 仅请求索引
1、2，最终逐字节一致且清理临时文件。注入损坏首块时最终摘要拒绝并清空缓存。
两个集成案例通过；这证明应用内交接，不代表真实 UDP 网络或双机验收。
