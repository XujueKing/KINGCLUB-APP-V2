# Video retry source identity

A ChatVideoOptimizer instance reused its prepared file before inspecting the current source. Replaced bytes (including same-size/same-path files) or a subsequent small source could return a prior video's upload copy. Before reuse, compute the existing account-and-content key off the UI isolate; only reuse when that key matches. Small/unsupported inputs clear the prepared association and return the supplied original. Missing output still regenerates; native encoder failure still retains the original. No file is deleted before queue ownership. Tests must cover changed bytes and a small replacement alongside stable retries.

Validation: 18 optimizer/file-send recovery tests and two-file static analysis passed. Replaced source bytes with unchanged path, size and timestamp produce a different content key and new prepared copy; replacing with a small file bypasses the old cached video. Existing tests retain stable-source compression reuse, original fallback, evicted-copy recovery and queue-owned retry behavior. Hashing remains off the UI isolate but rereads the original on retries; large-file device latency is not yet measured. No APK rebuild or phone installation.
