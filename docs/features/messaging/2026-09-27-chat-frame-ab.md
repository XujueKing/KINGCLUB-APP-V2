# A/B 会话渲染时间线采样

## 版本与方法

使用已覆盖安装的正式包 `com.lingmei.kingclub` profile APK，SHA256 `D1420F666D2B696187D7F805BCB446AF737FFD418A7B3592F791F0F13BDD9F70`。仅操作已授权 A/B，未操作第三台手机。

Android `dumpsys gfxinfo` 只返回 7 个原生窗口帧，不能代替 Flutter 内容渲染统计，因此未据其判断会话流畅度。改通过当前进程的本机 Dart VM service，临时采集 Dart/Embedder 时间线；结束恢复原 recordedStreams，移除本次端口转发。

从时间戳排序后的 `Frame` 与 `GPURasterizer::Draw` begin/end 配对，按线程和事件 ID 归属计算完整事件耗时，排除截断事件。P95 取升序数组 floor(0.95*n) 项。16.67 毫秒仅作 60 Hz 单阶段参考线，不能把两个阶段的超限数相加当作实际掉帧数，也不代表真实呈现延迟、GPU 完成时间或高刷新率验收。

## 结果

| 场景 | 完整 UI/光栅化样本 | UI P95 / 最大 ms | 光栅化 P95 / 最大 ms | UI / 光栅化超过 16.67 ms |
| --- | --- | --- | --- | --- |
| A 四轮键盘弹出/收起 | 309 / 309 | 6.132 / 12.190 | 8.097 / 17.014 | 0 / 1 |
| B 四轮键盘弹出/收起 | 329 / 329 | 7.051 / 18.866 | 7.690 / 20.444 | 1 / 2 |
| A 发送一条测试文字，采集约 3 秒 | 108 / 108 | 5.814 / 12.636 | 7.021 / 10.970 | 0 / 0 |
| B 同期接收该文字 | 106 / 106 | 2.085 / 32.657 | 7.044 / 11.950 | 1 / 0 |

测试文本为 `AB_UI_SMOOTH_0927_01`。两端 UI 均各出现一次该文本，A 输入框不再含该文本，证明本次发送和接收的可见结果；不是服务端去重审计。发送时 A 键盘打开，B 键盘关闭。

B 的 32.657 ms UI 帧内，主要顶层构建约 16.599 ms、布局约 11.287 ms、绘制约 2.405 ms。这里只定位到阶段，尚未定位到具体 Widget，也不能把一次采样归因于网络、头像或某一段代码。没有为得到漂亮指标临时关闭头像、移除历史或改动画。

## 结论与未完成项

本轮获得了两种设备上的真实 Flutter 阶段耗时，而非仅凭主观印象。仍存在少量长帧，尤其 B 接收首条测试消息的 UI 帧；会话 UI 性能验收保持进行中。

没有采集首次进入会话的完整转场，也未证明像素位移连续、输入框与系统键盘完全同步；长历史、媒体消息、连续消息和高刷新率场景尚需补充。用户对最终观感的验收也不能由这组耗时替代。

原始时间线及 UI 转储留在聊天隔离构建目录 `build/chat-frame-*.json`、`build/chat-perf-*.xml`，不提交潜在包含设备/会话数据的原始转储。本轮未修改生产 UI 代码。

## 后续：限制屏外预构建范围

检查发现会话 ListView 的上下预构建各为 640 逻辑像素。后续调整为 250（与本机 Flutter SDK `RenderViewportBase.defaultCacheExtent` 相同），减少每次消息更新可能牵涉的屏外行，不改消息分页、持久化、头像缓存、动画或历史数量。这里仅修正预构建范围，不把它称为 B 长帧的根因修复。

发送滚动、历史、页面切换和引用消息 4 个测试文件共 22 项通过，修改页面 analyze 通过。测试过程出现已有 SQLite `CastList<int,int>` 参数警告，未导致失败，本次没有改变数据库写入代码。
