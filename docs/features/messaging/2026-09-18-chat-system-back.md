# Conversation system-back handling

Observed A briefly backgrounding on Android Back while the conversation remained mounted. Do not assume its cause from one screenshot. Verify the router's imperative KingPageRoute back path separately. Confirmed source gap: composer panels have no back interception. Add PopScope so a visible attachments/emoji/gifts panel consumes Back and closes, while ordinary route pop and draft preservation remain unchanged. Native backgrounding remains a separate device follow-up.

Implemented PopScope around the conversation with panel-dependent canPop and the existing dismiss handler. A GoRouter + imperative KingPageRoute widget regression passed normal Back before the change, but both attachments and emoji cases incorrectly popped the conversation. After the fix all three cases pass: first Back closes a panel, subsequent Back returns to the previous route. Existing composer and text-draft regressions also pass (15 total); changed-file analysis passes. Logs: build/chat-system-back-before.log, build/chat-system-back-after.log, build/chat-system-back-analyze.log. This does not explain or claim to fix the separate Android activity-backgrounding observation. Not packaged or installed.
