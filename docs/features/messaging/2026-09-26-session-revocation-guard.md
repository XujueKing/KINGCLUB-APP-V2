# 撤销通知与当前登录隔离

发现：App 收到 `auth.session.revoked` 后直接清空当前登录。服务端通知已经携带 `data.sessionId`，但客户端没有核对。已排队的旧会话通知可能清除后来保存的新会话；不能据此断言它就是 B 此次登录失效的唯一原因。

修正范围：在安全存储的串行修改区内核对通知会话编号，仅清除同一会话。缺少编号、不同编号、重复撤销不改变当前登录。相同会话的凭据轮换不应阻止真实撤销。清理后若已有新登录，则不再跳转登录页。保留服务端撤销规则，不放宽登录有效期。

验证计划：旧通知与新登录并发、当前会话正常撤销、轮换后撤销、空编号与重复事件，以及既有迟到刷新回归。实机 B 的失效原因仍需后续复现核实。

完成：新增 3 项撤销保护测试与既有迟到刷新测试合计 11 项通过，修改文件静态检查无问题。隔离包构建成功并覆盖安装到 A、B，安装均返回 Success，未清应用数据。APK SHA256：`202CD486E6BECCA1DB458513E6ABA1AF3EC365F8118B38826D2344FEB60B83E4`。本次没有实机注入撤销事件，不能将安装成功记作 B 掉登录问题已全面验收。

另查明仓库当前登录过程 `027_kingclub_independent_mobile_members.sql` 按会员及 clientAppCode=kingclub 撤销所有已有活动会话，不按 APK 包名隔离。因此同一会员在商店预览版重新登录会与聊天预览版发生会话互斥；单纯切换应用不触发此规则。该结论来自源码，未查询线上 B 的撤销审计，不能断言其本次具体退出原因。未修改服务端单会话策略；并行预览宜使用不同测试会员。
