# 聊天静态图片上传接入

用户持续开发授权下接通真实图片链路，保持现有照片／拍摄入口与会话布局。

## 当前模块

- ChatImageUploader 调用 631 获取本人图片上传记录及短期凭证，以 AES-256-GCM 发送独立二进制请求，AAD 绑定账号、图片摘要、大小和上传记录。禁止跟随重定向携带凭证。
- 本地安全存储仅保存账号隔离的上传幂等 ID，不存凭证或图片字节。上传成功但响应丢失后，重选相同图片可复用 ready 记录；只有图片消息写入持久发送队列后才确认删除上传 ID。
- 会话变化取消当前请求；每个异步阶段检查身份，迟到结果不能进入新账号会话。源文件上限 20 MiB，服务端处理静态图并生成预览。
- 这是客户端到服务端的上传加密，不等同聊天双方端到端加密。

## 验收及未完成项

客户端测试覆盖实际二进制加解密、上传提交后丢失回执、重建上传器后的 ID 复用、消息入队后释放 ID、超限输入、会话切换和错误账号凭证。

尚未接入照片／拍摄按钮与接收图片气泡；重启后未完成上传需要重新选择原文件，并非完整离线附件队列。群图片、断点续传、孤立文件清理及双机真机验收未完成。服务端 053–056 仅隔离数据库验证，尚未部署到共享测试服务。

## 照片／拍摄入口进度

真实单聊的照片／拍摄已调用系统 ImagePicker，检查文件大小后进入独立预览页，明确点击发送才调用上传及 632 消息队列；关闭预览取消在途上传，离开会话或切换账号后不使用迟到选择结果。入队后的网络失败由已有消息重试机制处理，上传日志清理失败不得再次提示发送同一条消息。

当前照片及拍摄都是静态图片入口；群图片仍明确提示未接入。接收图片目前仍为 `[图片]` 文本占位，授权缩略图和完整预览待接通，因此不是图片聊天完整交付。

验证：chat-image-entry-analyze.log 两文件无问题；上传／队列 7 项测试通过。旧 direct_chat_extensions_visual_test 的 3 项失败在 HEAD 基线复跑完全一致（箭头 8×16 与旧期望 11×22；附件截图差异 28.50%/95432px；已取消的礼物入口 key），记录于 chat-image-entry-baseline.log，未更新截图掩盖失败。真机选图／拍摄、上传进度及双机图片验收仍缺。

## 图片气泡与预览接入

本节覆盖前文接收端仍为文本占位的阶段状态。真实 image 消息按 messageId 请求 633，气泡加载授权 thumbnail，点击进入独立可缩放 image 预览页并重新授权。显示使用现有账号隔离私有缓存；不将授权地址或图片字节写入消息记录。尚未收到服务端 messageId 的待发图片保留占位及发送状态。

账号变化立即移除图片并拒绝迟到响应；关系／会话设置变化和重连、返回前台时重新取得授权。新建授权前清除旧显示，拒绝服务端返回的异源或不匹配消息／图片槽路径。仅聊天不限制聊天图片，与好友主页内容权限分开处理。

消息行使用稳定 clientMessageId key，正常消息更新不会因对象重建反复重新加载全部图片。图片限制在聊天卡片区域内按比例显示；完整预览使用全局返回控件与页面切换。

验证：chat-image-view-test.log 11 项通过，含真实私有缓存组件构造、异源地址拒绝、账号切换、关系变化期间迟到响应、上传及发送队列。此处组件测试未验证真实图片字节在两台手机间传输，服务端部署及真机验收仍未完成。
