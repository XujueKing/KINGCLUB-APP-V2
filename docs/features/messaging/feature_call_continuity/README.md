# 通话小窗与锁屏保持

2026-09-29，用户明确要求修复返回即挂断、iPhone 熄屏后断声。状态：Approved for Development（本次增量授权）。

单聊/群聊、语音/视频在返回时最小化为 App 内可拖动小窗，点击恢复原通话。小窗包含通话状态或时长、视频画面（可用时）及明确挂断按钮。页面切换不销毁通话控制器、媒体、轮询或独占租约，不重复发起/接听。未发起的群选人页返回仍正常退出；退出登录、远端结束、显式挂断和 App 容器销毁清理资源。后台来电唤醒、跨 App 系统画中画不在此修复内。

实现：应用 builder 内放置持久通话 Host；全屏时使用轻量导航占位处理系统返回，小窗时移除占位但保留原页面 State。所有来电/呼出路径统一入口，呼出设置完成后将所有权从聊天页面转交 Host，避免聊天页销毁误取消通话。

iOS：声明 UIBackgroundModes/audio，复用 WebRTC 的 playAndRecord 音频会话；通过原生租约确认后台音频配置。已开始的群通话不再因为 iOS 缺少 Android 前台服务而在 paused 时挂断。视频通话期间禁用前台自动锁屏并在租约结束时恢复原值；手动锁屏允许系统停止摄像头显示，但保留音频与通话。不开启常驻空音频或后台自动采集。

验证：小窗/恢复不重建媒体，系统返回与标题返回一致，跨页仍显示小窗，挂断/远端结束/注销释放租约，选人未开始正常退出；Android 现有服务租约回归；iOS 构建与双机锁屏语音/视频验收分别记录，不用 Widget 测试代替真机结果。

平台依据：[Apple playAndRecord 后台音频](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/playandrecord)。当前插件 flutter_webrtc 已配置录放音会话，变更仅补应用后台声明与生命周期管理。

真机验收步骤（待执行）：

1. 两台设备建立语音通话，iPhone 分别自动锁屏、按侧键锁屏至少 60 秒，确认双方持续听到对方；解锁后时长不中断。
2. 建立视频通话，点击返回缩成小窗，退出原聊天并打开另一会话，拖动小窗后点击恢复，确认音频持续且恢复同一通话。
3. 前台视频等待超过系统自动锁屏时间，确认屏幕保持亮；手动锁屏确认音频持续，解锁后检查视频恢复。挂断后确认自动锁屏设置恢复。
4. 群语音/群视频重复以上流程；对方结束、退出登录后确认小窗消失、麦克风/摄像头停止占用。
