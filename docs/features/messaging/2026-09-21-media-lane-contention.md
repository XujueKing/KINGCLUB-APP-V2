# 缩略图与原图同时下载时的 peer 通道争用

d3ff0aab 双机图片消息 `f666c180-7e1e-4a3c-ab47-bb4bc38c4ea0` 正常显示，但完整图及缩略图均出现 HTTP 206。发送端有 3618 字节完整图片缓存，SHA-256 `f87605a764437b327d2bcc0619e5241a1d8b576fcd285500eea600ef4a4d0bc8` 与规范化源一致；只观察到一次 PeerServe source 阶段 StateError、接收入口零帧。旧日志未区分媒体种类，不能断言该错误是原图源损坏。

代码检查发现每个 peer 通道仅允许一个 receive，缩略图和原图同时请求时，第二个立即抛 busy，调用方继而回退 HTTP。新增测试复现该确定的并发行为。本次允许一个候选下载等待当前接收释放，最多两秒；额外请求仍立即回退，长文件不会形成无界等待队列。释放后重新检查通道、取消状态并重新授权。关闭通道立即唤醒等待者，迟到完成不会覆盖新的接收对象。

发送端非 release 诊断仅增加已验证的 media 枚举，不记录内容、身份或密钥，用于区分正常缩略图缓存缺失与原图异常。无需修改 SuperVM wire、服务端或 UI。

验证：新增释放后继续、两秒超时、取消、关闭四种争用测试，含单等待者上限；与缓存准备、取消续传、媒体源读取组合共 22 项通过，静态分析和 diff 检查通过。手机仍为 d3ff0aab，尚未用新包证明这一修正解决本轮实机 HTTP 回退；不将图片 UDP 计为通过。
