## 实际语义核实

最初计划通过转发验证同一 fileAssetId 的共享引用。真实接口结果表明当前 `ChatFileForwarder.prepare` 下载后重新上传，群原文件和私聊转发文件的 fileAssetId 不同；两者 SHA-256 和大小相同。该行为与代码一致，不能将本轮记为同一资产共享引用的实机验收。

## 实机步骤和结果

1. 生成 8400 字节纯文字测试文件 AB-Shared-0927.txt，放入 B Download，通过系统文件选择器发送到专用群，成为第 6 条群消息。
2. 对该卡片长按→转发→唯一 A 测试好友→确认发送，成功进入 A/B 私聊。只读数据库核实各一条对应消息、文件内容摘要和长度一致、资产编号不同。
3. B 两份发送端加密缓存的 `0.block` 均存在。B 清空专用群记录后，群原文件发送端缓存删除，私聊转发副本仍存在；群消息下载键持久删除标记存在。
4. B 关闭 Wi-Fi（wifi_on=0）、force-stop 并重启，登录首页保留。进入 A/B 私聊，点击测试文件→读取文件，页面明确显示“已从本地读取，文件校验通过”。随后 Wi-Fi 恢复并确认 wifi_on=1。
5. 回私聊只长按 AB-Shared-0927.txt→为我删除→确认删除。测试文件卡片消失，转发副本发送端缓存删除，私聊消息下载键删除标记存在；服务端该测试消息 viewerHidden=true。
6. 再次 force-stop 并重启，测试卡片未恢复、转发发送端缓存仍不存在；原有 AB_UI_SMOOTH_0927_02 文字仍在，Download 原文件仍在。
