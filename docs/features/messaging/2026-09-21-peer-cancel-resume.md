# Peer 下载主动中断后续传

主动取消或关闭页面曾同时关闭接收许可，导致关闭时无法保存已收齐的分块。现在把接收许可与本地分块保留条件分开：网络立即停止，完整块保存进原账号、原消息的加密续传缓存；每块写入前后检查登录态和删除状态。退出账号或删除消息不保留这些分块。完整文件仍必须通过原 SHA-256 和权限检查，未增加任何绕过授权的路径。

回归用真实磁盘 receiver 预装两个块对应的片段，并在尚缺尾部时取消、销毁页面、退出账号或删除消息。取消/销毁后重建 downloader 仅通过 HTTP 请求块 1、2，不重复块 0；账号/消息撤销场景不复用旧块。片段跨 1 MiB 边界的未完整块不会保存。

## 部分缓存不再锁定 HTTP

发现历史优化在存在第 0 块时直接跳过 peer。分块导入实现后，这会让已恢复的对端无法在新一次重试中优先使用。现移除该条件：完整持久化文件仍先离线恢复；未完成文件重新尝试已授权 peer，将缓存导入片段位图，只取缺失范围，失败才继续 HTTP。失败后的授权刷新和缓存重读也覆盖已有第 0 块的情形。

自动回归使用真实加密缓存和磁盘 receiver：取消后重新创建下载器，第二次连接仅注入第 0 块之后的缺失片段（包括跨块边界片段），确认 peer.completed 成功、HTTP 请求数为零、全文件内容一致。另保留 peer 不可用时仅请求缺块、缓存损坏、撤权、群文件和完整文件离线恢复检查。44 项回归及静态分析通过；此增量尚待双机安装和真实 HTTP→peer 场景。
