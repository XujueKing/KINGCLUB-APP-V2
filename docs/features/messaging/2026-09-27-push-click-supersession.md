# 通知点击等待期间的旧跳转失效

通知点击等待 SecureSessionStore 异步读取时，又有一次点击到达，旧实现会先打开旧目标，再处理新目标。导航方法自身还会读取一次会话，因此只在 Runtime 第一次读取后检查不足以覆盖第二个等待窗口。

PushOpenRuntime 在会话读取返回后遇到新的 sync 请求，先重新排空有界原生队列。导航方法完成第二次会话确认后，再检查目标是否仍为当前待处理点击，以及是否有尚未处理的同步请求。失效目标不跳转、不记为已处理；随后按既有逻辑处理最新点击。账号匹配、到期和当前会话复用规则保持。

新增两个可控制异步时序的测试：在第一次会话读取期间加入不同目标点击；在导航校验等待期间加入不同目标点击。两者均只打开新目标，后续同步不重复打开。连同既有格式、去重、账号、关闭、过期、路由和草稿保留测试共 10 项通过。修改的三个 Dart 文件 analyze 通过。

本轮为代码和自动化验证，未重新打包安装，不代替 OPPO 实际送达、锁屏新来电或系统回收验收。原生待处理队列仍为内存队列；本次不声称解决等待期间进程再次被回收的持久恢复。
