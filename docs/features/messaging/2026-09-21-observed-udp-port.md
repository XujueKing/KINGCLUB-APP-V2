# NAT 映射端口变化

原接收路径在解密前要求 UDP 来源端口与签名通道通报值完全一致。对端发往 STUN 和发往接收者的映射端口不同时，即使报文来自同一个已认证会话，也无法开始回程探测。

本次允许同一已通报 IP 的新端口进行有限验证：每秒最多 8 次未知端口解密尝试，仅有效的会话加密 ping 可创建观察端口；最多保存两个。随后发起绑定该地址和端口的随机一次性 challenge，收到有效 pong 才确认可用。未确认端口不能交付应用数据，现有健康路由不会被新端口打断；通报候选或本地接口变化时清空观察端口。候选 IP 之外的来源继续拒绝，仅增加不含地址的诊断计数。

这不是任意 NAT 的穿透保证：双方都无法向对方映射送达首包时，仍走已实现的加密中继和 HTTP 回退，不采用端口扫描或预测。

验证使用本机真实 UDP socket 和 SuperVM 原生安全会话：故意通报一个静默端口，从另一个端口发包。无效报文、单向有效 ping、错误 nonce 均不能确认路由；有效回程 challenge 后可交付应用帧。STUN 轮换、绑定解析、公共映射发现及 nonce 测试一并执行。手机公网结果另记，不用本机测试冒充双机公网验收。
