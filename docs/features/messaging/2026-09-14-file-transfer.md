# 原生聊天文件传输（进行中）

## 已实现
ChatFileUploader 从本地 File 逐块读取，先使用 DartSha256 增量摘要计算，再调用 649。最大 256MiB、分块 1MiB，空文件也保留一个零字节块。上传编号放在当前账号的安全存储命名空间，直到消息可靠排队后才 acknowledgeQueued。

使用服务端固定 AES-256-GCM/HMAC-SHA256 分块协议；AAD 校验账号、资产、文件名、总长度和摘要。每个上传回执核对资产/块号/摘要。续传时重新读取已有块并核对服务端摘要，不盲信本地进度。完成后调用 650 并校验 ready 元数据。读取和请求之间检查会话，退出登录或 dispose 取消上传；二进制请求不跟随重定向。

## 验证
chat_file_uploader_test 使用真实临时文件（1MiB+3字节）和加密算法，合成 HTTP 适配器独立解密每块，模拟首块服务端已保存但响应丢失，重建上传器后只补第二块且复用上传编号；ready 重试不重复上传；会话变化拒绝继续。此为客户端协议测试，不是手机与真实后端联调。

## 文件消息队列接入
单聊 651、群聊 653 已接入 repository 和 controller；新 sendFile 在上传结果校验后先写可靠队列，再请求发送，沿用原消息编号重试。回执严格匹配文件资产、名称、大小、摘要，错误回执保留失败记录；群权限失效阻止排队。SQLite 加密历史白名单保留文件元数据，不保存下载凭证。界面和选择器仍未连接，不算真机文件发送已可用。

验证：文件队列与加密历史 15 项测试通过，文件回执丢失后重建控制器复用原消息号，错误回执保留队列，磁盘写入失败禁止发送，群访问撤销禁止排队；文件元数据重开数据库后恢复且明文文件名/下载 token 未落库。此前同时运行语音队列回归共 20 项通过，最终 analyze 无问题。测试使用隔离本地数据库与合成接口，尚未真机联调。


## 系统文件选择与发送确认页
“文件”按钮接入 file_picker 12.3.0 的单文件系统选择。取消返回不发送；选择后验证本地路径与 256MiB 上限，进入发送确认页显示文件名。用户点发送才上传，显示分块进度，失败保留页面可重试；成功写入消息队列后才清理上传编号并返回聊天。返回页面 dispose 取消正在上传的请求。群聊复用同一 ChatSessionController。

原生选择库说明：https://pub.dev/packages/file_picker 。使用按需读取 API，不调用 readAsBytes 整文件载入。评估的 file_selector Android 实现会通过平台通道携带完整 bytes，因此未保留该依赖。iOS 要求与原生打包尚待单独验证。

限制：目前使用选择器的临时本地路径，尚无应用重启后自动恢复选择草稿；待选缓存与过期上传资产清理未完成。文件消息目前仅已有基础摘要显示，专用文件卡片/点击下载未接，不算完整文件聊天交付。共享后端文件接口尚未部署，暂不安装此构建替代用户正在用的版本。
