# 原生聊天文件传输（进行中）

## 已实现
ChatFileUploader 从本地 File 逐块读取，先使用 DartSha256 增量摘要计算，再调用 649。最大 256MiB、分块 1MiB，空文件也保留一个零字节块。上传编号放在当前账号的安全存储命名空间，直到消息可靠排队后才 acknowledgeQueued。

使用服务端固定 AES-256-GCM/HMAC-SHA256 分块协议；AAD 校验账号、资产、文件名、总长度和摘要。每个上传回执核对资产/块号/摘要。续传时重新读取已有块并核对服务端摘要，不盲信本地进度。完成后调用 650 并校验 ready 元数据。读取和请求之间检查会话，退出登录或 dispose 取消上传；二进制请求不跟随重定向。

## 验证
chat_file_uploader_test 使用真实临时文件（1MiB+3字节）和加密算法，合成 HTTP 适配器独立解密每块，模拟首块服务端已保存但响应丢失，重建上传器后只补第二块且复用上传编号；ready 重试不重复上传；会话变化拒绝继续。此为客户端协议测试，不是手机与真实后端联调。

## 下载实现约束
下载器通过 652/654 获取短期授权，严格匹配消息中的资产、名称、长度与摘要；只允许固定同源路径、不跟随重定向。逐块流式写入私有临时目录，每块限制预期长度、全文件增量 SHA256 校验，通过后再次授权并核对元数据，才返回文件。取消、错误、会话变化删除本次临时目录；成功文件由下载器持有到页面释放。暂不把私有临时文件当永久缓存，不声称已完成系统保存、断点下载或手机验收。

## Android 系统导出
采用 ACTION_CREATE_DOCUMENT 获取用户选定的新文件 URI，选定后再次复查会话和服务端权限，再由后台线程以 64KiB 缓冲复制私有下载文件；校验长度和 SHA256。来源限应用 cacheDir 下本下载器的临时目录，不接受任意路径。只向本次系统选择返回的 URI 写入。错误/取消尽力删除本次新建文档，页面离开和会话变化取消导出。参考 https://developer.android.com/training/data-storage/shared/documents-files 。iOS 导出待实现，不宣称跨平台导出已完成。

Android 导出实现已加入 MainActivity/ChatFileExport 与 ChatFileExporter，详情页下载完成后显示“保存到文件”，只有系统复制成功才显示已保存。导出相关测试覆盖选择取消、选择后权限撤销、页面释放和成功路径，连同下载及详情页共 13 项通过；四个 Dart 文件 analyze 无问题。测试中的系统通道为合成回执，原生 Kotlin 编译/profile APK 构建仍在进行，未称原生保存或手机大文件已验收。后续需验证实际 document provider、低空间失败、保存后哈希及取消残留；iOS 仍待接入。
