# 聊天历史与离线恢复进度

## 已修复：单聊补收期间的通知遗漏

DirectChatController 原先在历史请求进行中直接返回该 Future；如果快照生成后新消息到达，实时通知不会触发下一轮读取，消息可能一直等到下一次通知或重进页面才出现。

改为在进行中的同步上记录待补拉标记，同一批突发通知合并一次；当前请求结束后从最新已同步序号继续读取。清空历史时清除补拉标记，旧代请求不能写回；已销毁控制器不再发起同步。

11 项控制器测试通过，新增八次通知并发时恰好补拉一次、读取 after=1 得到第二条消息的回归。已有清空历史、迟到分页、发送与重试、队列隔离回归通过。

## 尚未完成

当前已收消息仍只保存在控制器内存，只有待发送队列使用平台安全存储；不能宣称已实现离线历史。后续需要账号隔离的持久化消息库、分页索引、可靠游标提交、清空游标与群成员准入版本失效处理，保证重启后恢复不显示已清空或无权访问的消息。媒体授权必须独立重新校验，不能将签名链接或请求密钥写入历史数据库。此次未修改服务端、未打包安装。


## 加密 SQLite 存储层（尚未连接控制器）

新增 ChatHistoryStore：每账号独立 SQLite 文件及系统安全存储中的随机 256 位密钥；消息 payload 用 AES-256-GCM，附加认证数据绑定账号、会话和序号。序号／分页索引不加密，不声称整个 SQLite 文件加密。消息只保存允许的字段，排除媒体授权和传输凭据。数据库存在但密钥缺失时拒绝创建替代密钥，避免静默覆盖旧记录。

分页消息与补收 cursor 同事务写入；持久 epoch 随清空递增，旧 epoch 提交直接拒绝。磁盘测试使用实际 SQLite FFI 和真实密码实现，覆盖重开、分页、账号／会话隔离、凭据排除、错误密钥、序号篡改、无效批次不推进 cursor、清空后旧写入拒绝。6 项通过，尚未接入 DirectChatController / GroupChatController，不能当作离线历史已交付；后续还需准入失效、多端清空同步、容量策略与真机验证。

SQLite 事务与 FFI 使用依据：https://pub.dev/documentation/sqflite/latest/ 、https://pub.dev/packages/sqflite_common_ffi 。本轮未部署后端或构建 APK。

## 群离线历史接通
