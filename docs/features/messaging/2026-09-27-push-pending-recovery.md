# 通知目标在登录等待期间的安全存储恢复

原实现仅在内存中保留通知点击。现 Android App 为 PushOpenRuntime 接入现有 FlutterSecureStorage，独立键保存最多一条经过校验、字段白名单重建的目标。记录仅含版本、事件编号、接收账号、目标、类型和原始到期时间，不保存正文、供应商额外字段、令牌或会话凭据。

原生队列交给 Dart 后，先保存最新有效目标，再等待登录和导航就绪。新 Runtime 从同一安全存储恢复并重新校验格式、有效期、接收账号；新的点击优先覆盖旧目标。成功跳转或确定失效后删除。等待登录时不延长通知有效期，关闭 Runtime 不删除尚未完成的有效目标。

保存失败时保持待写状态，在下一次既有生命周期/路由同步时重试，不在未保存时继续打开。删除失败时保留丢弃状态，当前 Runtime 下一次同步优先重试删除，不因账号切回而重新执行该目标。不新增轮询、后台采集或自动接听。

验证：使用安全存储插件的测试替身重建两个 Runtime，确认登录等待中的目标被新 Runtime 读取、成功后清理且不重复打开；另覆盖过期、非法记录、跨账号、写失败重试、删除失败后账号切回。连同通知解析/竞态和路由保留测试共 16 项通过，修改 Dart 文件 analyze 通过。

限制：测试证明存储接口与 Runtime 恢复逻辑，不代表手机 Keystore 或系统真实回收已验收。原生 Intent 到 Dart 保存完成之间仍有小窗口；此时回收不在本次恢复保证内。存储删除失败并立即终止进程时也不能保证删除已落盘。真实 OPPO 送达、锁屏新来电和系统回收仍需集中实机验证。本次尚未打包安装。
