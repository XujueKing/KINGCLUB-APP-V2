## 消息与数据规则

- 客户端先写本地持久 Outbox，再发网络请求；重试复用同一个 clientMessageId。服务端以会话、发送方、clientMessageId 唯一约束去重，并验证重复 ID 的内容一致。
- 服务端事务同时写消息、会话序列和事件 Outbox。只有持久化成功才确认 accepted；delivered/read 必须有目标设备/会员回执，不能用 WebSocket 连接成功代替。
- MySQL 保存业务事实；Redis 只承担在线状态、速率限制、短期路由和扇出。断网后以持久游标补收，不依赖 Redis Pub/Sub 保存历史。
- 分页与补收使用不透明游标；服务端序列属于具体会话/传输，不把服务器时间、链高度作为全局消息顺序。
- 群已读、成员变动、为我删除、撤回作为版本化事件；撤回不能保证对方未截图或已下载文件被远程销毁。
- 媒体采用上传意图、已验证媒体引用、缩略图、限时授权读取；聊天消息不能提交任意外部路径。本机缓存按会员隔离。
- 现有 WebSocket 是客户端到服务端加密，不是端到端加密。端到端加密需成熟协议、设备密钥生命周期、换机恢复和群密钥方案，不能自行拼装或提前宣传已具备。

## 主网与通话边界

界面依赖 ChatRepository；ChatTransport 负责消息提交/同步，ChatMediaStorage 负责附件，ChatIdentity 负责身份和设备证明，CallSessionPort 负责通话生命周期。现有 CCSOP 与未来主网分别实现适配器。

- 用户已提供 D:/WEB3_AI/SUPERVM，当前 HEAD 27e9dee1。已读取 NovoRUDP FrameV0、修复窗口、传输边界、跨机性能记录及 reachability 实现。移动端 SDK、设备签名绑定、密钥恢复、离线信箱、附件持久性及聊天投递语义仍需逐项验证。接口存在不代表兼容性验证完成。
- 默认不把聊天正文、实名、定位、音视频写上公开链；链身份只作经过验证的账户绑定。链上资产交易与即时消息时序分开。
- 实时音视频使用 WebRTC 媒体传输；信令、鉴权、呼叫状态存储和可用中继仍要实现。首期准备自建能力，不默认购买第三方套餐。群通话需评估 SFU 带宽和机器容量。
- “无服务器化”目标是可替换中心协调与存储依赖，而非承诺不需要在线节点。手机被系统挂起、离线收信、NAT 穿透失败都必须有可验证的处理。
- 任何主网接入先跑与 CCSOP 相同的去重、权限、补收、取消、过期和重放契约测试，能力缺失明确禁用，不用降级掩盖。

接入判断：优先作为可靠消息、录音文件及附件的候选传输；仍需通过手机 ARM64 桥接、鉴权加密、MTU/分片、进程恢复、离线邮箱以及双端契约验证。

FrameV0 的 SHA-256 checksum 是完整性校验，不等价于端到端加密或身份认证。仓库其他层有认证代码，接入时要追到实际生效路径，不能仅凭字段推断安全保证。

实时语音/视频单独验证：过期音视频帧需要截止时间策略，不能无限等待可靠补包；本轮查看的 NovoRUDP 核心未找到完整音视频抖动缓冲/自适应码率证据。继续保留 WebRTC 媒体实现接口，后续只有 NovoRUDP 实时策略实测达标才替换。录音消息是可靠文件，和实时语音通话分开。
