# 附件停滞后的主动探测

实际 20 秒视频中断测试中，停止发送方后约 9 秒才开始 HTTP 续传。原接收器只使用 8 秒无有效进度超时，没有主动检查发送进程是否仍持有当前加密会话。

本次接入已有的认证端点存活探测。仅在已经收到有效远端数据后，连续 2 秒没有新增分片才触发路由恢复反馈和探测；探测最多等待 1 秒。探测失败且这段时间没有新进度时，结束当前 peer 尝试，由既有下载器保存完整缓存块并自动续传。具体 HTTP 建连时间另计，不承诺用户端严格 3 秒完成切换。

对端响应但文件发送慢，仍保留原 8 秒预算。尚未开始发送的文件准备不提前探测；已导入缓存也不算远端发送进度。探测期间收到新的有效分片后，旧探测失败不会取消恢复中的下载。文件完成/关闭时取消探测计时器；不关闭共享聊天链路，不更改权限、加密、UI 或 SuperVM 协议。

`novorudp_download_stall_test.dart` 覆盖不可达、探测无返回的时间上限、慢准备、活跃慢发送、晚到失败与新数据竞态。该文件和 receipt、prepare、cancel/resume、UDP/HTTP handoff 组合运行，44 项全部通过（81 秒，日志 `build/peer-stall-regression.log`）；本次三个实现文件及新测试静态分析通过。首次命令误写不存在的 cancel 测试文件名，修正为 `peer_cancel_resume_test.dart` 后完整重跑，不将首次失败视作通过。
