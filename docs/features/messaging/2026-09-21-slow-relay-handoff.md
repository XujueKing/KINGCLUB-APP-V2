# 大附件慢中继自动回退

公网实测 3.3 MB 图片通过加密中继耗时约 53 秒，而另一次 HTTP 下载约 5 秒。不能由此假设所有网络中 HTTP 都更快；本次仅针对持续慢速中继增加有界选择。

- peer 仍然先尝试；超过 1 MiB 的附件才参与此判断。
- 从新数据实际到达开始至少观察 8 秒，每 2 秒采样；恢复缓存和重复帧不计为新进度。
- 连续两个窗口没有 UDP 数据、确有中继数据，新进度低于 128 KiB/s，且剩余超过 512 KiB、按当前速度预计还需超过 8 秒，才关闭此接收尝试并进入原 HTTP 路径。
- 接收关闭保存完整加密分块，并通过上一节点的 cancel 通知停止远端当前发送；HTTP 重新授权后只读取缺块。未知路由、仍有 UDP 数据、快速传输和快完成的传输不触发此策略。
- HTTP 超时或重试失败后仍可恢复 peer；恢复尝试不再次触发慢中继回退，避免来回切换。

这是初始保守阈值，不是链路速度保证。当前 A 蜂窝网络/B Wi-Fi 的 UDP 探测仍未成功；该修改不改变 NAT、寻址认证、SuperVM 共识或既有 UI。

验证覆盖真实磁盘 receiver 与加密分块缓存：慢中继接收了完整块 0 后自动改 HTTP，仅请求块 1–3；同速度 UDP 完整收到且没有 HTTP 请求；中继回退后 HTTP 超时，第二次 peer 恢复即使速度仍慢也能收完，不反复回退。全量下载与跨媒体接续回归结果另附。

下载器及跨媒体接续共 69 项回归通过（3 分 20 秒），静态分析通过。慢中继样例约 8.5 秒触发回退；同速度 UDP 完整接收 3,145,731 字节且 HTTP 请求为零。此处是自动测试，不代替双机公网验收。
