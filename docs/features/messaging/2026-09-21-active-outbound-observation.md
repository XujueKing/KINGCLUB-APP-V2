# B 主动发包前后对照（2026-09-21）

## 实测结果

B 保持家庭 Wi-Fi，使用同一个 Android shell UID UDP socket，先向自有
STUN 3478 获取映射，再用同一服务器的临时源端口进行两阶段对照。
连续两次执行结果一致：

| 检查 | 结果 |
|---|---|
| 初始 STUN 回复 | 成功 |
| B 未向临时端口发包时收到该端口 token | 否 |
| B 主动向临时端口发一包后收到第二阶段 token | 是 |
| 末尾 STUN 回复 | 成功 |
| 同 socket 前后 STUN 映射 | 相同 |

两阶段使用不同 token；收包验证精确源 IP、端口和 token，避免迟到包计入
第二阶段。服务器同一 socket、同一目标映射，两阶段各发送三包。
映射与 token 仅通过子进程管道协调，不写入报告。没有修改路由器、防火墙
或应用安装包；临时 dex 已移除。

## 判断和边界

这支持“B 主动发包后，此端点的回包通道可达”，不能再把 B 家庭网络描述为
完全不能打洞。没有证明服务器收到 B 发出的那个包，也没有定位过滤设备。
诊断使用 shell UID 的独立 socket，不等于聊天生产 socket 打洞成功。

结合之前 A 对两个 STUN 目标出现不同公网 IP 和端口、B 对两个目标映射一致
的观测，目前下一重点是目标相关映射下的候选地址获取与交换。不能直接把
STUN 观察地址当作 A 面向 B 时的有效地址，亦不能以本次对照宣称 A/B 已直连。
现有中继回退保留；本节点没有改动 SuperVM 协议、共识或业务逻辑。
