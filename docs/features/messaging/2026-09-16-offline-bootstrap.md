# 断网冷启动进入本机聊天

A 真机关闭 Wi-Fi 和移动数据并强制结束后重新启动，实际停留欢迎页并提示网络连接失败，无法进入已有聊天缓存。网络已恢复到原启用状态。根因是启动器仅接受在线会员刷新成功，网络错误虽未删除安全存储，却没有本机进入路径。

修复限定于启动入口：正常先恢复在线会话，仅明确 NETWORK_ERROR 时允许同一份仍有效、先前已通过审核的本机会话进入 App。重新读取安全存储并校验账号/凭证绑定，注销、换号、未审核或本机刷新期限过期均不走此路径。现有接口仍使用真实鉴权，不将离线快照用于成功续期或授予服务端权限；聊天 API 的 restoreSession 行为保持不变。

验证包括断网已审核进入、未审核拒绝、换号迟到失败拒绝、明确撤销不降级。本次不改变注册流程、审批标准或聊天 UI。

## 验证结果

- 36 项离线启动、注册恢复、续期和资料并发测试通过，3 文件静态分析无问题。
- Profile/LAN 构建 68.6 秒完成并覆盖安装 A，同时包含已读回执校验和历史回拨节点；B 未更新。
- 实际断网再次 force-stop 后冷启动，进入主页；消息列表显示缓存会话及“网络不可用，请稍后重试”。此时 Android connectivity 明确报告 `Active default network: none`。
- 打开 A/B 会话，原文字、表情、语音通话 00:27 和视频通话 00:14 等历史仍可见。没有触发新发送、回拨或媒体解码，不把本次计为离线新消息补交/历史回拨验收。
- 执行恢复 Wi-Fi 与移动数据，设置读取均为 1，connectivity 恢复默认网络 120；返回聊天列表已无断网提示。

私有界面证据位于 build/phone-a-offline-*、build/phone-a-online-restored.xml，不提交仓库。
