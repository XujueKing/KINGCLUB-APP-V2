# Group access denial during send

A send response can reveal removal before a history refresh. On current-generation CHAT_GROUP_ACCESS_DENIED, immediately invalidate visible history and local access using the existing history barrier. Preserve unsent content as a failed outbox item. Manual and queued retry must not contact the server without restored group access. Reply/hide capabilities must also become false. Stale send responses must not revoke a newer history generation. No UI changes or automatic rejoin.

Regression covers send-time denial, retained failed text, blocked follow-up send/retry, and recovery after an authoritative history refresh. Validation: 43 tests passed across group_chat_controller, group_chat_history, group_call_controller and group_call_session; analysis of the changed Dart files passed. Initial new test used a non-UUID client ID and was corrected to the actual contract; an intermediate batch referenced a nonexistent history test filename and was rerun with the discovered group_chat_history_test.dart. Logs: build/group-send-revocation-final.log and build/group-send-revocation-analyze.log. Not packaged or installed; real phone removal acceptance remains pending.
