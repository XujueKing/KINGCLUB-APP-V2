# 原生语音播放异步错误恢复

本机 audioplayers 6.8.1 的 onPlayerComplete 来自原生事件流，流本身也会转发错误。聊天播放和录音草稿预览原来只处理 play() 的 Future 异常，没有订阅流错误；开始播放后才发生的解码错误可能成为未处理异常，并残留播放状态。

现在两个入口均处理流错误并停止播放器。聊天清除当前播放状态、允许再次授权重试；旧片段在新语音下载期间上报的错误不会取消新下载。草稿预览恢复播放按钮、保留录音并提示重试；后台和失效会话不会弹出播放提示。

验证：语音播放、草稿预览和历史刷新共20项测试通过；4个修改文件静态分析通过。覆盖原生错误注入、状态清理和再次播放。未安装手机，不将测试替代硬件解码、后台或蓝牙实测。

后续补齐短录音完成回调竞态：若原生完成事件先于 play() 回执返回，旧代码会再次把按钮设成播放中。完成事件现在使在途播放操作失效，迟到回执不能恢复已结束状态。新增组件用例复现这一顺序，并验证完成后可再次试听。草稿与聊天播放共19项测试通过，相关静态分析通过；仍待实机验收。
