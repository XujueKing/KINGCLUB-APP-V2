# 中继候选通知与 UDP 心跳解耦

## 问题与修改

实际聊天使用的 NovoRudpLanRoute 定时任务此前等待候选地址经中继发送完成，
然后才发 UDP 心跳。中继发送不结束会阻塞后续定时任务；发送抛错还会进入
外层异常分支清除直连确认。因此中继自身故障可能破坏本来仍可用的 UDP 路径。
收到新候选地址时的回告也有同样的等待。

现在自动候选通知独立发送，错误不影响 UDP 心跳；每条路由最多保留一个
未结束的自动通知，避免中继挂起时不断积累任务。直连仍须通过既有加密身份、
端点挑战、时效检查，不以中继成功代替直连验证。显式 advertise 接口保持原语义。

## 验证

使用本机 NovoRUDP native DLL、真实 UDP socket 和原生 AEAD，测试中继控制
回调分别抛错、永久等待两种情形：两端超过六秒心跳有效期（观察九秒）持续
ready，之后仍实际接收 UDP 加密数据；等待模式每端只有一个自动通知在途。
同批路由重建、未知源地址与端口学习回归，共 5 项通过。目标文件静态分析通过。

这是实际路由代码修复及主机集成测试，不是 A/B 当前移动网络跨网直连通过。
没有修改 SuperVM 共识、UI、账户和路由器；手机仍运行前一版，未在本节点重装。
