# Native audio processing constraints

Installed flutter_webrtc 1.6.2+hotfix.1 Android GetUserMediaImpl.getUserAudio uses MediaConstraintsUtils.parseMediaConstraints for an audio map. That parser reads mandatory/optional only; top-level echoCancellation/noiseSuppression/autoGainControl are not forwarded to createAudioSource. Defaults may still process audio, but the app's explicit settings were not taking effect through that path.

Supply the three matching goog* optional constraints alongside standard top-level keys, shared by direct and group calling. Keep current recording profile and UI. Android record 2.2.0 already enables NoiseSuppressor/AcousticEchoCanceler/AutomaticGainControl when available with VOICE_COMMUNICATION input; unsupported hardware effects are not proof of software fallback. Server voice processing validates/normalizes AAC, it does not perform denoising. Real noisy-room/echo quality remains device acceptance, not a constraint-map test claim.

Validation: 54 native direct/group media and voice-capture tests passed; five-file static analysis passed. Ran the installed plugin's unmodified Java MediaConstraintsUtils, ConstraintsMap, ConstraintsArray and ObjectType with desktop stubs only for Android logging and the WebRTC constraints data container. The old top-level map produced zero native constraints; the amended map produced three optional keys with string value true. Harness output: ACTUAL_ANDROID_PARSER_BEFORE_EMPTY_AFTER_THREE_ENABLED_FLAGS (build/audio-parser-check). This verifies parsing, not execution of the WebRTC audio engine or measured sound quality. Group capture's old exact-map test was updated to include the newly required native keys. No plugin cache source was edited and no phone APK was installed. This patch postdates the current 72902aa APK.
