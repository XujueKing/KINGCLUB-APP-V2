# NovoRUDP 主动取消握手

新增 `NovoRudpPeerHandshake.cancel()`：立即释放本机原生握手与加密通道，并向 683 发送对应 exchangeId 的取消请求。服务器已接收 offer 但回执丢失时，仍使用原请求编号取消。重复本机取消不会再次发请求。

登录失效与普通资源释放仍使用同步 `close()`，不在退出登录后发起请求。取消接口失败向调用方报告；不能把本机关闭当成远端已确认取消。若 offer 与 cancel 在网络中乱序且取消先到，仍可能依靠服务端 45 秒过期回收，未宣称消除此情况。

验证：Windows 原生 NovoRUDP DLL，握手丢包恢复、取消后拒绝继续握手、接收方拒绝已取消邀请、通道关闭后拒绝加密；连同信令仓库测试共 7 项通过，相关 2 文件静态分析无问题。信令使用测试替身，本次未进行真实 HTTP 或手机验收。

当前手机聊天尚未调用该握手模块，683 仍未在线开放；该节点不代表聊天已自动切换到直连。下一步需要在实际建连流程调用主动取消，并完成真实接口与双机验证。
