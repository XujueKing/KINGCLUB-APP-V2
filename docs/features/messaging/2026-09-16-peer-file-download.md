# NovoRUDP 附件接收协调

源码核对：NovoRudpFileSender/Receiver 尚无聊天产品调用方；ChatFileDownloader 仍通过服务端分块授权下载。MemberRelayText 只承载文字，不将独立 UDP 测试计为附件双通道交付。

下一步协调层持有已认证 FrameLink 和由调用方独立授权的文件大小/摘要及传输 ID，过滤其他消息流，接入 Receiver 的落盘和 ACK，完成后才返回摘要验证文件。每次处理前后检查当前访问授权；超时、断线、权限撤销必须失败并清理临时文件，不关闭同通道其他聊天。成功文件由协调层持有至调用方复制并关闭。

这一层不从对端自行授予权限、不创建聊天消息、不把 ACK 当作服务端入库；授权消息与设备的协商、聊天下载调用和实际双机自动切换仍待接入。验证先用真实原生加密 UDP 与磁盘，不能代替手机验收。

已实现 NovoRudpFileDownload：使用调用方授权判断，过滤不匹配流/对象和非数据帧，接收任务最多256个，完成前校验大小与摘要，超时/会话变化/失败清理；关闭仅释放该文件，不关闭共享链路。成功结果供调用方复制后关闭，仍未接入产品下载器。

验证：Windows 真实原生 DLL + 加密 UDP + 临时磁盘，协调层4项通过（70KB完整性、其他流隔离、摘要错误清理、超时、撤销授权及关闭后共享链路继续可发）；发送器/接收器原有回归及首批协调层共17项通过，随后新增摘要用例并重跑协调层4项。18MiB丢包用例耗时70780ms，25484包中主动丢3595包，校验一致；这是受控回环故障测试，不是手机或公网速度指标。两文件 analyze 通过。日志保存在 build/peer-file-coordinator-*.log，未安装手机。下一步仍需消息授权协商、运行时接线与服务端下载回退。

聊天下载接入阶段：给 ChatFileDownloader 增加显式授权 peerDownload 提供方，仅单聊尝试，接入前保留服务端 grant 校验，文件复制到下载器自己的临时目录后独立校验大小/摘要，再复核权限。失败先关闭直连接收，重新授权后按原 HTTP 下载；取消/换号不回退。连接最多3秒，迟到连接必须关闭。运行时尚未提供该连接器，因此默认路径仍是服务端，不宣称产品已启用直连。

验证：聊天下载器接真实原生加密 UDP 接收层，两项通过（独立复制后校验正确且零HTTP二进制请求；传完后的最终授权撤销拒绝交付并清理）。授权接口为受控响应，不代表真实服务端协商。现有HTTP下载及新增直连不可用回退、连接中取消共23项通过；取消在500ms内终止且不发HTTP，迟到连接清理。三文件静态分析通过。运行时 peerDownload 仍未提供，产品默认路径未切换，下一节点须接可信会员/消息协商后才能双机验收。
