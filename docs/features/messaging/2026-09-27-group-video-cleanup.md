## 合成素材

使用已有本机 imageio_ffmpeg 提供的 FFmpeg 7.1，生成彩条运动测试图和低音量 440Hz 音轨；没有读取私人视频。生成命令：

```sh
ffmpeg -f lavfi -i 'testsrc2=size=640x360:rate=24' \
  -f lavfi -i 'sine=frequency=440:sample_rate=48000' -t 6 \
  -c:v libx264 -preset veryfast -crf 23 -pix_fmt yuv420p \
  -c:a aac -af volume=0.1 -movflags +faststart AB-Group-Video-0927.mp4
```

源文件 565820 字节、640×360、24fps、6 秒。此大小属于原素材，不用于宣称 App 压缩率。

## 实机证据

1. 通过 B 正常“＋→照片→选择视频”选择测试素材，预览后发送；服务端成为专用群第 5 条消息。发送后 B 可见 1 条，A 可见 5 条。
2. 根据真实消息及当前账号计算 MediaCache 定位：发送端视频、消息封面、封面传输副本确实存在；消息完整视频、完整视频传输副本和转发副本不存在。发送端播放复用源副本，不把不存在的副本算作删除成功。
3. B 关闭 Wi-Fi，核实 wifi_on=0，打开视频。连续截图的素材时间从 00:00:00.792（帧 19）推进至 00:00:02.417（帧 58），画面和进度条推进，证明离线解码播放，而非只有封面。
4. 保持 Wi-Fi 关闭，force-stop 并重新打开正式 App，登录首页恢复。通讯录→群聊→测试群，6 秒视频卡片保留；再次打开，截图显示素材已播放到 00:00:01.000（帧 24）。随后 Wi-Fi 已恢复为 1。
5. 正常群详情→清空聊天记录→确认清空。六个视频相关缓存键的文件和对应续传目录均不存在，六个持久删除标记存在。
6. 再次 force-stop 并重启，登录首页正常；六个文件仍不存在、删除标记仍存在。Download 中的源 MP4 保留，未删除用户原文件。
7. 只读服务端核验：群 active，lastSequence=5；A 成员 active、hiddenThrough=0、可见 5 条；B 群主 active、hiddenThrough=5、可见 0 条。没有解散群、退出成员或删除其他成员历史。
