# 使用期间聊天登录续期

A 真机在已登录页面停留后，聊天列表出现“网络不可用”，联系人列表出现加载失败，好友资料直接显示 `Session expired`。检查实际请求路径发现，`MessagingRepository.open()` 每次读取当前凭证，但收到 `SESSION_EXPIRED` 后没有调用已有的登录续期流程；此前续期仅由登录恢复入口触发。

本次将聊天、联系人和资料所共用的 MessagingRepository 请求接到 AuthenticatedChatApi：仅服务端明确返回 SESSION_EXPIRED 时，调用既有刷新令牌流程，成功后以原参数/原消息编号重试一次。网络失败不自动重复调用，第二次过期不循环。账号、sessionId 和登录代际在发送前后均校验；退出或切换账号不会在新账号下补发旧操作。

RealAuthRepository 对相同 sessionId、apiKeyId、刷新版本的并发恢复共用一次任务，避免多页同时使用一次性刷新令牌。仍使用已有 compare-and-save 保护，迟到刷新不能覆盖或清除新登录。

自动化：33 项聊天续期/登录恢复/迟到刷新/资料更新测试通过；4 个修改文件静态分析无问题。新增测试覆盖 8 个同时过期的请求只刷新一次、原消息编号不变、网络失败不重试，以及刷新期间换账号禁止补发。测试替身验证状态机，不替代真机续期验收。

附件独立上传客户端、其他业务仓库不在此次改动范围。

真机更新：Profile/LAN 包已覆盖安装 A。冷启动后通讯录恢复、B 的真实资料正常返回，显示互相关注与正确会员号；此前的加载错误消失。冷启动本身也会触发既有恢复入口，因此这不单独证明持续停留直到再次过期的请求续期路径已在手机验收。

同次完成 A 对 B 的备注验收：保存临时备注后通讯录即时显示备注和原昵称，字母分组随备注变化；退出资料再进入备注页仍读到保存值。随后清空测试备注并保存，通讯录恢复原昵称和 X 分组。没有修改其他好友。
