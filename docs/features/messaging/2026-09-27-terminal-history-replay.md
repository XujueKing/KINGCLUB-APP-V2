# 已删除消息重复同步的历史扫描优化

清理函数原先只要收到 hidden/recalled 标记且库内存在相应行，就会解密遍历全部会话，重新收集共享媒体引用。重连分页可能重复返回已保存的终态标记，使本来没有新删除内容的同步工作随全库历史量增长。

提交批次本来已经读取并解密同序号旧行，以保证删除/撤回不会被迟到响应覆盖。现在将其中已处于终态的序号传给清理函数，排除重复媒体清理；仍处理草稿引用，首次删除、未知删除标记、清空边界和共享引用清理保留原路径。没有新增数据库结构或明文消息字段。

新增规模回归使用计数 SecretKey、真实 SQLite 和 AES：同一撤回标记重复同步，在其他会话增加 500 条消息前后密钥提取次数相等。现有首次/重复删除通知、共享媒体最后引用、草稿清理、历史存储及发送文件缓存测试共 90 项通过，修改文件 analyze 通过。

此为代码与本机回归证据，不是整体聊天 UI 已顺滑或双机删除全场景已验收。尚未安装，与群心跳提示增量合并下一批验证；其他会话的 onboarding 改动未包含。
