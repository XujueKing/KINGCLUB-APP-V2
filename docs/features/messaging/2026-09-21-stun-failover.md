# STUN 多入口故障切换

原实现只使用一个配置的 IPv4/DNS STUN 地址及端口；一次 binding 无回复后，8 秒停止发送，但到 30 秒才换事务重试同一入口。新增部署配置的最多三个备用 `host:port`，不从对端消息或未知目录接受寻址服务器。

- 保留 `KINGCLUB_NOVORUDP_STUN_HOST`、`KINGCLUB_NOVORUDP_STUN_PORT`，默认端口仍 3478。
- 新增 `KINGCLUB_NOVORUDP_STUN_FALLBACKS`，逗号分隔 IPv4/DNS `host:port`，最多三项，去重。不支持 URL、凭据、IPv6 或任意长度列表。
- Binding 约 4 秒无响应后轮换下一入口（现有 2 秒调度会影响实际时间），重新生成事务；DNS 查询仍最多 2 秒，失败后轮换。成功的入口继续用于刷新映射。
- 响应同时匹配当前请求的事务、服务器 IP 和端口。迟到的旧节点响应不能替换新结果；换网期间完成的旧 DNS 查询也不应用。
- 寻址异步执行，不阻塞现有加密中继。STUN 返回地址不代表对端身份或直连成功，仍须经既有认证控制通道交换候选、完成端点探测。

预览构建脚本增加 `-StunFallbacks @('已部署节点:端口', '另一已部署节点:端口')` 参数。参数需要已有 `-StunHost`，主节点、备用端口必须真实运行且已获准开放。此代码节点没有开放任何新公网端口，也没有填入第三方公共 STUN。仅改配置不能解决 UDP 整体不可用，现有中继/HTTP 回退仍需保留。

验证：STUN 解析、候选探测及真实本机双 UDP socket 故障切换共 7 项通过；静默主端口切到备用端口后，迟到主端口回复未覆盖映射。现有真实 SuperVM relay runtime 在 LAN 关闭及开启下分别 2 项通过（合计 4 项），含认证文件路由计数；静态分析与 PowerShell 语法检查通过。

这不是公网封锁仿真或跨运营商验收。当前手机安装 cfbbe494，新增多入口及 6383df57 前段补片尚未安装；当前部署仍只有已授权的 UDP 3478 寻址入口。公网备用节点/端口与公共 WSS 接入仍需部署条件及相应授权，独立网络双机测试仍待条件满足。
