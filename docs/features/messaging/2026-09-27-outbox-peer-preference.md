# 离开会话后的点对点优先重试

问题：会话页面创建 DirectChatController 时配置了 preferRelayText，可用时先通过 NovoRUDP 的自适应点对点路径发送；ChatOutboxRecovery 创建的控制器只配置发送函数，没有偏好判断，自动恢复时始终先等待 CCSOP 发送结果。这导致同一条待发文字在会话内外使用不同策略。

修正：恢复任务在每次尝试时按当前连接状态读取偏好，与会话页面一致。既有 textSender 仍负责账号代际校验、目录授权、直连／中继选择与冷却，不根据旧连接快照永久锁定路径。失败仍走 CCSOP；已得到点对点回执的稳定 clientMessageId 保存在持久队列，后续补齐服务端回执时不重复发送点对点消息。当前架构仍同步 CCSOP 历史，不能据此宣称完全不依赖服务器。

覆盖：优先开关与点对点成功／失败四种发送顺序；重建恢复任务后保留 peerDelivered；同一 ID 的服务端确认与队列移除；原有可见会话所有权、群权限撤销、账号改变、冷却和有限时间回退。26 项针对性测试及两个变更文件静态分析通过。此增量不等于当前 A 移动网络／B 家庭 Wi-Fi 纯直连成功证据。
