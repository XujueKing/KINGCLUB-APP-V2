# 群通话客户端接入（进行中）

新增GroupCallRepository，复用MessagingRepository的会话绑定和加密请求通道，对应后端678发起、679动作、680状态、681本人当前通话。构造函数不会发起请求或开启录音/摄像头；请求ID由通话操作持有，重试保留原编号。

GroupCallSnapshot验证通话/群UUID、音视频类型、2–9位唯一参与者、本人包含关系、已知成员状态、版本与时间范围及结束状态一致性。成员列表不可修改，不接受响应中的设备session信息。发起及动作回执再次核对目标群、通话、媒体类型和参与账号集合。保留appliedVersion与当前version区别，允许旧操作重放返回更新后的结束状态；不据此重新接听。

验证：group_call_repository_test.dart与现有call_repository_test.dart共10项通过；两文件flutter analyze无问题。覆盖构造无副作用、网络失败后的相同请求、越账号/重复成员/未知状态/结束状态矛盾、当前通话为空、查询ID不一致、成员不可变、目标不一致、旧动作重放版本。测试使用注入的ChatApiCall，**不是Flutter到真实服务或真实通话验收**。

后台109接口已登记但默认停用。尚未接用户入口/媒体会话，未打包或安装新APK；不会把接口封装当作可用群通话。沿用已确认UI，继续接实际通知、媒体和双机/多机验收。

新增GroupCallController：按顺序处理操作与读取，watch合并失效通知并轮询指定通话；每次刷新最多两次读取，避免慢网络下持续通知阻塞排队的接听操作。轮询仅read，不自动接听或续租。媒体层后续只应在真实连接有效时调用heartbeat动作。

不确定的网络失败保留原requestId和expectedVersion，即使中间刷新看到更新版本也不重建该操作。明确版本冲突则丢弃旧请求、同步后等待下一次显式操作。登录切换/关闭后停止轮询及订阅，迟到响应和排队动作不能重新打开通话；结束或本人被撤销时关闭本地控制器。当前事件和会话变更Stream由调用方注入，尚未在App入口挂接。

控制器与数据层共11项定向测试通过，控制器/测试静态检查通过。新增验证包括通知合并、持续通知不阻塞用户动作、登录变化丢弃迟到结果、网络重试编号保持、明确版本冲突换编号和撤销后停止请求。仍使用注入API/事件，不代表真实WebSocket、设备录音或群通话完成；没有媒体实现、打包或安装。
