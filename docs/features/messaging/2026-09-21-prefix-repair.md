# 初次发送期间补齐前段缺片

双机中断视频时，临时文件长度已超过 2 MiB，但 HTTP 回退只复用了 1 MiB。接收器只能保留分片完整的缓存块；写入高水位不能证明前段没有缺片。原发送器先发送全部初始数据，再集中读取缺片 ACK，导致早期缺片可能一直保留到文件尾部。

本次每发送 256 个初始分片，使用现有认证 DONE/ACK 与 repair planner 检查前段，最多处理四个缺片窗口。只补传已经发送的序号，未发送尾部仍走正常顺序发送；补传后恢复顺序读取位置。复用现有分批节奏、重传份数、权限检查和取消/超时，不改 SuperVM wire 或共识，也不关闭共享聊天链路。受限轮数避免严重丢包导致前段无限阻塞，不能保证任意中断点所有缓存块都完整。

新增真实加密 UDP 测试：初次发送故意丢掉序号 3，在初始发送到 255 时已补传该片，未提前 repair 未发送尾部；601 个分片最终文件哈希验证成功。其余测试覆盖丢数据及最终 ACK、续传、取消、权限撤销、共享链路生命周期、空文件及源变更。

首轮回归的旧重复数据测试出现本机 UDP send buffer unavailable 未捕获异常。其周期发送改为仅容忍 SocketException；原有超时原因和有效接收字节断言保持，不将初次失败记为通过。18 MiB 丢包场景首轮独立完成于 72474ms，25468 个包、3568 次丢包；该本机测试不是手机或公网性能承诺。

手机仍为 cfbbe494。本次前段补片改动尚未安装手机，实际中断时完整块保留率仍需验证；跨运营商 P2P 仍未验收。

最终验证：使用 `NOVORUDP_NATIVE_LIBRARY` 指向现有本机 DLL 完整重跑 `novorudp_file_sender_test.dart`，35 项全部通过，约 94 秒（`build/peer-prefix-repair-rerun.log`）；发送器和测试静态分析通过，`git diff --check` 通过。
