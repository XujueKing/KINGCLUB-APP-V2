# 前台恢复与列表刷新顺序

检查现有生命周期实现：会话列表在 resumed 时刷新；已有请求进行中时设置后续刷新标记。直接会话会同步历史和待发队列，已读标记受前台及当前页面可见条件限制。本轮未发现足够证据修改这些业务逻辑。

扩展 `conversation_refresh_order_test.dart`：保留原标签切换案例，新增完整 inactive→hidden→paused→hidden→inactive→resumed 生命周期。聊天标签处于非选中状态但页面仍挂载，分页请求未结束时连续两次返回前台，断言请求没有重复分页、旧请求结束后发起最新首页读取、最新会话行替换旧数据，未读回调最终为最新值 4。

与 `chat_transport_wakeup_test.dart` 合并运行，4 项全部通过。后者覆盖通道恢复事件唤醒后台队列及可见会话队列，不依赖轮询计时器。本机日志：`build/foreground-recovery-test.log`。

本轮只增加自动回归覆盖，未改运行代码、未重装手机。这不代表 Android 锁屏下进程保活、系统通知推送、被系统杀进程后的实时接收已验收；这些仍需独立实现或实机验证，不能与返回前台后的同步混淆。
