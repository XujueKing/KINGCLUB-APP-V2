# 信息架构与入口归属

- 文档状态：`Approved for Development`
- 版本：`Shell IA v1`

## 1. 一级结构

```text
App Shell
├─ 首页
│  ├─ 一起玩 AA → 套餐详情 → 确认订单
│  ├─ VIP 组局 → 创建/局长管理
│  ├─ 安全扫码 → 点单/好友/入场的受控分流
│  └─ 入场凭证
├─ 消息
│  ├─ 会话列表 → 单聊 → 单聊详情
│  ├─ 通讯录 → 用户主页/关系操作
│  └─ 系统通知
├─ [中央扫码动作]
├─ 发现
│  └─ 短视频/作品流（只读，不发布）
└─ 我的
   ├─ 我的主页 → 编辑资料/个人二维码
   ├─ 订单中心 → 订单详情/支付结果
   ├─ 钱包与资产流水
   ├─ 私人储物柜 → 取件码
   └─ 设置 → 支付安全/注销/关于与法律
```

## 2. 页面归属原则

- 一级导航永远由客户端版本控制，不读取服务端路由配置。
- 同一页面只有一个主归属，但可以由多个经过批准的 RouteIntent 到达。
- “消息”分支同时容纳会话与通讯录；两者是独立页面，不在一个页面中复制业务状态。
- 首页是到店业务入口聚合，不复制订单中心、钱包或个人资料内容。
- 我的只展示摘要和入口，权威明细由对应独立页面负责。
- 扫码结果先进入 KC-P-012 做格式、来源和 allowlist 判断，再产生具体 RouteIntent；二维码内容不得直接作为路由字符串执行。

## 3. 一级入口覆盖

| 业务域 | 默认一级入口 | 备注 |
|---|---|---|
| identity | Shell 之外 | 登录和会员准入完成后才能进入 Shell |
| home / club | 首页 | AA、VIP、入场；储物柜例外归我的 |
| messaging / social | 消息 | 联系人、好友申请、会话与系统通知 |
| content | 发现 | 只读内容流 |
| commerce | 首页扫码或我的订单 | 点单从扫码进入，历史订单从我的进入 |
| membership_wallet | 我的 | 本期只读资产 |
| profile_settings | 我的 | 资料、安全和法律 |

## 4. 全局徽标

- 消息 Tab：会话未读 + 系统通知未读的去重聚合，显示 `1...99`，超过显示 `99+`。
- 好友申请提醒：在通讯录入口显示，不重复叠加到多个一级 Tab。
- 首页、发现、我的默认不显示营销红点；未来新增必须独立评审来源、去重和清除规则。
- 徽标是提示，不是权威业务状态；进入页面后由对应 Fake/Repository 重新读取。

## 5. 明确禁止的入口

- 发现页不显示“发布作品”。
- 聊天页不显示建群、群管理、红包或金币转赠。
- 我的不显示代理、员工、财务、经营后台或账号绑定入口。
- 扫码不得打开服务端返回的任意 URL/路由，也不得直接确认支付或入场成功。
