# 协议确认页评审记录

## 2026-08-24 首次正式评审

### 已确认事实

- K107 只读返回当前强制 `terms/privacy` 的公开版本、标题、发布时间、摘要和受控 Markdown，缓存截止时间为 5 分钟。
- K102 只接收协议代码与版本，服务端重新取得摘要并在登录事务中追加 `consentRecord`。
- 当前没有“登录后独立提交协议同意”的 K 接口，本页不能声称单独落库成功。
- K102 发现旧版本时不会验证/消费短信 challenge，客户端可刷新 K107 后继续原登录流程。
- 正式协议正文和首个发布版本尚未由运营/法务提供，仍是生产上线门槛。

### 当前评审建议

1. 同一页面支持 `readOnly` 和 `loginRecovery` 两种严格类型化模式，不再创建额外协议全文页面。
2. 路由不携带正文、手机号、challenge 或凭据；恢复模式只携带内存 `loginFlowId`。
3. 两份协议使用标签内联展示完整 Markdown、版本和 `publishedAt`，不伪造生效日或变更摘要。
4. readOnly 模式不形成同意；恢复模式确认只原子更新内存 ConsentSnapshot，服务端记录仍由 K102 创建。
5. K107 到期时在确认前刷新；目录变化会清除旧勾选，两份协议作为一个新 generation 重新确认。
6. 不强制滚动到底，不默认勾选，不自动同意；拒绝会明确退出本次登录流程。
7. 客户端复核正文 SHA-256、大小与 Markdown 安全结构；危险/不支持内容失败关闭，不静默删改后继续。
8. challenge 在阅读期间过期则销毁流程并回手机号页，不提交陈旧验证码。
9. 已登录用户的协议升级同意另行设计接口和页面流程，不用本页本地状态替代服务端证据。

### 当前结论

页面目标、两种入口、路由隐私、正文呈现、同意写入边界、目录刷新、版本竞态、Markdown 安全、challenge 到期、拒绝流程、可访问性和验收标准已形成完整评审稿。当前保持 `In Review`，等待用户批准以上九项规则；批准后可更新为 `Approved for Development`，但仍须等待 Flutter foundation 文档通过后才能编码。
