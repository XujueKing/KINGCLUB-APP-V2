# 协议确认页交互与生命周期

## 1. 只读流程

```text
/auth/mobile
  -> 点击《用户协议》或《隐私政策》
  -> /auth/consent(readOnly, initialAgreementCode)
  -> K107 或有效的已验摘要内存缓存
  -> 阅读/切换标签
  -> 关闭并返回手机号页
```

只读模式不显示同意复选框和提交按钮。关闭只返回来源页，不改变手机号输入或原勾选；如果返回时目录 generation 已变化，手机号页必须清除旧勾选。

## 2. 登录版本恢复流程

```text
K102 -> AUTH_CONSENT_VERSION_INVALID
  -> 验证码页清除验证码和旧 ConsentSnapshot
  -> /auth/consent(loginRecovery, loginFlowId)
  -> 强制刷新 K107
  -> 展示两份当前协议与“协议已更新”提示
  -> 用户明确勾选并继续
  -> 原子写入新的内存 ConsentSnapshot
  -> challenge 有效：replace /auth/code(loginFlowId)
  -> challenge 过期：销毁流程并 replace /auth/mobile
```

本页不调用 K102、不保存验证码，也不创建服务端 `consentRecord`。用户回到验证码页重新输入后，K102 才按权威目录校验版本并在登录事务中记录同意。

## 3. 标签与正文

- 顶部使用“用户协议/隐私政策”两个可访问标签，默认定位到入口指定项或发生变化的第一项；两项都必须可到达。
- 标签显示公开版本，正文顶部显示 K107 的标题和发布日期；不展示不存在的生效日或变更摘要。
- 每个标签的滚动位置只在当前页面实例内保存；目录 generation 变化后重置受影响正文到顶部。
- 不以滚动到底作为同意条件，因为它不能证明理解且会阻碍读屏/大字体用户；明确勾选才是客户端动作证据。
- 文本允许系统选择与复制公开内容，但埋点、日志和崩溃附件不得采集选择内容或正文全文。

## 4. 同意、拒绝与竞态

- 复选框默认未选中，链接/标签切换不改变勾选；按钮只有目录完整、缓存未过期、challenge 有效且当前 generation 已勾选时启用。
- 点击同意后先锁定 generation，再原子替换流程协调器中的 ConsentSnapshot；迟到的 K107 结果或重复点击不得覆盖。
- 若点击时缓存已到期，先刷新 K107。目录不变才继续；发生变化则清除勾选并提示重新确认。
- “暂不同意”与系统返回在恢复模式下先提示“不同意将退出本次登录”；确认后销毁 PendingSmsLogin，返回手机号页。
- App 进入后台不视为同意或拒绝；回前台时检查 K107 缓存与 challenge 截止时间。

## 5. ConsentSnapshot

```text
catalogVersion
agreements[]:
  agreementCode
  version
  contentDigest
acceptedAtClient
```

该对象只用于保证客户端提交的是用户看到的 generation。`acceptedAtClient` 不是审计权威时间，也不发送为服务端 consent 时间；K102 最终只发送代码和版本，服务端从当前目录取得摘要与服务器时间。

## 6. 可访问性与外链

- 页面标题、标签、版本、发布日期、正文层级、复选框和按钮具有明确语义与焦点顺序。
- 切换标签后读屏公告新标题和版本，不自动朗读整篇正文；动态字体下正文与底部操作区均可滚动访问。
- 外链显示目标域名并要求用户确认离开；只允许 HTTPS 白名单，返回后保持当前标签和滚动位置。
- 错误通过文本和图标表达，不仅依赖颜色；加载失败时焦点移动到错误标题和重试按钮。
