# 验证码页交互与生命周期

## 1. 主流程

```text
replace /auth/code(loginFlowId)
  -> 从内存流程协调器读取 PendingSmsLogin
  -> 显示 maskedMobile 与两个截止时间
  -> 手输/粘贴/系统填充六位验证码
  -> 每个 inputRevision 最多一次密文调用 K102
  -> Session Repository 原子提交完整凭据
  -> K104 复核最小身份（由会话用例负责）
  -> replace 到白名单 returnTo 或默认首页
```

`PendingSmsLogin` 只存在进程内，包含规范化手机号等 K102 必需字段；页面模型和路由日志只能看到 `loginFlowId` 与脱敏展示值。

## 2. 输入、粘贴与系统填充

- 视觉上可使用六格样式，交互和语义上必须是一个真实输入控件，避免焦点跳格、删除错位和读屏混乱。
- 键盘使用数字模式，但仍在提交前校验 ASCII 数字；不得信任键盘类型等于输入约束。
- 合法粘贴可包含常见空格或连字符，去除包装后必须恰好六位；包含字母、表情或超过六位时整体拒绝并给出文本提示。
- iOS/Android 使用系统提供的一次性验证码 autofill 能力；不申请短信读取权限，不扫描通知，不把短信正文交给埋点或日志。
- 六位完成时自动提交一次，同时保留可访问的“验证并登录”按钮；读屏或外接键盘用户可显式触发，SingleFlight 保证不会重复。
- 错误后清空并聚焦输入，但不得让读屏逐位朗读已输入验证码。

## 3. 重发

- 冷却结束后显示“重新获取验证码”；点击生成新的用户动作 idempotencyKey 并密文调用 K101。
- 快速连点、请求超时后的结果确认复用同一业务 idempotencyKey；每次传输使用新的 requestId/nonce。
- 重发执行期间保留旧 challenge。只有新响应通过契约校验后，才一次性替换 challengeId、两个截止时间和脱敏号码。
- 替换后清空验证码、递增流程 generation，并忽略旧 generation 的所有迟到 K102/K101 结果。
- K101 限流时按 `retryAfterSeconds` 更新重发截止点，不说明命中手机号、设备还是 IP 维度。

## 4. 协议版本变化恢复

```text
K102 -> AUTH_CONSENT_VERSION_INVALID
  -> 清除旧 consent snapshot 与验证码输入
  -> K107 读取新 terms/privacy
  -> /auth/consent(loginFlowId) 明确重新同意
  -> challenge 仍有效：返回 /auth/code 并重新输入
  -> challenge 已过期：replace /auth/mobile 并重新获取
```

服务端密文 E2E 已证明该错误发生在短信证明验证前，challenge 保持 `sent` 且失败次数不增加。客户端不得因版本变化自动勾选、自动同意或自动重新发送短信。

## 5. 返回、前后台与进程恢复

- 返回手机号页前先销毁当前验证码和 PendingSmsLogin；手机号页重新发起时创建新流程。
- 短暂前后台切换可保留进程内输入，但恢复时必须重新计算两个截止时间；超过 challenge 截止点立即进入 `expired`。
- Android 页面可见期间启用安全窗口；iOS 在进入后台前以中性遮罩覆盖任务切换预览。离开敏感流程时恢复宿主窗口策略，避免影响非敏感页面。
- 进程被系统终止后不恢复验证码、手机号、challenge 或 consents；冷启动回 `/auth/mobile`。
- 不把页面纳入可恢复导航快照，不允许通过深链直接构造 `loginFlowId`。

## 5.1 K102 弱网判定

- 握手、本地序列化或明确的发送前离线失败表示业务请求未发出，可以保留验证码并由用户重试。
- 一旦 K102 密文请求开始写入网络，超时、断连、应用被杀或响应解密/验签失败都视为结果未知。
- 结果未知时清除验证码和 PendingSmsLogin，replace 回手机号页并提示“登录结果未确认，请重新获取验证码”。不得后台自动重放。
- 服务端可能已经提交一个客户端未持有凭据的会话；重新验证成功后，单设备事务会撤销它。未完成重新验证时，该会话按服务端访问 TTL 自然失效。

## 6. 会话成功与失败

- K102 成功后立即停止验证码交互，把完整响应交给单一 Session Repository 提交任务。
- 存储提交成功前不得展示首页、连接 WebSocket 或把用户标记为已登录。
- 任一暂存/提交失败时清除全部部分凭据；由于服务端可能已创建会话，后续 foundation 必须定义可审计的本地失败处理与短期服务端过期兜底，页面不得伪称远端已注销。
- 提交成功后由会话用例调用 K104 复核；复核失败按启动鉴权规则清理或重试，不回退显示旧验证码。

## 7. 文案与可访问性

- 标题、脱敏号码、验证码输入、剩余时间、重发、帮助和验证按钮均有独立语义标签。
- 倒计时视觉可每秒更新，但读屏只在“可重发”“验证码已过期”等状态跃迁时公告。
- 错误使用文本、图标与焦点共同表达，不只依赖颜色或震动。
- 动态字体放大、横竖屏、键盘弹出和小屏设备下，输入、错误与重发入口都必须可滚动到达。
- “登录成功后其他 KingClub 设备将退出”保持可见或可访问，不根据账号是否存在改变文案。
