# 验证码页验收

- [ ] 六位输入、粘贴和系统自动填充只触发一次登录请求
- [ ] 非法字符或超过六位的粘贴整体拒绝，不静默截断或提交
- [ ] 错误码、过期、限流、离线、服务不可用和身份人工审核均有稳定映射
- [ ] 确定未发出的 K102 可重试；发出后结果未知必须重置流程，不重放同一验证码
- [ ] challenge 到期与重发冷却分别按截止时间恢复，前后台切换不延长时效
- [ ] 重试登录不重复发短信；重发仅在成功后替换 challenge，旧/迟到结果不再被使用
- [ ] 协议版本变化会刷新 K107、清除旧同意和验证码，但不消耗仍有效 challenge
- [ ] 一次性凭据整体写入安全存储；任一写入失败不留下半会话
- [ ] 新设备登录后旧设备 HTTP/WS 会话失效，新设备正常进入目标路由
- [ ] 返回、前后台切换和进程重启不会把验证码存入普通持久化
- [ ] 日志、埋点、崩溃报告和 URL 不含验证码、手机号、challenge 或凭据
- [ ] Android 安全窗口与 iOS 后台快照遮罩在进入/离开页面时正确启停
- [ ] 读屏、动态字体、外接键盘和倒计时不会阻断输入、提交或重发
- [ ] Widget/集成测试覆盖成功、错误、过期、锁定、限流、双击、弱网、版本变化和安全存储失败
- [x] UI Mock 的六位输入、成功/错误/过期/结果未知、帮助提示和重新获取入口可操作，测试说明位于正式操作之后

## 文档准入缺口

- [x] K101/K102/K107 请求、响应和错误边界已实现并通过密文 E2E
- [x] 页面状态、自动提交、系统填充、粘贴、倒计时和重发规则已形成评审稿
- [x] 旧协议版本不消耗 challenge 的服务端证据已具备
- [x] 用户批准本页规则及 K102 结果未知时重新验证的 V1 策略，评审记录已更新为 `Approved for Development`

以上功能项在 Flutter 实现后逐项验收；页面规格已于 2026-08-24 批准开发，但仍受 Flutter foundation 文档准入约束。
