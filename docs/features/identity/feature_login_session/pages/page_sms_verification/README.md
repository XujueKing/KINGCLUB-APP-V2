# 验证码页

## 文档状态

`In Review`。未批准前不得创建 Flutter 页面实现。

## 页面目标

完成六位短信验证码录入，通过 `K260824000102` 创建或登录 KingClub 会员，并安全接收一次性会话凭据。

## 路由与返回

- **当前建议**：路由 `/auth/code`，参数只存在内存导航状态：`challengeId`、`maskedMobile`、到期/重发时间和 `returnTo`。
- 参数缺失或 challenge 已过期时替换回 `/auth/mobile`，显示“请重新获取验证码”。
- 返回手机号页时销毁当前输入；服务端 challenge 可自然过期，不在客户端伪造取消成功。
- 登录成功后原子写入安全存储，替换路由至协议确认页或目标业务页；不得回到验证码页。

## 信息架构与线框

```text
[返回]
输入验证码
验证码已发送至 138****0000
[ _ ][ _ ][ _ ][ _ ][ _ ][ _ ]
00:60 后可重新获取   [收不到验证码？]
[验证并登录]
```

验证码视觉可分格，但语义上使用单一可访问输入；支持系统短信自动填充，禁止主动读取短信权限。

## 状态与交互

- `editing`：仅接收六位数字；粘贴时过滤非数字但不静默截断异常长内容。
- `submitting`：防重复提交；自动填满可触发一次提交，失败后必须允许编辑。
- `invalid_code`：清空或选中输入，保留剩余尝试的通用提示，不暴露内部计数。
- `expired`：禁止继续提交，引导重新获取。
- `rate_limited/locked`：按服务端重试时间显示，禁止绕过。
- `offline/retryable`：不清输入；用户重试登录时不重新发送短信。
- `success`：一次性处理 `apiKey/refreshToken`，整体安全落盘成功后才导航；落盘失败立即清除部分数据并提示重试登录。

重发使用 `K260824000101` 的新用户动作 idempotencyKey，并以新 challenge 替换旧 challenge。页面离开、账号被撤销或 App 被清理时，不保留验证码。

## API 与协议映射

登录调用 `K260824000102`：`challengeId/mobile/code` 来自当前流程；应用和设备字段来自可信上下文；`consents` 只提交服务端已发布且用户已确认的版本。成功响应中的密钥只能交给安全会话 Repository。

如果当前发布版本要求登录前同意，则使用手机号页已确认版本；若登录期间协议版本变化，服务端拒绝并转协议确认页重新确认，禁止客户端伪造旧版本。

## 埋点、隐私与可访问性

- 埋点：`sms_code_view/submit/result/resend/help`；不得记录验证码、手机号、challenge、账号、Token 或密钥。
- 系统截图/任务切换预览应对验证码和号码区域采用平台安全策略；错误日志只保留稳定分类和 requestId。
- 读屏按“第 N 位”或单输入完整读法，不逐位泄露已输入数字；倒计时变化不应每秒打断读屏。

## 不做事项

不在本页展示实名、设置密码、修改手机号或处理多账号合并；身份冲突只显示通用人工处理入口。
