# 验证码页评审记录

## 2026-08-24 首次正式评审

### 已确认事实

- K101/K102 已实现 300 秒 challenge、60 秒重发冷却、最多 5 次失败、手机号/IP 限流和短信业务幂等。
- K102 成功响应只在握手密文中一次性返回完整会话凭据；页面不得逐字段持久化或记录。
- K107 已提供当前 `terms/privacy` Markdown 和摘要；旧协议版本返回 `AUTH_CONSENT_VERSION_INVALID`。
- 服务端密文 E2E 已证明旧协议版本在验证码校验前被拒绝，challenge 保持 `sent` 且失败次数为 0。
- 新设备登录只有在新事务成功后才撤销旧 KingClub 会话，不影响物业 App 会话。

### 当前评审建议

1. 页面路由只携带内存 `loginFlowId`，原手机号、challenge、协议快照和 returnTo 由功能级流程协调器保存。
2. 手输、合法粘贴和系统填充达到六位后自动提交一次，同时保留显式提交按钮和 SingleFlight。
3. 粘贴不静默截断；规范化后不是恰好六位时整体拒绝。
4. challenge 到期与重发冷却使用两个独立截止时间；新 challenge 成功前保留旧 challenge。
5. 协议版本变化时清除验证码和旧同意，刷新 K107；仍有效的 challenge 不重发、不增加失败次数。
6. 不显示“还剩几次”，避免客户端与并发/服务端真实计数不一致；锁定后停止使用当前 challenge。
7. Android 使用安全窗口，iOS 使用后台快照遮罩；不申请短信读取权限，只使用系统 OTP autofill。
8. 会话凭据通过后续 Session Repository 的原子 bundle 契约提交；成功前不进入 authenticated。
9. K102 无登录业务幂等响应重放：确定请求未发出才保留验证码重试；发出后结果未知则失败关闭并重新获取，下一次成功登录撤销可能遗留会话。

### 当前结论

页面目标、路由隐私、输入与自动提交、错误映射、双截止时间、重发竞态、协议版本恢复、K102 未知结果、会话提交、安全预览、可访问性和验收用例已形成完整评审稿。当前保持 `In Review`，等待用户批准以上九项规则；批准后更新为 `Approved for Development`，但仍须等待 Flutter foundation 文档通过后才能编码。
