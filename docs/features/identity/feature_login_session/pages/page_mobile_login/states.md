# 手机号登录页状态与错误映射

## 1. 页面状态

| 状态 | 含义 | 主要交互 |
|---|---|---|
| `loadingAgreements` | 读取当前强制协议目录 | 手机号可输入，提交禁用 |
| `idle` | 协议目录可用，等待输入 | 输入、打开协议、勾选、提交 |
| `invalidInput` | 客户端基础格式不通过 | 就地提示并聚焦输入框 |
| `consentRequired` | 未明确同意当前 terms/privacy | 高亮协议区，不发请求 |
| `submitting` | 正在握手并发送验证码 | 禁止重复提交和编辑关键字段 |
| `rateLimited` | 服务端要求等待 | 显示统一倒计时，允许修改手机号 |
| `offline` | 协议目录或短信请求因网络失败 | 保留内存输入，允许重试 |
| `serviceError` | 可恢复的服务端/协议错误 | 通用提示，允许重试或编辑 |
| `routingCode` | 已取得 challenge，替换到验证码页 | 终态 |

手机号输入、协议勾选和 idempotencyKey 属于同一表单 generation。手机号或协议版本变化时，旧 generation 的网络结果不得导航。

## 2. 手机号规范化

- V1 国家/地区固定为中国大陆 `+86`，不提供可切换国家码。
- 接受用户粘贴的 `+86`、`0086`、空格和常见连字符；仅在内存中去除国家码包装与分隔符。
- 客户端基础校验为规范化后 `1` 开头的 11 位数字，不固化可能变化的运营商号段；服务端执行最终规范化和合法性判断。
- 输入原文与规范化值都不得写入普通缓存、日志、埋点、崩溃附件或 URL。
- 用户主动修改号码后，清除旧错误、倒计时、challenge 上下文和未确定请求的 idempotencyKey。

## 3. 协议目录状态

页面只有在同时取得当前 `terms` 与 `privacy` 的 `published` 版本，且标题、正文引用和 `contentDigest` 完整时才能进入 `idle`。任一协议缺失、版本撤回、摘要不匹配或正文不可打开时失败关闭。

协议目录更新后必须清除旧勾选；用户同意的是一组确切的 `agreementCode + version + contentDigest`，而不是永久布尔值。

## 4. 短信错误映射

| 结果 | 页面状态 | 规则 |
|---|---|---|
| 成功 | `routingCode` | 只传内存流程对象，不把手机号/challenge 放入 URL |
| `AUTH_SMS_RATE_LIMITED` | `rateLimited` | 使用服务端 `retryAfterSeconds`；不显示命中手机号、设备还是 IP 限流 |
| 手机号参数无效 | `invalidInput` | 通用“请输入正确手机号”，不显示内部校验细节 |
| 明确离线/超时 | `offline` | 结果不确定时复用同一业务 idempotencyKey，传输 requestId 必须更新 |
| 握手/签名/解密失败 | `serviceError` | 不信任响应，记录脱敏 requestId，不自动无限重试 |
| 其他 4xx/5xx | `serviceError` | 统一文案，不透传堆栈、供应商信息或内部码 |

## 5. 防账号枚举不变量

- 已注册与未注册号码使用相同标题、按钮、成功路径和自动注册说明。
- `K260824000101` 不返回注册状态；页面不得在发送验证码前调用任何账号查询。
- 发送结果埋点不得包含手机号、手机号哈希、是否注册或服务端账号标识。
- 页面不得根据响应耗时、短信供应商结果或身份权威状态改变可见文案。
