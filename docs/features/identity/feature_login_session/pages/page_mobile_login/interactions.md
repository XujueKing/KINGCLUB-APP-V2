# 手机号登录页交互与生命周期

## 1. 主流程

```text
进入 /auth/mobile
  -> 读取当前 terms/privacy 发布目录
  -> 输入/粘贴手机号
  -> 分别打开协议正文并返回（不强制滚动到底）
  -> 用户主动勾选
  -> 点击获取验证码
  -> 创建表单 generation + 业务 idempotencyKey
  -> 新握手密文调用 K260824000101
  -> 成功后 replace /auth/code
```

阅读正文和勾选是两个独立动作；链接不能切换复选框，复选框不得默认勾选。首次登录基础协议是必要条件，但营销、定位、通讯录和个性化推荐授权不得捆绑。

## 2. 输入体验

- 输入框语义标签为“手机号”，视觉前缀固定 `+86`，使用电话数字键盘。
- 输入过程中允许空格分组显示；光标、删除和粘贴不能跳位。
- 粘贴内容包含其他字符时保留可解释的数字/国家码格式；无法确定时不静默猜测，提示用户修正。
- 清除按钮只清手机号与相关错误，不改变当前协议版本；是否保留勾选取决于协议版本是否变化。
- 页面进入后台或临时打开协议正文时可保留内存输入；进程被杀后不持久化手机号。

## 3. 提交与幂等

- 按钮仅在协议目录完整、手机号基础格式有效、当前版本已同意且无请求执行时启用。
- 一次点击只创建一个 idempotencyKey；快速连点、超时重试和网络恢复后的结果确认复用该键。
- 每次实际 HTTP 尝试重新握手并生成新的 requestId/nonce；不得重放相同密文包。
- 收到确定业务结果、手机号被编辑或页面流程销毁后结束当前 idempotencyKey 生命周期。
- 成功导航后迟到响应不得覆盖新 challenge 或重复导航。

## 4. 限流倒计时

- 使用服务端 `retryAfterSeconds` 换算为本机单调时钟截止点，不依赖修改系统时间。
- 倒计时前后台切换后按截止点重算，不逐秒持久化。
- 限流期间允许修改手机号；修改后可重新提交，但服务端设备/IP 限流仍是最终权威。
- 不提供“换号码绕过”“联系客服解除”或暴露具体限流维度的提示。

## 5. 导航与返回

- 从启动失效进入时，页面不允许返回启动鉴权页；Android 返回可二次确认退出 App。
- 从用户主动退出或可返回的公开页面进入时，按调用方提供的安全返回策略处理，不恢复已认证页面快照。
- 打开协议正文采用登录功能内只读子路由，返回后保留表单 generation；若目录版本已变化，清除勾选并提示重新确认。
- 到验证码页使用 replace 或受控登录流程栈，验证码页返回时可回本页重新编辑，但旧 challenge 不得继续由本页持有。

## 6. 可访问性与文案

- `+86`、手机号输入、清除、协议链接、复选框和提交按钮分别具有语义标签。
- 错误通过文本、图标和焦点移动共同表达，不仅依赖颜色。
- 键盘、系统字体放大和屏幕旋转时，提交按钮与协议区保持可滚动访问。
- “号码未注册时将自动创建 KingClub 会员”始终显示，不根据号码状态变化。
