# 同城统一身份演进流程

## 第一阶段：模型统一

1. KingClub 使用与物业一致的公版身份表和字段语义。
2. 为旧 KingClub 用户建立 legacy 映射。
3. 创建全局不碰撞的 `personId`。
4. 创建 KingClub `appMembership` 和独立 App 资料。
5. 登录、会话和单设备限制按 `clientAppCode` 隔离。

## 第二阶段：身份对账

1. 对物业和 KingClub 登录身份生成受控哈希。
2. 只生成候选匹配，不凭手机号自动合并高风险账号。
3. 通过用户确认、实名结果或运营审核解决冲突。
4. 建立可审计、可撤销的账号合并记录。

## 第三阶段：集中身份服务

1. 建立 `city_identity` 数据库或身份服务。
2. 先迁移登录身份和会话签发。
3. 物业与 KingClub 通过身份服务取得 person/account/appMembership 上下文。
4. 业务数据继续留在各自数据库。
5. 完成对账和灰度后停止业务库自行签发身份。
