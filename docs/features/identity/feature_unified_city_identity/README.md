# 同城统一账号

- 文档状态：Approved for Development
- 所属业务域：identity
- 最后更新：2026-08-24

## 目标

让物业与 KingClub 直接复用同一个 `U... userAccount`，避免先产生两套用户编号再做自然人合并。

## 已确认决策

- 第一阶段不单独部署中央身份服务。
- 物业数据库中的公共用户体系暂时作为统一账号权威源。
- KingClub 不生成 `K...` 用户账号，也不新增 `personId`；统一用户 ID 就是 `userAccount`。
- KingClub 首次注册通过服务端内部接口查询或创建 `U...`。
- KingClub 先注册时，物业权威库写入账号、手机号登录身份和真实状态的实名占位/摘要。
- 占位不代表物业注册完成，不创建物业成员、房屋、角色或权限。
- KingClub 与物业的资料、会员、会话、钱包、订单和业务权限继续隔离。

## 数据所有权

| 数据 | 权威来源 |
|---|---|
| `U... userAccount` 编号与账号状态 | 物业公共身份模块 |
| 手机号/微信登录身份绑定 | 物业公共身份模块 |
| KYC 状态、来源和必要摘要 | 物业公共身份模块 |
| KingClub 成员和资料 | KingClub 数据库 |
| KingClub Session/API Key | KingClub 数据库 |
| 物业成员、房屋和物业权限 | 物业数据库的业务域 |
| 钱包、金币、订单 | 各 App 严格独立 |

## 当前建议

- KingClub 只通过受保护内部接口访问统一身份，不直接读写物业业务表。
- 内部接口只在首次注册、身份绑定或冲突处理时调用；普通 KingClub 请求使用本地账号投影。
- 统一身份变更使用 Outbox/事件同步，KingClub 按版本幂等消费。
- 将来抽离身份模块时保持 `U...` 不变，只迁移权威表和内部接口实现。
