# 同城统一身份

- 文档状态：In Review
- 所属业务域：identity
- 最后更新：2026-08-24

## 目标

让物业与 KingClub 在业务数据独立的前提下，使用一致的基础用户模型，并为未来统一登录、账号合并和跨 App 授权建立稳定身份主键。

## 已确认决策

- KingClub 复用物业公版用户体系的表结构、字段语义、安全存储和会话规则。
- KingClub 可以在公版基础上扩展 App 成员、资料和审核能力。
- 物业和 KingClub 都面向同城用户，未来建设统一用户系统。
- 两个 App 的业务数据库、会员、权限、钱包和订单保持隔离。
- 第一阶段不单独建设中央身份服务；KingClub 在独立库中使用兼容模型并预留后续抽离能力。

## 当前建议

- 建立不可暴露给客户端的全局 `personId`。
- `userAccount` 表示平台登录账号，`appMembership` 表示某个 App 内成员。
- 登录身份绑定到全局账号/自然人，不直接绑定到 KingClub 业务表。
- 第一阶段即记录 `sourceSystem + legacyUserAccount + personId + appMembershipId` 映射。
- 如果暂时使用独立身份表副本，ID 必须全局不碰撞并保留未来迁移来源；后续抽成 `city_identity` 数据库或服务。

## 默认共享和隔离

| 数据 | 默认策略 |
|---|---|
| personId | 统一 |
| 手机号/登录身份 | 经授权后统一 |
| 账号安全与冻结状态 | 统一或同步 |
| 实名结果摘要 | 按合法目的最小共享 |
| 昵称、头像 | App 独立 |
| 会员审核 | App 独立 |
| 好友、关注、聊天 | 待产品决策 |
| 钱包、金币、订单 | 严格独立 |
| 门店、代理和物业权限 | 严格独立 |
