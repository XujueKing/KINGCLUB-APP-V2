# 协议确认页

## 文档状态

`In Review`。未批准前不得创建 Flutter 页面实现。

## 页面目标

在当前发布的用户协议或隐私政策尚未获得有效同意时，展示版本摘要和全文入口，取得明确同意后才允许创建/继续登录会话。它不是默认每次启动展示的注册页。

## 入口、出口与路由

- **当前建议**：路由 `/auth/consent`，参数为服务端协议目录引用和已验证 `returnTo`，不得携带手机号或凭据。
- 从手机号页打开协议全文属于只读子路由；从登录版本冲突进入时要求重新确认。
- 同意后返回原登录动作或进入目标业务路由；拒绝/返回则清除待提交验证码与临时登录上下文，回手机号页。
- 协议目录不可用时失败关闭，不得使用客户端硬编码版本继续登录。

## 信息架构与线框

```text
[关闭]
协议与隐私说明
版本、生效日期、变更摘要
[用户协议 >]
[隐私政策 >]
[ ] 我已阅读并同意以上协议
[同意并继续]
[暂不同意]
```

全文页面显示标题、版本、生效日期、可滚动正文和返回；不得以默认勾选、倒计时自动同意或弱化拒绝按钮诱导授权。

## 状态与规则

- `loading_catalog`：读取服务端已发布协议目录。
- `ready`：版本和正文完整，可分别打开阅读。
- `consenting`：防重复提交；记录协议代码、版本、用途和客户端时间，服务端时间为审计权威。
- `version_changed`：清除旧选择并加载新版本，明确提示已更新。
- `offline/error`：不可继续登录；允许重试或暂不同意退出。
- `accepted`：只使用服务端确认结果继续，不在客户端伪造 consentRecord。

V1 默认要求 `terms` 与 `privacy` 两项均明确同意。未来营销授权、定位或通讯录授权必须拆分，不能捆绑到基础登录协议中。

## 数据、埋点与可访问性

- 页面输入输出仅包含协议代码、发布版本、展示内容引用和同意结果；手机号、账号和会话密钥不属于页面模型。
- 埋点：`consent_view/document_open/accept/decline/error`，记录协议代码与公开版本，不记录正文选择、用户身份或敏感数据。
- 支持动态字体、读屏标题层级、正文滚动位置恢复和清晰焦点；复选框与链接分别可操作。

## 不做事项

本页不承担实名认证、个性化推荐授权、系统权限申请或广告授权；每种额外目的需独立功能文档和撤回机制。
