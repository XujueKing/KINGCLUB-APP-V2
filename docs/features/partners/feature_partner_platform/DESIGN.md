# 合作平台流程与设计草案

## 页面与权限

“我的”原专属客服位置显示合作平台，沿用其他服务项图标尺寸与文案规格。入口可见不等于获准营销：未申请进入介绍/申请，审核中进入进度，被拒进入原因及修改；批准后进入工作台。暂停合作仍可看本人历史账目、提出资金问题，不能领新任务、签新绑定或发布营销活动；已有款项是否冻结需独立的资金状态，不能用禁用登录吞掉余额。

权限来自可信会话：普通会员仅申请与本人状态；合作伙伴仅本人任务/收益/顾客；平台审核员按被授予权限审核申请与任务；**super_admin或已授权customers.read可读全平台客户/合作者名录**。角色不采用agenyType数字大小推定。每次查询和写入均校验对象归属，客户端隐藏菜单仅做展示。

## 合作身份与商家主体

2026-10-08 已确认要求，来源为 [RQ-20261008-01](../../../product/2026-09-09-native-product-review/REQUIREMENT_INBOX.md)。合作体系分为以下四种身份；本节补充已有权限模型，具体页面与操作授权还需按身份和区域细化。

| 合作身份 | 所属部分 | 已确认职责 |
|---|---|---|
| 超级管理员 | 管理员部分 | 合作平台的超级管理员身份 |
| 省级合作者 | 管理员部分 | 只负责组织市区域合作者 |
| 区域合作者 | 管理员部分 | 可以执行申请成为商家的任务 |
| 合作者 | 普通合作部分 | 可以执行申请成为商家的任务 |

商家经营主体一般由一个普通会员账号担任该主体的超级管理员。该会员的商家管理权限对应经营主体及其授权门店，合作平台超级管理员的权限对应合作平台；服务端分别核验这两种权限范围。会员没有合作身份时，仍可按商家主体授权管理商家。

商家入驻任务由区域合作者或合作者执行，任务执行归因与商家主体管理员账号分别保存。省级合作者按已确认职责组织市区域合作者。四类合作身份与现有 L1–L15 收益等级分别定义，组织层级不自动产生级差分佣。

实施状态：现有代码已有上级关系、城市信息、主体所有者门店授权及部分平台操作权限，四类身份标签、L1–L15独立展示和超级管理员指定省/市负责范围已实现，详见[合作者名录与信息管理](2026-10-08-collaborator-management.md)。身份设置不自动授予平台操作权限。具体区域审批权限、入驻验收人及商家管理员绑定时点仍待详细设计。

## 页面布局

全页沿用APP内页白色居中标题、统一左返回。背景#111111、卡片#202020、主文案近白、辅助文案#A6A6A6，香槟色用于按钮及费率。16dp外边距、20dp卡内边距、12dp卡间距、正常文字16dp/约1.4行高，金额32dp，主按钮52dp。大字时允许自然增高，不固定截断；不复刻亮黄大卡片。所有金额复用千分符和币种精度，不跨币种直接相加。

### 合作首页

1. 身份行：头像、合作伙伴称谓、L等级、当前活动费率；点击可看15档费率及已配置升级条件。没有条件时不造进度条。
2. 收益卡：本月已入账收益为主金额；下方可提现、待结算、冻结/提现中分区。提供“提现”“转入平台余额”，进入金额确认流程，不直接转账。
3. 首要操作两格：合作伙伴码、领取任务。任务入口展示真实进行中数量，不制造营销红点。
4. 列表：我的派对、提成明细、我的特约顾客、任务记录。超级管理员额外显示客户名录。
5. 待结算不并入可提现；待审核任务奖励不冒充实际收入。错误保留有效旧数据并提示局部重试，不先清空整页。

### 申请

简介→所在城市、合作方向（带局/推广用户/推广商户，可多选）、联系方式复用已认证资料、经验说明→协议确认→提交→审核状态。一次读取返回资料及所需字段；提交返回申请状态。审批人、时间、原因留记录。协议版本由平台配置，不擅自编写法律承诺。

### 任务中心

顶部“可领取 / 进行中 / 已完成”；类型筛选获客、带局、商户拓展。卡片显示任务名、城市/门店logo、奖励方式、截止时间、名额及状态。金额规则不完整的任务不能发布。

详情顺序：奖励→完成条件→步骤→预算/名额→有效期→审核及到账规则→固定52dp领取按钮。注册任务步骤：领取任务→展示合作码→用户完成注册并扫码→服务器确认绑定和新客资格→奖励确认/待审核→分佣入账。注册资格满足但评分尚未最终确认时不显示已赚到20元。

商户拓展：领取→提交商户线索→平台去重→签约证据→指定审核人验收→入账。商家任务发布表单仅包含任务、奖励和验收，不恢复旧“编辑&发布”内容后台；入口置于其有权限的商家业务端，APP本模块负责领取/跟踪。

### 合作伙伴码与顾客

二维码页：伙伴头像、昵称、合作身份、任务名称（有绑定任务时）、居中码及简短说明。关系码不能与消费扣款码混用；解析结果不得授权后台或扣款。服务端校验合作有效状态、任务、截止、领取资格、是否自绑/已绑定，并对首次绑定及奖励去重。

扫码成功显示真实绑定结果及适用奖励说明，返回扫码前一页。多次扫码同一关系返回已绑定，不再奖励；已绑别人的会员不得悄悄换绑。活动链接可以预填候选推荐人，但不能靠客户端参数直接记钱。

特约顾客列表：头像/昵称、关联时间、有效状态、本人获得的贡献佣金；筛选新关联与有消费。顾客详情只列本人可见的关联和收益记录，不提供身份证、完整手机号、其他门店储值或无关订单。超级管理员客户名录另有强制权限、分页、搜索和访问审计。

### 提成与资金

提成明细按月份、来源（带局/特约顾客/新客任务/商户任务）、状态筛选。每条显示事项、门店、时间、金额/币种，点入可看到来源订单/任务、有效消费、费率、本人所得、规则版本及入账状态。

提现页显示可提现额、提现方式、金额、手续费及预计到账规则；服务端返回受理≠到账，只有支付通道确认才显示完成。转余额页明确“转入平台余额”，校验同币种目标账户，双方账目同事务成功，不标为银行卡提现。暂不支持的币种或通道需明确不可操作原因。

交易提交只禁用该动作，网络未知通过requestId查结果。系统通知用提交后的事件队列，卡片、未读、横幅去重，点入对应收益/提现详情；不能把前台WebSocket当成离线推送已完成。

## 数据与结算规则

以下是逻辑实体，不是已创建的表或已登记接口ID。先复用现有会员、商户、派对、订单、支付、币种、授权与通知记录，仅新增缺失实体。

| 实体 | 必要内容/约束 |
|---|---|
| 合作申请及身份 | memberRef、状态、审批轨迹、等级及生效时间；会员有且仅有一个当前平台合作身份 |
| 合作规则版本 | 适用门店/任务、有效期、平台费率、15档等级费率、推荐费率、基数/叠加/舍入/退款/成熟规则；发布后不可覆盖旧版本 |
| 顾客关联 | customerRef、partnerRef、来源任务、绑定时间、终止原因；当前有效关系唯一；资格和一次性新客奖励另存唯一事实 |
| 任务及领取 | 发布者、承担预算主体、任务类型、验收条件、币种预算、规则版本、领取及验收状态；并发领取不超预算 |
| 收益事件 | 来源订单行/支付分配/任务、受益人、归因类型、基数、费率、金额、币种、规则快照；来源事件+受益人+奖励类型唯一 |
| 分佣账户及流水 | 独立可用/待结算/冻结，按币种隔离；记账平衡、只追加与冲正，账本为准；不得使用ProfileAssets展示字段直接发钱 |
| 提现/内部转账 | requestId唯一、金额、来源与目标、状态、通道流水、关联记账批次；冻结→确认出账或失败释放 |

商家应付平台与平台应付营销分开记录。以1,000、30%、10%为例：商家佣金应付300、平台营销应付100；100不是再由商家额外支付。平台是否收讫、商家应收和营销可提现是不同事实，2026-10-07用户确认每笔收益入账满7天可申请提现，非固定周几、非次月。实际入账与商家收讫条件分开，未完成资金出账前不能宣称已支付。

2026-10-07用户确认：推荐2%从带局者的原提成中划分，不另加。逐顾客计算：全局有效消费1,000，带局比例10%，其中有推荐人的顾客消费600，则带局者600×8%+400×10%=88，推荐人合计600×2%=12，总分佣100。每位推荐人只获得本人关联顾客的份额；不能按三个人头给三份整场2%。同一受益人兼带局/推荐身份时仍保留两项归因，总收入不增加。组织层级不自动产生分佣；级差方案未获确认。

2026-10-07最终确认：有效消费基数仅包括微信、平台余额实际支付的消费金额。本店储值本金、赠送金额、优惠券、金币均排除；此前“本店储值本金计入”的口径已被用户修正。组合支付按每位顾客的支付来源拆分，不按订单总价计佣。例如消费1,000元，本店储值支付600元、微信支付400元，则基数为400元；带局比例10%时总分佣40元，若该顾客有推荐人，其中8元归推荐人、32元归带局者。全额本店储值付款的消费基数为0，不产生这两项消费提成。

退款按原订单行、原支付来源、原归因和原比例冲正，不读取新的等级/关系再重算。只退本店储值等不计佣部分时，不冲减微信/平台余额部分产生的佣金；部分退款累计冲回不超过原收益。已经提现的收益需要明确追偿/后续抵扣政策，不直接修改历史流水。充值和押金解冻不是计佣消费。活动加价、税费归属及其他未确认渠道不得自动扩大计佣范围。

直接加密资产计价的门店同样必须携带assetRef、网络/合约（适用时）与精度，禁止统一乘100或以浮点算钱。新客8–20元目前只确认人民币奖励；不自动推导其他资产奖励或汇率。跨币种内部转账不自动兑换。

## 一页/一次动作一次请求

以下为候选动作名，实施时登记正式超级接口编号和存储过程，不能将本表视为已部署。

| 页面/动作 | 一个存储过程返回/处理 |
|---|---|
| partner.context | 身份/申请、等级、权益、收益汇总、任务数量及可见入口，一次返回 |
| partner.application.submit/review | 校验身份/审批权、写申请或审批、返回新状态 |
| partner.tasks / task.context | 分页任务与汇总；详情返回全部条件、奖励及可操作状态 |
| task.claim / task.submit / task.review | 幂等领取、提交证据、审核；审核与确认奖励原子化 |
| partner.code / partner.bind | 生成或解析业务凭证，校验状态，绑定关系并创建唯一任务事件 |
| partner.customers / customer.context | 仅本人关联及贡献；管理员名录独立权限动作 |
| partner.earnings / earning.context | 汇总与分页、明细证据及状态 |
| partner.payout.context / payout.submit | 可提现和通道/费用；锁余额、创建申请与事务事件 |
| partner.transfer | 同币种分佣扣账、平台余额入账、唯一通知事件同事务 |

读页面不启动无必要写事务。外部提现网络请求由现有适配器执行，不塞进DB事务；回调/查询按唯一通道凭证落账。首次分页显示后可后台预取，其余请求限真正用户动作或分页，不能为一个首页串多个查询。新接口不信任客户端userAccount、等级、费率或金额结论。

## 验收门槛

- 未批准合作身份不能通过深链/伪造请求读分佣或他人顾客；普通营销不能读客户名录；停用状态即时生效。
- L1/L15分别6%/20%；1,000×10%=100；升级不改旧单；两次支付不得把整个订单基数重复计算。
- 重复扫码、并发首次绑定、重复审核/支付回调只产生一次关系和奖励；没评分不当作满额。
- 同订单不同受益人/不同来源正确分列；规则缺失或预算不足禁止发布，不发0元假成功。
- 退款、部分退款、提现失败、重复回调、网络超时恢复均可对账；提现与转余额不能并发透支。
- APP四种语言，屏幕宽度320–430dp、大字、键盘不顶起支付栏、长店名/千分位/不同币种不溢出。
- 真实空、加载、失败分开；缓存不跨账号；收益变更局部更新；到账通知可点详情且不重复计未读。

首期验收不包括预约管理、收银、内容发布、软件设置。文档/布局草图完成不代表任何资金功能已上线。
