# 任务与独立奖励账本 · 2026-10-07

本节点为代码实现和隔离测试，尚未部署或安装。消费订单提成、退款冲正、提现和转平台余额仍未接通。

## 已实现

- 合作首页任务入口、任务列表和详情，现有深色卡片、白色标题、52高按钮，四语言。
- 平台管理员创建草稿；门店所有者可从商家身份页创建本店草稿。只有平台管理员能批准发布，门店不能单方承诺平台奖励。
- 规则描述必填，明确验收和评分要求。会员获客奖励限定8–20元，商户任务金额由平台配置；金额明确为人民币。尚未配置颜值评分分段，不伪造自动评分。
- 每次领取对应一次获客名额，按最高奖励预留预算；同一合作伙伴每任务只能有一个进行中名额，处理后可以再次领取。领取可取消，释放预留预算。
- 会员证据必须是已批准注册且已关联该合作伙伴的会员；商户证据必须是有效门店。平台人工核对新客资格、签约和任务规则；引用有效不等于自动验收成功。
- 审核奖励必须在任务上下限内，拒绝奖励必须为0；不能审核自己的领奖。每个会员/商户全局只能产生一笔该类获客奖励。
- 领取、创建和审核有幂等请求，未知结果只允许重试原请求；明确业务拒绝允许修正输入。
- 独立奖励账本从任务审核入账时起算，满7天进入可提现期。首页和收益明细展示待结算与已成熟金额、入账时间、可提现日期和审核说明。提现/转余额按钮仍未开放，不将记录收益冒充真实付款。

## 接口与数据库

复用K261007002030。context及任务动作→kingclub_partner_tasks，其余申请/团队等→kingclub_partner_portal。每个页面/动作一次请求、一次过程，动作直接使用返回结果更新；分页和进入子页是独立动作。

迁移365新增Task、TaskClaim、Reward三表及过程目录。任务锁串行控制预算，顾客/门店获客唯一键防重复奖励；所有写入同事务回滚。平台余额与门店储值不被此过程修改。

## 验证

真实MySQL隔离随机表/过程：草稿权限、发布、预算不足、领取取消、提交越权、自己审核拒绝、重复审批、跨任务重复获客奖励、奖励回滚、本人账本隔离、7天到期归类、门店草稿和平台发布权限通过。测试只使用合成记录并清理本次对象。

客户端覆盖精确分金额与千分位、超时原请求重试、业务拒绝后修正、空任务无虚构奖励。仍缺真实评分来源、签约自动验收、实际消费提成、资金出账及真机端到端验收。
