## 目标与用户价值

让已登录且会员准入通过的普通会员，在一个轻量、稳定的首页看到当前门店语境、核心到店入口、近期行程摘要和受控运营内容，并能快速进入 AA、VIP 组局、入场凭证或安全扫码。

## 已确认事实

- 旧 `pages/index/index` 同时承载首页、聊天、通讯录、内容、储物柜和我的，`index.js` 约 10 万字节，不能整体迁移。
- 旧首页展示昵称、等级、金币/钻石、广告、AA、VIP、扫码和图文/视频瀑布流；底部栏目还由服务端 `tabData` 动态控制。
- App Shell v1 已确认四个固定主目的地和中央扫码；首页只归属到店业务，不复制消息、发现、钱包、储物柜或个人资料。
- KC-P-027～033 分别拥有 AA、VIP 和入场页面；KC-P-012 负责扫码安全分流。

## 当前建议

首页 v1 固定为以下五段，模块顺序由客户端版本控制：

1. 品牌头部：KingClub 标识、会员称呼和当前门店/城市文字；不展示完整账号或资产余额。
2. 核心入口：一起玩 AA、VIP 组局、入场凭证、安全扫码。
3. 今晚行程：最多一个最相关的预约/组局/入场摘要；没有时显示轻量引导。
4. 精选活动：运营卡片轮播或横向列表，动作仅允许批准的 `HomeAction`。
5. 服务提示：营业/活动提示及更新时间，不形成新的专题详情页。

首页不使用无限瀑布流。短视频/作品统一归 KC-P-013 发现页，资产统一归 KC-P-039/我的。

## 本期不包含

- 首页内聊天、通讯录、内容瀑布流、钱包余额、金币/钻石、储物柜或编辑资料。
- 服务端动态下发 Tab、Widget 类型、任意页面路径或任意 URL。
- 首页内直接下单、付款、核销、签到或确认入场。
- 新增门店列表、活动专题详情、全局搜索或通知中心页面。

## 待用户确认

1. 首页采用“品牌头部 + 四个核心入口 + 今晚行程 + 精选活动 + 服务提示”的 v1 结构。
2. 首页不再展示金币、钻石、等级进度和内容瀑布流；它们分别归我的/钱包和发现页。
3. 首页与底部中央按钮都可打开安全扫码，两个入口行为完全一致。
4. 精选活动只允许无动作、打开本期批准页面或切换主 Tab，不打开外部网页。
5. 首页不主动申请定位；当前门店/城市使用账号默认值或服务端已保存选择，门店切换后续另行评审。
