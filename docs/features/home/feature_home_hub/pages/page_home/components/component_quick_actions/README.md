## 视觉规则

- 单行三列，不改成 2×2，也不增加第四个入口。
- 左、中旧尺寸 `246×140rpx`；右侧旧宽 `160rpx`。
- 背景径向渐变 `#B8A289 → #7E6951`，圆角 `15rpx`。
- 第一、第二项的低透明度装饰图形固定在左侧并允许被卡片边界裁切；中文标题位于右侧偏上，英文位于右侧下方。
- 第一项使用旧 `H01.png` 的符号底纹；第二项使用旧 `H02.png` 的多人底纹；不能换成普通线性图标。
- 第三项比前两项窄：`qrcode2.png` 作为铺满卡片的低透明度二维码底纹，`qrcode3.png` 作为居中的深棕扫描框，`SCAN QR` 位于图标下方。
- 中文标题约 `38rpx`、600 字重；英文约 `20rpx`、正常字重；全部文字为深棕 `rgb(66,46,25)`。
- 三张卡使用同一米棕色体系，但不得抹掉原图中从左上到右下的轻微明暗变化。
- H01/H02/二维码背景纹样都保持低透明度；前景文字和扫码框必须清晰。
- 卡片间保留黑色窄缝，三项整体左右对齐首页 Banner 和瀑布流内容边界。
- 点击保留轻量按压反馈，不改变内容、文案或图标。
- 中文标题不得用粗体近似：严格按旧版 `38rpx / font-weight: 600` 换算；英文严格按 `20rpx / normal` 换算。两行均按卡片右边缘对齐，保留旧版 `30rpx` 右边距，不能再用相对 `Alignment` 分别估算位置。
- 左、中、右卡宽严格保持 `246:246:160`，卡高统一 `140rpx`；卡间隙按旧版剩余空间等比换算，三张卡的上下边缘与文字基线必须整齐。
- H01/H02 分别按旧版 `126rpx`、`140rpx` 尺寸和负边距裁切；二维码底纹按 `110rpx`、旋转 45° 与旧负边距还原，不使用三张统一尺寸。
- 2026-08-28 用户最终确认：三联入口整行只允许存在一条斜向光带。三项共用同一动画时钟、同一进度和同一移动速度；光带从“一起玩”连续经过“组局玩”再进入“扫码”，不得分别计算 3/6/9 秒位置。
- 2026-08-28 动效微调：单条光带完整穿越周期由 6 秒加快至 4 秒，光带宽度由整行的 28% 放大至 42%；移动仍必须线性、匀速且只有一条。
- 2026-08-28 第二次尺寸微调：保持 4 秒穿越速度不变，光带宽度由整行的 42% 继续放大至 60%。
- 2026-08-28 透明度微调：光带中心峰值透明度由旧版 30% 提升至 70%；透明边缘、60% 宽度、4 秒匀速和单光带跨卡轨迹保持不变。
- 2026-08-28 第二次透明度微调：光带中心峰值透明度由 70% 降至 20%；透明边缘、60% 宽度、4 秒匀速和单光带跨卡轨迹保持不变。
- 2026-08-28 第三次透明度微调：按用户“再大一点”的要求，将中心峰值透明度由 20% 小幅提高至 30%；其他动效参数不变。
- 每张卡内部严格复刻旧版伪元素：流光层宽高均为卡片的 `200%`，初始位于 `top:-50% / left:-50%`，使用 `45deg` 的 `transparent 25% → rgba(255,255,255,.3) 50% → transparent 75%` 渐变，并带 `30deg` 旋转；移动范围为自身宽度的 `-100% → 100%`。
- Flutter 绘制时必须以“光带本体相对竖直方向倾斜 30°”作为视觉验收结果；不得把 WXSS 的渐变角和元素旋转角直接相加，避免最终呈现为近乎竖直的白条。
- 流光只由卡片圆角边界裁切，不得以卡片等尺寸的旋转矩形代替，否则边缘会形成突兀的大三角；系统开启“减少动态效果”时停止流光。
- 恢复旧版 `hover1`：按下期间整卡透明度降为 70%，松开或取消后恢复；不额外叠加 Material 水波纹。
- 旧版滚动超过阈值时显示顶部粘性副本 `order_top`；V2 是否复刻粘性副本以截图滚动 QA 为准，但内容必须完全一致。

## 交互边界

- 300ms 内重复点击只产生一个 RouteIntent。
- 一起玩和组局玩只进入已批准的 Fake 页面，不创建真实预约或订单。
- 扫码只进入安全扫码 Mock，不启动相机、不识别真实二维码。
- 不可用时位置不消失，显示稳定不可用原因。

- [ ] 三张卡按 `246:246:160` 比例排布，H01/H02/二维码纹样分别使用原版尺寸与偏移。
