## 1. 本轮目标

### 已确认事实

- 用户于 2026-08-26 明确要求：Flutter App 先逐页复刻旧微信小程序 UI，再评审后续改版。
- 本轮仍遵守“先文档、后开发”：本规范获用户确认前，不修改 Flutter 首页实现。
- 首页只使用 Mock/Fake 数据，不连接旧超级接口、新超级接口、WebSocket、支付、推送或其他生产 SDK。
- 复刻依据为用户提供的旧版首页截图，以及旧项目 `pages/index/index.wxml`、`index.wxss`、`index.js`。

### 已确认方案

- 视觉层先忠实还原旧首页的信息密度、配色、图片区块、快捷入口和悬浮底栏。
- 技术层继续使用 Flutter V2 已批准的类型化导航、会话守卫和 Fake Runtime；不把旧版超大 `index` 文件结构迁回 V2。
- 复刻完成并通过截图对照验收后，再单独建立“首页改版 v2”文档；不得在复刻过程中混入未经确认的新设计。

## 2. 复刻边界

### 必须复刻的 App 内容

1. 黑色首页背景与香槟金/棕金视觉体系。
2. 顶部 KingClub Logo、会员等级、认证、经验、金币、钻石和经验进度条。
3. 首屏大幅运营 Banner。
4. “一起玩 / 组局玩 / 扫码”三联快捷入口。
5. 两列运营海报瀑布流及其圆角、间距和裁切方式。
6. 底部悬浮胶囊导航、选中态圆形底和五个旧版图标。
7. 纵向滚动、Banner 轮播、点击反馈、下拉刷新和底栏切换的 Mock 交互。

### 不绘制的系统/平台内容

- 不在 Flutter 页面内部绘制手机外框、刘海、时间、Wi-Fi、电量和系统 Home Indicator；这些由 Android/iOS 系统负责。
- 不伪造微信小程序右上角“更多/关闭”胶囊，因为它属于微信宿主界面，不是 KingClub 页面资产。用户于 2026-08-26 已确认 App 不需要该控件。
- Flutter 使用真实 SafeArea，首页内容从系统状态栏下方开始。

### 底栏确认

- 用户于 2026-08-26 明确否决“中心图标映射安全扫码”，要求完全复刻旧版底栏。
- 五个一级位置固定为：`首页 / 消息与通讯录 / 内容 / 私人储物柜 / 我的`。
- 中央白底粉色爱心图标是内容 Tab；该图标以用户提供截图为最终视觉依据。安全扫码只从首页“扫码”等受控业务入口进入。
- 视觉与主目的地语义复刻旧版，但工程仍使用五个独立 Flutter 分支，不恢复旧版超大 Swiper 或服务端动态 `tabData`。
- 旧版“已在内容 Tab 时再次点击中心按钮进入作品发布”不在本期恢复，因为 D2 作品发布仍是已确认暂缓项；若未来恢复，必须先建立发布页面文档并变更范围基线。

## 4. 尺寸与布局基线

旧页面以 `750rpx` 为设计宽度。Flutter 以逻辑像素按屏宽等比换算，并在 `360～430dp` 手机宽度内保持比例。

| 区域 | 旧版依据 | Flutter 复刻规则 |
|---|---:|---|
| 页面背景 | `#000000` | 全屏纯黑，内容可滚动 |
| 左右内容边距 | `30～35rpx` | 约屏宽 `4.0%～4.7%` |
| 顶部品牌区 | 固定 `680rpx` 内容宽 | SafeArea 下方横排，Logo 与资产区基线对齐 |
| Logo | CSS `140rpx` 宽 | 屏宽约 `18.7%`，保持原图比例 |
| 经验条 | CSS `360rpx` 宽、`4rpx` 高 | 屏宽约 `48%`，香槟金前景与低透明底色 |
| Banner | CSS `690×417rpx` 容器 | 内容宽约 `92%`，按素材比例裁切，圆角约 `8dp` |
| 快捷入口 | `246×140rpx`、扫码 `160×140rpx` | 单行三列，约 `8dp` 间距，圆角约 `8dp` |
| 瀑布流 | 两列、`6rpx` 轴间距 | 两列 Masonry，约 `6～8dp` 视觉缝隙 |
| 海报卡 | `332rpx` 宽，`410～460rpx` 高 | 保持各素材原始长宽比，统一圆角，不拉伸 |
| 悬浮底栏 | `660×110rpx`、圆角 `50rpx` | 屏宽约 `88%`，高度约 `58dp`，底部叠加 SafeArea |
| 底栏背景 | `#1a1611EE` + blur 20 | 深棕黑半透明胶囊；设备不支持模糊时使用同色实底 |

## 8. 交互契约

| 控件 | Mock 行为 | 约束 |
|---|---|---|
| Banner | 4 秒轮播；可左右滑动 | 开启“减少动态效果”后停止自动播放 |
| 一起玩 | 打开已批准 AA 路由的 Mock 流程 | 300ms 防重复导航 |
| 组局玩 | 打开已批准 VIP 组局 Mock 流程 | 不创建真实订单 |
| 扫码 | 打开已批准 SafeScannerRoute Mock | 不调用相机和真实扫码 SDK |
| 海报 | 打开受控 Mock 预览/已批准页面 | 未完成目标页映射时只做可关闭预览，不拼任意 URL |
| 下拉刷新 | 切换 Fake 场景并保留旧内容直到完成 | 不发网络请求 |
| 底栏 | 切换首页、消息、内容、私人储物柜、我的五个固定分支 | 中央不是扫码；不恢复服务端动态 Tab |

## 9. 状态与异常

- `initialLoading`：保留顶部、快捷入口和底栏位置，Banner/海报显示等比例骨架。
- `ready`：完整复刻场景。
- `partialImageError`：单张图失败时保持卡片尺寸和文字替代，不影响其他模块。
- `emptyPromotion`：无 Banner/海报时保留快捷入口；使用受控空态，不显示上一版新设计模块。
- `refreshing`：保留当前画面并显示轻量刷新反馈。
- `offlineCached`：继续展示本地 Fake/缓存快照并标注离线。
- `sessionInvalid`：由全局路由守卫退出首页，不在页面内伪装登录态。

## 10. 视觉验收

1. 在同一逻辑视口和相同滚动位置下，把旧版参考图与 Flutter 截图并排比较。
2. 首轮重点核对：顶部比例、Banner 高度、三联入口宽度、瀑布流间距、底栏宽高与底部安全距离。
3. 必须使用旧版真实 Logo、入口纹样、资产图标和底栏图标。
4. 不得出现上一版首页新模块，不得绘制微信/手机系统外壳。
5. Android 模拟器至少验证 `393×852` 等效视口；再检查 360dp 与 430dp 宽度无溢出。
6. 主流程控件可点击，滚动与返回正常；200% 字体不造成核心动作不可达。
7. 完成实现后必须生成 `design-qa.md`，记录参考图、实现截图、差异、修正结果和最终 `passed/blocked`。
