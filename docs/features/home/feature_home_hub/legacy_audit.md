# 旧版首页审计与 V2 取舍

- 文档状态：`Approved for Development`
- 审计基线：`KingClub-app / master / 505d222 / 1.1.37`

## 已确认事实

| 旧版能力 | 证据/行为 | V2 去向 |
|---|---|---|
| 首页头部 | 昵称、性别、等级、经验、认证、金币和钻石同时展示 | 首页只保留轻量会员称呼；资产归我的/钱包 |
| 快捷入口 | 一起玩、组局玩、扫码在顶部与滚动区重复出现 | 四个稳定业务入口，扫码可与 Shell 中央动作等价 |
| 广告 | `AD` 轮播，点击后在 index 内展开参数化内容 | 精选活动卡片；动作枚举 allowlist，不接任意路由 |
| 软文/视频 | `nat_list` 瀑布流并混合视频播放 | 移至 KC-P-013 发现页；首页不做无限流 |
| 动态 Tab | 服务端 `tabData` 决定底部栏目和页面数量 | 已由 App Shell 决策为客户端固定四主目的地 |
| 首页接口 | `S231202503100658` 同时返回用户、资产、广告、内容、Tab、版本与礼物信息 | 拆成面向首页的只读投影；页面不感知旧接口字段 |
| 生命周期 | `onShow` 自动刷新，滚动到底继续请求 | 首次加载、显式下拉刷新和有界摘要；重选 Tab 只滚到顶 |
| 页面弹层 | 昵称、奖励、更新、入场结果等共用首页弹层 | 分别归 identity、wallet、bootstrap、admission 页面 |

## 已确认风险

- 首页数据接口责任过宽，一个失败会同时影响导航、资料、内容和运营展示。
- 页面使用本地 `preUserInfo.userAccount` 授权并输出大量日志，不符合 V2 Session 边界。
- 服务端 `tabData` 和广告内容可改变客户端结构，缺少稳定导航 allowlist。
- 空态、局部错误、缓存新鲜度和迟到响应处理没有独立状态模型。
- 同一业务入口重复出现但缺少统一防重复导航。

## 当前建议的保留原则

- 保留夜生活品牌氛围、AA/VIP 主入口和运营精选能力。
- 保留“下拉刷新”，但仅刷新首页快照；失败时可继续显示标注时间的旧缓存。
- 删除首页无限加载和复杂内容展开，让首页成为业务 Hub 而非所有功能容器。
- 所有跨域动作通过类型化 `HomeAction`，不得把服务端字符串当作 location。
