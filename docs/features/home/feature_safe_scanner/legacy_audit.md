|---:|---|---|

## 已确认风险

- 使用 `decodeURIComponent + substring + parseInt` 手工解析，没有严格 scheme、host、版本、长度或签名边界。
- 完整扫码内容和业务响应进入 console，可能泄露账号、桌台、门店、签名和凭证。
- 码类型直接映射本地函数，读取一个码即可触发写接口，缺少“预览/确认/服务端权威状态”分层。
- 目标页面通过 query 接收业务字段，无法证明字段来自可信解析结果。
- 取消、权限拒绝、格式错误、过期、重复使用、弱网和结果未知没有统一状态机。

## 当前建议的迁移原则

- 不兼容执行旧 type 2～8、10 的动作；需要保留的业务以后分别建设消费者或员工流程。
- 旧码如需迁移，由服务端 resolver 在受控兼容期识别并转换；Flutter 不复制旧字符串解析器。
- 扫描、解析、业务执行分成三个边界：`ScannerPort -> ScanResolverRepository -> 目标功能 Repository`。
