- Scope ID：`KC-F-013`

- UI 状态：`In Progress`（2026-08-26，离线 Mock）

## 目标与用户价值

让已登录且会员准入通过的普通会员安全扫描 KingClub 批准的二维码，在明确识别类型和下一动作后进入对应页面，避免二维码内容直接触发加好友、入场、核销、支付或任意路由。

## 已确认事实

- 旧首页 `scanQrCodeSub` 通过字符串截取 `type` 和 query 参数，支持 0～10 多类码并直接调用业务接口或拼接页面 URL。
- 旧码包含加好友、门票入场、代理、取酒、签到、付款/奖励/核销、出门、点单和加群；其中多个属于写操作、员工/代理能力或本期明确暂缓范围。
- 旧实现会记录完整扫码结果，且把 `tableId/shopId/tableName/userAccount` 等直接放入页面参数。
- App Shell 已确认 KC-P-012 是全屏 overlay；关闭、取消、拒绝权限或识别失败后返回原分支和原滚动位置。
- 本期消费者 App 不包含员工交付、代理后台、完整群聊、红包/金币转赠或运营核销。

## 当前建议的消费者 allowlist

| 稳定类型 | 扫描后允许动作 | 明确禁止 |
|---|---|---|
| `friendProfile` | 打开受控好友预览/申请流程 | 自动加好友、从码中信任账号权限 |
| `tableOrdering` | 打开 KC-P-034 点单页并交付不透明 `scanContextRef` | 信任码内桌名、价格、门店或直接创建订单 |
| `admissionContext` | 打开 KC-P-033 入场凭证/状态页 | 扫码即入场/出场、客户端宣布核销成功 |

储物取件码由会员在 KC-P-048 展示给员工端扫描；会员 App 扫到员工、代理、群聊、签到、领取、付款、核销或储物交付码时显示“此码不适用于当前 App”，不执行降级动作。

## 本期不包含

- 扫码后直接写入好友、入场、出门、签到、订单、支付、奖励或核销状态。
- 任意 HTTP/HTTPS URL、动态 route、WebView、App Link 或服务端任意按钮动作。
- 相册图片识码、连续批量扫码、员工/代理扫码、条形码商品扫描。
- 真实相机权限、扫码 SDK、超级接口或业务页面接入。

## 已确认决策

用户于 2026-08-25 回复“按建议确认”，批准以下方案：

1. 本期全局扫码只允许好友、桌台点单、入场上下文三类消费者码。
2. 储物取件码由会员展示、员工端扫描，不在会员 App 执行交付；代理、签到、奖励、付款、核销和加群码均拒绝。
3. 扫码只解析并分流，不直接完成任何业务写操作；最终状态必须在目标页面由服务端确认。
4. v1 只使用后置摄像头实时扫码，不支持从相册选图识码。
5. 未识别、过期、已使用、离线、权限拒绝均留在扫码页重试或安全返回，不尝试打开原始 URL。
