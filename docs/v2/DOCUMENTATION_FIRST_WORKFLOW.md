# 文档先行开发流程

## 1. 强制规则

每一个功能和每一个页面都必须拥有独立文档目录。功能文档设计未完成前，不得开始该功能的 Flutter 开发；页面文档未完成前，不得创建该页面实现。

标准顺序：

```text
冻结本期 App 功能/页面总清单
  -> 为每个功能建立目录、完成规格并评审
  -> 为每个页面建立目录、完成 UI/交互/状态/数据/验收设计并评审
  -> 全部清单达到文档准入
  -> 创建 Flutter UI，实现 Mock/Fake 数据和全部状态
  -> UI 模拟整 App 主流程、异常流程、返回路径并验收
  -> 项目状态达到 UI Flow Approved
  -> 按批准契约连接真实超级接口、WebSocket 和原生 SDK
  -> 集成测试、真机验收与归档
```

不得采用“写一个页面就顺手接一个真实接口”的方式。UI/Mock 阶段和真实接入阶段必须分开提交、分开验收并可独立回滚。

## 2. 功能开发准入 Definition of Ready

以下内容全部完成，功能才可进入 UI/Mock 开发：

- 目标、用户价值、范围和不做事项明确。
- 用户角色、入口、前置条件和主流程明确。
- 状态机与异常流程明确。
- 页面清单和页面间导航明确。
- 数据模型、API 契约、权限和错误码明确，或有批准的 Mock 契约。
- 埋点、日志、隐私、安全和合规要求明确。
- 验收标准和测试场景可执行。
- 依赖、风险、灰度和回滚方式明确。
- 文档状态标记为 `Approved for Development`。

缺少任何一项时，状态保持 `Draft` 或 `In Review`。

即使单个功能达到 `Approved for Development`，只要本期 App 功能/页面总清单尚未全部达到文档准入，就不得开始 Flutter UI 实现。

## 3. 页面开发准入

页面目录至少应包含：

- 页面目标和用户任务
- 入口、出口、返回行为和路由参数
- 信息架构与组件清单
- 加载、成功、空、错误、无权限、离线和会话过期状态
- 交互规则、校验、弹窗和防重复提交
- API 字段映射或 Mock 数据
- 设计稿链接/版本；无设计稿时提供明确线框说明
- 埋点与可访问性要求
- Widget/Mock 流程验收用例，以及 UI 全局验收后使用的真实集成验收用例

## 4. 文档状态

| 状态 | 含义 | 是否允许编码 |
|---|---|---|
| Draft | 草稿，边界可能变化 | 否 |
| In Review | 正在产品/设计/技术评审 | 否 |
| Approved for Development | 文档达到准入；对 App 页面仅允许在全局清单完成后进入 UI/Mock | 条件允许 |
| UI Mock Implemented | 页面 UI、状态和 Fake Repository 已实现 | 仅 Mock |
| UI Flow Approved | 本期整 App UI Mock 主流程和异常流程已验收 | 允许真实接入 |
| Integrated | 已连接批准的真实接口/SDK并通过集成测试 | 是 |
| Implemented | 对应实现、Mock 与真实接入均完成开发测试 | 是 |
| Accepted | 已完成业务验收 | 是 |
| Deprecated | 已废弃，仅保留历史 | 否 |

`UI Flow Approved` 是项目级门禁，不因某一个页面 Mock 已完成而提前授予。

## 5. 变更控制

- 开发后需求变化，先更新文档和验收标准，再修改代码。
- 影响多个功能的决定记录为 ADR，并链接到所有受影响目录。
- API 字段变化必须先更新 OpenAPI/Mock 契约，再生成或修改客户端模型。
- UI/Mock 阶段发现流程缺口时先回写功能和页面文档，再修改 UI；不得用真实接口返回临时补设计。
- 真实接入必须实现已经由 Mock 使用的 Repository/port，不允许页面改为直接依赖 Dio、WebSocket 或厂商 SDK。
- 紧急修复可以缩短评审，但不能跳过问题、方案、影响范围和验证记录。

## 6. UI Mock 全局验收

进入 `UI Flow Approved` 前必须满足：

- 本期范围内所有功能和页面文档均为 `Approved for Development` 或更高状态。
- 每个页面完成加载、成功、空、错误、离线、无权限和会话失效等适用 UI 状态。
- Mock/Fake 覆盖启动、登录、首页、返回、退出以及本期全部业务主流程和异常分支。
- 页面跳转、返回栈、弹窗、防重复提交、可访问性和多尺寸适配完成 UI 验收。
- Mock DTO 不伪装成服务端事实；字段必须来自批准的接口契约或明确标记的临时 Mock 契约。
- UI Mock 不访问真实生产/测试服务，不使用真实手机号、订单、聊天、支付或身份数据。
- 验收记录明确哪些 UI 已确认、哪些需求退出本期范围。

## 7. 真实接入规则

- 真实超级接口、WebSocket、支付、推送、媒体、地图等按功能逐项接入，但只能发生在项目达到 `UI Flow Approved` 之后。
- 接入只替换 Fake adapter，不改变已经验收的页面任务、导航和状态语义；需要改变时先回退到文档评审。
- 每个真实接口必须有契约测试、错误映射、弱网/超时、幂等、隐私和回滚验证。
- Mock 和 Fake 保留用于自动化测试、演示和离线开发，不能在接入完成后删除。

## 8. 完成标准 Definition of Done

- 实现与已批准文档一致。
- 核心规则、Widget 和关键集成测试通过。
- 加载、空态、错误、弱网和权限状态已验证。
- 日志无敏感信息，埋点和监控可用。
- Android/iOS 目标真机完成冒烟。
- 文档补充实现差异、已知限制和发布说明。
- 产品或指定验收人将状态更新为 `Accepted`。
