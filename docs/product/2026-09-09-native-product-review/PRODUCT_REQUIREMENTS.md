**2026-09-10 最新更新**：8 个业务板块及全局媒体要求见[25 条需求](REQUIREMENT_INBOX.md)，PR-01～41 编号保持稳定。用户明确先做注册准入，确认**保留腾讯照片实名认证，仅不接新增 App 活体核身 SDK**，覆盖此前“不接权威库”的解释。注册模块可独立 UI 验收后接隔离测试环境；尚未验收/真实接入，其他模块和生产门禁不变。

## 1. 产品目标与角色

KING CLUB App 的核心任务是“成为会员、找到朋友和内容、约局到店、消费与查看权益”，并为授权角色提供代理、订台、库存、收银、财务管理。管理员功能已被用户明确纳入 App 产品，不再仅作为消费者 App 外的依赖；仍不混入普通会员界面。

| 角色 | 应有能力边界 |
|---|---|
| 访客 / 未登录 | 登录、协议、必要说明；不能取得会员私密内容 |
| 注册中 / 待审核 / 需补件 | 仅对应准入流程、审核进度及申诉/帮助入口 |
| 正常会员 | 经服务端授权的社交、内容、到店消费和个人权益 |
| 局长 / 群主 / 群管理员 | 按具体组局/群资源授予权限，不等于平台管理员 |
| 暂停 / 注销处理中 | 状态说明及必要的订单/资产处理路径，不能继续普通交易 |
| 员工 / 门店 / 审核 / 客服 / 财务 / 代理 | App 内授权管理能力；按角色、门店、所属会员/订单隔离。工作台位置与补充 Web 端待评审，不能以隐藏按钮替代服务端权限 |

冻结/注销时能否查看未完成订单与申请退款应专门设计，不能用统一“踢回登录”造成资产不可处理。

## 4. 不照搬的实现与待定的业务规则

**已确认用户方向**：重构可以替换手工旧代码/存储过程，UI 相似不要求内部结构相同。

**当前建议**：不迁移共享 Basic 凭据、不以本地 userAccount 当鉴权、不接受客户端金额/收件人/权限作为事实、不保留无条件成功页、不复制全量隐私日志、不把逗号成员字段作为新库权限依据。
