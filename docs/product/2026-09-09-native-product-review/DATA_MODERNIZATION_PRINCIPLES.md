# KING CLUB 数据库现代化原则

- 状态：**Confirmed Direction / 具体模型逐功能评审**。
- 用户确认：旧数据库和业务逻辑没有问题，是当前有效业务基线；新版可以改进手工形成的代码组织、表结构和架构，但不能擅自改变正确业务结果。
- 目标数据库：继续采用 CCSOP 已选 MySQL 8.4。现代化的关键是模型、约束、事务和工程治理，不为追求“新”而更换数据库品牌。

## 1. 不重写业务事实，只重构表达方式

旧小程序、旧 Java、`s_interface`、`K_` Routine 和 `k_` 表共同构成行为基线。新版对每项规则采用以下顺序：

1. 用旧接口、存储过程、表数据和页面行为确认输入、输出、副作用与异常结果。
2. 把隐含规则写成明确契约、状态机和测试案例。
3. 在新模型中减少耦合、补充约束与审计，但保持批准范围内的业务结果。
4. 通过同一组合成输入的新旧对照测试、迁移对账和回滚演练证明没有语义退化。
5. 只有用户明确批准的产品规则变化，才允许产生与旧版不同的业务结果，并记录版本和生效时间。

## 2. 哪些地方可以更现代

| 方向 | 旧版有效做法 | 新版增强方式 |
|---|---|---|
| 事务 | 存储过程用 `START TRANSACTION / COMMIT / ROLLBACK` 保护组合写入 | 保留单库短事务；跨服务用 Outbox、幂等消费者和补偿，不用分布式长事务 |
| 表职责 | 一张表可同时承载账号、实名、会员、偏好和展示字段 | 按稳定业务事实拆表；共享身份、会员资格、注册申请、照片证据和偏好各自有明确 owner |
| 关系 | 业务关系部分靠字符串、代码约定或软关联 | 对关键关系增加外键或等价受控约束、唯一键、CHECK、版本列和一致命名 |
| 状态 | 多个整数状态由过程和页面共同解释 | 使用版本化枚举与显式状态迁移；未知、待审、补件、拒绝、撤销分开 |
| 幂等 | 事务可防单次失败，但外部请求重试语义较隐含 | 每个写命令有幂等键、请求状态和唯一业务键，防双击、超时重试和迟到响应 |
| 资产 | 钱包、流水和奖励在事务内更新 | 保留精确金额和原子性；账本尽量追加写，余额可核算，冲正替代静默改历史 |
| 外部服务 | Java 编排腾讯、文件和数据库过程 | Adapter 隔离供应商；调用记录最小化，数据库事务不等待外部 HTTP，失败可恢复 |
| 敏感数据 | 旧系统按当时需要保存姓名、证件、照片和 URL | 最小采集、私有对象、加密/指纹化、日志脱敏、用途与保留期、访问审计 |
| 接口治理 | `s_interface` 动态目录与 Routine 形成成熟运行机制 | 保留目录驱动优势；补齐强类型 DTO、权限、超时、错误码、版本、测试和对象登记 |
| 可观测性 | 主要依赖返回码和业务表状态 | 增加 requestId、correlationId、审计事件、指标和不含敏感原文的失败诊断 |

## 3. 不把“现代化”做成过度设计

- 不把每张表拆成独立微服务；先按领域逻辑隔离，只有规模和团队边界证明需要时才物理拆分。
- 不因存储过程“看起来旧”就全部删除。高并发原子记账、库存或批量一致性操作，经过清晰契约和测试后仍可使用 Routine。
- 不用 JSON 替代稳定关系字段，也不为了范式纯度拆出大量没有独立生命周期的小表。
- 不把外键当唯一一致性方案；大批量迁移、软删除和跨域引用需要结合约束、应用校验与对账。
- 不一次性重写全部客户端、服务端和数据库；按功能纵向闭环迁移，旧端保持运行，逐域切换唯一写入方。
- 不以技术“先进”改变佣金、颜值阈值、奖励、会员资格等产品规则。

## 4. 现代化是否成功的判断标准

每个功能至少证明：

- 相同有效输入得到与旧版一致的业务结果，明确批准的变更除外。
- 单步失败、数据库异常、重复请求和迟到响应不会产生重复或半完成业务结果。
- 关键关系、状态和金额可以由数据库约束及测试验证，而不是只靠开发者记忆。
- 新旧迁移数量、引用、余额、权益和状态可对账，差异有原因和处置记录。
- 敏感数据访问更少、更可审计，日志和测试不泄露真实资料。
- 新成员可以从表注释、目录、接口契约和测试理解功能，不必先读完一个超长过程。
- 性能以基准、执行计划和真实容量模型证明，不以“拆表/微服务/ORM”名称判断。

## 5. 首功能的应用

注册准入继续承认旧事务和回滚逻辑正确。新版把手机号会话、照片实名、两图评估、人工审核、会员资格、钱包/奖励分清职责；单库关键状态仍使用短事务，跨域副作用通过 Outbox 和幂等业务键保持一致。详细证据与目标缺口见[注册准入数据库审查](../../features/identity/feature_member_onboarding/database_review.md)。
