# GitHub 仓库内容策略

- 生效日期：2026-09-08
- 用户要求：不上传与源码无关的参考附件和缓存，控制仓库文件体积。

## 保留

- `lib/`、Android/iOS 工程源码与构建配置。
- `pubspec.yaml`、锁文件、必要的开发脚本。
- `assets/` 中 App 运行需要的素材；目录名包含 `legacy` 不代表备份文件。
- 自动化测试及 `test/goldens/` 中测试实际依赖的基准图。
- `AGENTS.md`、README、迁移与架构文档、功能和页面契约、文字验收记录。

## 只保留在本地

- `docs/` 内的截图、参考图、录屏、UI 层级 XML 和设计附件。
- 根目录 `references/`、`reference/`、`screenshots/`、`recordings/`。
- 临时检查文件、缓存、依赖安装目录、构建产物和安装包。

本次清理只取消附件的 Git 跟踪，不删除原工作目录中的文件。文档里的历史附件路径保留用于本地追溯；新克隆不包含附件，不能把缺失附件当作已提供的视觉验证证据。需要时重新执行验收或向原工作目录持有人索取。

## 提交检查

使用 Node.js 运行 `node scripts/check_repository_content.mjs` 检查暂存区（服务端开发环境已有 Node.js）：

1. 不允许提交匹配 `.gitignore` 的文件，防止强制添加绕过过滤。
2. 默认单文件上限为 10 MiB，当前快照全部文件之和上限为 100 MiB。这是本项目的体积预算，不是 GitHub 的平台限制。
3. 检查的是 Git 暂存区中的内容，不计算本地缓存，也不等于仓库克隆或 `.git` 目录大小。

后续确需超过预算的运行素材，应先确认压缩、按需下载或其他存储方案，不因临时验收附件提高预算。

## 历史边界

普通删除提交只清理最新分支快照，已提交的附件仍在历史中。若需要降低完整克隆体积，须另行明确批准历史重写与强制推送，事先保存备份并协调其他使用者；不得把本次普通清理描述为已清空 Git 历史。
