## 当前主要技术问题

### 认证和数据边界

- 客户端没有发现用户级 access token、session 或 refresh token。
- 登录状态主要依据本地 `preUserInfo`。
- 业务接口使用共享 Basic Authorization，并由客户端提交 `userAccount`。
- 后端必须核查所有对象级权限，防止客户端替换账号访问其他用户数据。
- WebSocket 签名只由账号、手机号和时间戳做 MD5，没有服务端短期 Ticket。

安全改造目前不是第一阶段功能目标，但服务端 V2 设计不能继续复制这一认证模型。

### WebSocket 确定性缺陷

`app.js` 的 `reconnectSocket()` 使用未定义变量 `that`，异常又被空 catch 吞掉，可能导致：

- 原心跳没有清理
- 原 Socket 没有关闭
- 新旧连接同时存在
- 重复心跳和重复消息

其他问题：重连成功不清零 retryCount；新建心跳前不清旧定时器；消息 JSON.parse 没有保护。

### WXML 绑定缺少方法

已确认以下实际绑定缺少 JS 方法：

1. 协议图片：`click_photo`
2. 黑名单滚动：`onPageScroll`
3. 收银台：`manualShake`
4. 订单条码：`barEnlargePage`
5. 群背景：`bindEnter`
6. 视频频道：`clicktap`
7. 设置年份：`bindDateChange`
8. 作品发布相机错误：`error`
9. 作品发布更多设置：`copyBind`

### 支付和订单

- `pay.js` 从页面参数直接解析完整 orderData。
- 价格、优惠、余额、金币和奖励字段大量在客户端计算。
- 服务端必须完全独立重算订单，不得信任客户端金额结果。
- `mode=8` 可以只凭页面参数显示支付成功；只能作为展示，不能作为业务凭据。
- 多处 JSON.parse 页面参数没有异常保护。
