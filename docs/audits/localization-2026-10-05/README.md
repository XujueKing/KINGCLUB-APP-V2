## 已确认的问题及优先级

1. **付款与规则优先**：`scan_order_confirmation_page.dart` 的“提交订单”“单价”“小计”和价格变化确认等为固定中文。不能在付款页只翻译支付按钮而遗漏应付变化提示。金额、订单状态、退款方式、责任金额必须保持原语义。
2. **派对流程未贯通**：`together_play_page.dart` 的空状态、错误重试等没有完整跟随入口；个人创建、加入、核销后的规则说明要按整条流程验收。
3. **个人/安全页面不完整**：`my_profile_page.dart` 的资料加载、编辑主页、资产入口、预约/客服等仍有固定中文；设置页只是主菜单已翻译，权限、注销、缓存弹窗未全部补齐。
4. **系统原生提示不在 Flutter 文案内**：`ios/Runner/Info.plist` 的定位、相册、麦克风、相机用途说明是中文，需对应本地化资源。相机说明还应核对当前扫码等实际用途，不宜直接照字翻译过时用途。
5. **协议仍只有旧正文资源**：`assets/legacy/legal/agreements.json` 和 `terms_consent_page.dart` 未按语言选正文；标题仍出现 KINGBAR。译文不能擅自修改运营主体、责任、期限或法律含义；品牌与主体名称需分别核对。
6. **图片和动态内容不能由源码扫描证明已翻译**：旧图标/宣传图可能包含中文。聊天内容、昵称、地址、活动主题属于用户或商家数据，不能自动覆盖；商品接口有四语言键也不等于四个值都已准确翻译。
7. **语言不等于经营地区**：泰语不能自动改币种、经营日或活动日期。交易时间仍按门店时区；日期控件需检查泰语历法显示与真实日期一致。
8. **可读性待实机验收**：英文长按钮、泰语组合字/断行、繁体字形、动态大字、VoiceOver 标签需要逐页检查。现有语言切换与少量窄屏测试不代表全 APP 排版通过。

## 本次修正

- 系统消息“业务编号”原英文 `Receipt`、泰文 `ใบเสร็จ` 表达收据，改为 `Reference number` / `หมายเลขอ้างอิง`。
- “存酒/取酒”英文使用 `Drinks stored / Drinks collected`，避免 `Wine` 被理解为仅葡萄酒；取酒泰文明确为领取已寄存饮品。
- 充值采用 `Top-up`，赠送金额采用 `Bonus credit`，区分赠送额度与现金。
- “全部已读”泰文改为明确的“将全部标记为已读”，避免只是“阅读全部”。
- 点单无桌号预览路由与预览桌台分支补传当前 locale；真实扫码路由原本已传入，不把预览问题误报为全部点单失效。

## 翻译口径

见 [术语表](TERMINOLOGY.md)。逐页翻译完整句子，保留参数及动作后果；禁止把语言标签、业务类型、状态码和路由一起替换。简繁不只做字形转换；品牌用官方名称。没有明确语境的“核销”“实收”“储物”“免单”必须结合业务动作译。

建议交付顺序：付款/退款/核销与派对流程 → 个人/安全/登录 → 聊天/联系人 → 内容/帮助 → 原生权限、图片及读屏。每批验证四语言、长文、小屏和原业务路径。此清单中的未修项仍待实施，不以扫描完成替代翻译完成。
